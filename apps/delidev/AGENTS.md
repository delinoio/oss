# DeliDev desktop

- Follow `docs/apps-delidev-desktop-contract.md`, the full issue #964 contract and `docs/packages-delidev-api-client-contract.md`. A frontend build does not establish complete desktop acceptance.
- Keep Go business authority and direct generated Connect/Connect Query calls. Rust owns only infrastructure and native presentation. Never proxy agent traffic through Tauri or add a browser product.
- Preserve drafts and independent outcome/archive/dispatch/recovery state. Bind mutations to original revisions/request identities and expose exact retries after uncertainty; never retry a mutation automatically.
- Render content as inert text, bound pages/caches, fetch changed messages by ID and cancel stale connection work. No credentials or mutation payloads in query keys. Generated read request parameters (including search text and cursors) may exist only in connection-scoped memory keys; no credentials, cursors, prompts or transcript content enter logs or Web Storage.
- Question responses retain original question IDs, exact offered choices and explicit unanswered arrays. Never accept protected answers through an ordinary input. Approval choices preserve the pinned native request and exact offered amendments; permission reductions retain native deny descriptors. Queue editing binds the revision at the beginning of editing, and Steer binds the observed execution/turn without an implicit send fallback.
- Keep settings modal accessible with focus containment, Escape and focus restoration without remounting the session. Give every workspace icon an accessible name. Do not reinterpret a server capability or unavailable evidence as permission to execute.
- Frontend development uses fixed loopback port 46311 and fails on conflicts. Run package `pnpm test` and build verification; remove generated `dist` output. Native Rust changes also require root Cargo tests and actual host lifecycle validation.

- The native host uses the same immutable official Tauri revision as the repository with an isolated optional `desktop-host` Wry feature; do not add Wry to DevHud's protected desktop graph. The default Rust library is display-independent infrastructure.
- Bundle only the Go executable from this checkout for the selected target. Invoke its closed startup/pairing/inspection commands with bounded output/time and a minimal environment; never accept a renderer-supplied path, argv, data root or arbitrary file/network command. Reuse the same client identity and refuse implicit re-pairing after revocation/corruption.
- Only the trusted main app entry receives the local-bootstrap capability. Deny external navigation/popups, retain the fixed local Connect CSP, and keep app webview storage ephemeral. Native connection failure logs carry classifications only. Closing or fully exiting the app never stops the detached server.
- Native supervision invokes only Go's local `server ensure` boundary, honors its durable explicit-stop intent and original configuration/generation, and never supervises a remote paired scope. Bound jittered retry delays and controller output/time; join the loop and cancel its short controller on app exit without terminating a detached server. Report supervision separately from session cleanup. Revalidate active read caches after reconnection while retaining drafts for the same server/device/credential identity; only transient status reads may retry automatically.

- Configuration forms retain the original document and revision, including server-owned observations and unknown fields. Block stale saves while preserving drafts. Account keys exist only in the transient input and the bounded connection-scoped exact pending request; clear the input on submission/hide and release mutation variables after completion. Explicit connection, validation, discovery and credential cleanup remain separate actions; pending removal retries retain the original server mutation identity. Never infer readiness or switch providers/accounts.
- Repository forms inspect paths only through the selected Worker and retain its original asynchronous job. Configuration acceptance is not successful publication: track the original save job through Worker validation, preserve uncertain operations, and require an explicit return to the retained draft after a confirmed failure. Project repository order, primary selection and configured-empty restrictions are independent; never replace empty restrictions with unrestricted access. Deletion uses its original revision and confirmation, and routing previews remain read-only server decisions.
- Schedule forms submit only editable definitions, retain original mutation revisions and never synthesize Local Worker proof. Preserve an unchanged authenticated Local origin; new or relocated Local selection requires fresh matching proof from the fixed local Worker scope. Render authoritative next-run times, distinguish accepted occurrences from execution, and retain independently readable history after configuration deletion. Worker discovery preserves all executable selections and separates version/protocol observations from execution readiness; uncertain checks retain the original job.
- Session creation uses paginated explicit selections, byte-bounded prompts and separate per-repository starting overrides. Recovery confirmations capture their session revision and original execution identity; incomplete preparation cleanup requires its own explicit action. Track original recovery jobs, retain uncertain retries after peer changes, and never infer cleanup or invoke Resume/enqueue from recovery acknowledgment.
- The main-only `local_worker_proof` native read inspects only the fixed CLI-owned `worker` directory and matches its server/endpoint to the paired desktop client. It cannot pair, start, replace or select a renderer-supplied credential path. Read proof afresh before Local mutations, reject changed machines/connections, and retain tokens only in the exact pending wire request after uncertainty; never in form state, query caches or logs.

- Local Worker controls use only the main-only closed native action enum and fixed CLI-owned scope. Registration, startup and inspection are separate explicit operations; stop captures the original generation and retains that target through uncertainty and settings navigation. Status refreshes never repeat lifecycle mutations. Native/Go startup cancellation, lease waiting and controller exit cannot imply per-session cleanup, new pairing after revocation, automatic process restart or OS-service readiness. App exit leaves detached Workers running.

- Paired-device authorization is independent of online status. Revocation captures the original revision, warns when targeting this desktop, preserves exact uncertain retries and cannot infer session cleanup or replace credentials. Diagnostics render only bounded known report fields, keep unknown/partial evidence explicit and distinguish the loaded owner identity from protected account-store health or inference readiness.

- Server preferences edit only inherited default routing and the global Worktree fetch gate, retaining every unrelated policy field and original singleton revision. Seed absent configuration from the documented Go defaults and verify parity through real Go integration. Do not offer duplicate creation or generic deletion of the singleton, rewrite existing execution snapshots or apply fetch changes to Local checkouts.

- Doctor version-2 presentation follows `docs/cmds-delidev-diagnostics-contract.md`: preserve decimal-string precision, partial/unavailable/superseded states, retained observation timestamps and legacy/unknown report boundaries. Stream presence, version/handshake observations, saved-credential readability and account readiness must remain distinct; diagnostics cannot invoke repair, login or harness probes.

Revalidate authority before token delivery; never mix server caches/drafts, infer current connectivity from cached status, start remote servers or use a different credential after failure.
