# Troubleshooting bundlewhy

:::warning Availability
bundlewhy is not yet published to npm. Version 0.1.0 is in development.
:::

Every error prints a stable `BW_*` code, a message and a recovery instruction. A failed or cancelled run never retries automatically; after you fix the cause, start a new run.

## Project and configuration selection

| Code                      | Meaning                                                                                                                                     | Recovery                                                                                                                                                                                                    |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `BW_USAGE`                | The command line or a request is invalid.                                                                                                   | Check the command with `bundlewhy --help`.                                                                                                                                                                  |
| `BW_PROJECT_NOT_FOUND`    | The project directory or its `package.json` cannot be read or is invalid.                                                                   | Run bundlewhy in a directory that contains a valid `package.json`, or pass `--project <dir>`.                                                                                                               |
| `BW_BUNDLER_NOT_DETECTED` | No supported bundler was found, or the bundler cannot be inferred from the configuration file.                                              | Pass `--bundler vite` or `--bundler rspack`, together with `--config <file>` if needed.                                                                                                                     |
| `BW_BUNDLER_AMBIGUOUS`    | Several bundlers are candidates.                                                                                                            | Select one with `--bundler`.                                                                                                                                                                                |
| `BW_CONFIG_NOT_FOUND`     | No configuration file was found, or the selected file cannot be read.                                                                       | Pass an existing file with `--config <file>`.                                                                                                                                                               |
| `BW_CONFIG_AMBIGUOUS`     | Several configuration files or builds are candidates.                                                                                       | Select one with `--config <file>`, or with `--config-name <name>` for an Rspack configuration that exports several builds.                                                                                  |
| `BW_CONFIG_LOAD_FAILED`   | The bundler could not load the configuration.                                                                                               | Fix the error in the configuration. TypeScript Rspack configurations load through Node.js type stripping, so they must use only erasable TypeScript syntax (for example, no enums or parameter properties). |
| `BW_UNSUPPORTED_BUILD`    | The selected configuration is a library, SSR or Node-target build, or a Vite plugin changes the project root after the protection snapshot. | Select a client production build configuration. For Vite, set the final root in the configuration before plugin hooks run.                                                                                  |

## Engine and Node.js

| Code                            | Meaning                                                                                           | Recovery                                                                                        |
| ------------------------------- | ------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| `BW_BUNDLER_NOT_INSTALLED`      | The bundler package is not installed in the project.                                              | Install the project's dependencies, then start a new run.                                       |
| `BW_ENGINE_VERSION_UNSUPPORTED` | The installed bundler version is not in the [compatibility matrix](/bundlewhy/supported-engines). | Install a supported version, or pass `--allow-unsupported-engine` to analyze anyway.            |
| `BW_NODE_NOT_FOUND`             | The Node.js executable was not found.                                                             | Install Node.js 22.18 or newer, or set `BUNDLEWHY_NODE` to the path of the Node.js executable.  |
| `BW_NODE_VERSION_UNSUPPORTED`   | The Node.js runtime is older than 22.18.                                                          | Install Node.js 22.18 or newer, or set `BUNDLEWHY_NODE` to a supported Node.js executable.      |
| `BW_MINIFIER_NON_DEFAULT`       | The build uses a non-default JavaScript minifier. Minifier categories are unavailable.            | Use the default minifier to analyze minifier optimizations. Module-graph results remain usable. |
| `BW_MINIFICATION_DISABLED`      | JavaScript minification is disabled in the selected configuration. On Vite, dead-code elimination can still run. | Enable minification for production builds to analyze minifier optimizations.                    |

## Build and collection

| Code                    | Meaning                                                                                                                                                                                                                          | Recovery                                                                                                                                                                                                                                               |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `BW_BUILD_FAILED`       | The diagnostic build failed.                                                                                                                                                                                                     | Fix the build error if the production build also fails in the project. If it succeeds, a plugin or option is incompatible with the diagnostic build (bundlewhy forces the output directory, source maps and a collector plugin). Then start a new run. |
| `BW_COLLECTION_FAILED`  | bundlewhy could not collect or read the build information, or the installed bundler lacks an API the adapter needs.                                                                                                              | Start a new run and do not change the run directory while it runs. If the message names a missing bundler API, install the supported bundler version. Report a bug if the problem continues.                                                           |
| `BW_SOURCE_MAP_MISSING` | Some chunks have no usable source map. Their findings use generated locations. In Vite builds, chunks made only of Vite or Rolldown helpers (such as the preload helper and runtime) are not reported; Rspack chunks always are. | Check plugins that disable or rewrite source maps.                                                                                                                                                                                                     |
| `BW_SOURCE_UNREADABLE`  | Some source files could not be read.                                                                                                                                                                                             | Check the file permissions, then start a new run.                                                                                                                                                                                                      |
| `BW_SOURCE_UNVERIFIED`  | Some readable source files lack a build-time text snapshot, so their analyzed revision cannot be verified.                                                                                                                       | Check source-map settings for embedded source text, then start a new run.                                                                                                                                                                              |
| `BW_PROJECT_MODIFIED`   | `package.json`, the selected configuration or a lockfile changed during the run.                                                                                                                                                 | Do not change these files while a run is in progress, then start a new run.                                                                                                                                                                            |
| `BW_RUN_CANCELLED`      | The run was cancelled. Its results are incomplete.                                                                                                                                                                               | Start a new run when you are ready.                                                                                                                                                                                                                    |
| `BW_RUN_INTERRUPTED`    | The run stopped before it finished, for example because the process was terminated. Its results are incomplete.                                                                                                                  | Start a new run.                                                                                                                                                                                                                                       |
| `BW_OUTPUT_DIR_INVALID` | The output directory cannot be created or written.                                                                                                                                                                               | Choose a writable `--out-dir`.                                                                                                                                                                                                                         |

## Result and report problems

| Code                             | Meaning                                                                                                                                                                            | Recovery                                                                                                                                                                                                                                                                                                           |
| -------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `BW_SCHEMA_UNSUPPORTED`          | The saved results use a format version that this bundlewhy version does not read.                                                                                                  | Open the results with the bundlewhy version that wrote them, or start a new run.                                                                                                                                                                                                                                   |
| `BW_RESULT_INVALID`              | The saved results or the report are damaged, incomplete or not written by bundlewhy.                                                                                               | Pass a run directory created by `bundlewhy analyze`, or start a new run.                                                                                                                                                                                                                                           |
| `BW_RESULT_TOO_LARGE`            | The result exceeded 512 MiB, so source content and snippets were not saved.                                                                                                        | Analyze with `--exclude-sources`, or analyze a smaller build.                                                                                                                                                                                                                                                      |
| `BW_EXPORT_FAILED`               | The report could not be written, or the output file already exists.                                                                                                                | Choose another `--output` path, pass `--force` to replace the file, or check that the destination is writable.                                                                                                                                                                                                     |
| `BW_SOURCE_STALE`                | Source files changed or were removed after the analysis.                                                                                                                           | Saved locations and snippets describe the analyzed version. Start a new run to analyze the current code.                                                                                                                                                                                                           |
| `BW_SOURCE_FRESHNESS_UNVERIFIED` | A source file's current state could not be checked, so bundlewhy could not tell whether it changed after the build (or, for a source without build text, whether it still exists). | For a source with build text, results use the source text from the build's source maps and are still usable. For a binary asset, generated asset module or other source without build text, only the path is kept and its existence is unverified. Check the file permissions, or reopen the run later to recheck. |
| `BW_SOURCE_NOT_FOUND`            | The requested source is not part of this analysis.                                                                                                                                 | Select a source from the analysis, or start a new run if sources were excluded.                                                                                                                                                                                                                                    |

`BW_SOURCE_STALE` reports edits only for text sources. In current runs, imported images and other assets (including small inlined assets and `?url`, `?raw` or `?inline` imports) keep their path in the analysis but their content is not checked for changes (only their removal is reported), and the module code the bundler generated for them is not shown as source code. A normal source file that was replaced by non-text content is still reported as changed.

Earlier schema-1 runs may retain generated asset module text. When that text is present, reopening the run recognizes the module and does not compare its hash with the asset file, including an unchanged SVG. In an earlier run saved with `--exclude-sources`, that text is absent: reopening can skip an unchanged non-text binary asset with a recognized binary path, such as PNG, but it can report `BW_SOURCE_STALE` for an unchanged text-backed asset such as SVG. Start a new run if you need current freshness information from an older excluded-source result.

`BW_SOURCE_FRESHNESS_UNVERIFIED` is not a change claim: it means the live file could not be read (for example because of a permission or I/O error), so freshness could not be checked. The build's source text stays in use, the source is not marked stale, and the run is not partial. Only a file that no longer exists (including a symlink whose target is gone) is reported with `BW_SOURCE_STALE`; a permission error, a path below a regular file, a directory in place of a file, a file outside the project or over 16 MiB, or any other I/O error never marks a source as changed. The same rule applies to imported assets, for which bundlewhy only checks that the file still exists. For sources that have no build text (imported assets, generated asset modules), the warning says that their existence could not be checked and does not claim that the analysis uses a build snapshot for them. If bundlewhy cannot check whether a run is complete or cannot open its result file because of such an error, it says so instead of reporting the run as complete or missing. Reopening a run rechecks the files: the warning disappears once they are readable and equal to the analysis, and it stays while a file still cannot be read.

Each time you reopen a run, bundlewhy shows at most one `BW_SOURCE_STALE` warning with the current count; it disappears when the files match the analysis again, and it stays while any source is still marked as changed or removed (for example a file that was already missing during analysis). An exported report keeps the stale warning and flags as they were when you exported it and does not recheck files.

## Local server and browser

| Code                      | Meaning                                                                                  | Recovery                                                                                  |
| ------------------------- | ---------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| `BW_SERVER_BIND_FAILED`   | The local server could not listen on `127.0.0.1`.                                        | Check local firewall or sandbox settings, or use `--no-serve` and open the results later. |
| `BW_BROWSER_OPEN_FAILED`  | The browser could not be opened.                                                         | Open the printed URL manually.                                                            |
| `BW_ACCESS_DENIED`        | The local server rejected a request without a valid access token or from another origin. | Open the exact URL that bundlewhy printed for this run.                                   |
| `BW_ACCESS_TOKEN_MISSING` | The UI page has no access token.                                                         | Open the exact URL that bundlewhy printed, including its fragment.                        |

## Logs

- Add `--verbose` to show debug logs on the terminal.
- Set `BUNDLEWHY_LOG` to a log filter, for example `BUNDLEWHY_LOG=bundlewhy=debug`, to choose the detail level.
- Logs are colored by default. Disable color with `--no-color` or the `NO_COLOR` environment variable.
- Each run directory contains `bundlewhy.log` with JSON lines: timestamps, run identifier, stage, durations, engine versions and error codes.

Logs never include source content, environment variable values, credentials or access tokens. Review any file before you attach it to a report.

## Support

Report problems through [Delino OSS GitHub Issues](https://github.com/delinoio/oss/issues). Include the bundlewhy version, the output of `bundlewhy engines`, the error code and the relevant lines from `bundlewhy.log`. There is no support response-time commitment.
