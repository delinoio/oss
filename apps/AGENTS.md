### Instructions for `apps/`

- Follow root `AGENTS.md` and project-specific docs before adding or changing app code.
- Keep app-specific contracts synchronized in the project index doc (`docs/project-*.md`) and relevant app-domain contract docs (`docs/apps-*.md`) in the same change.
- Keep repository and domain rules in the appropriate `AGENTS.md` files.
- Public documentation app content must not expose repository-internal implementation details. Use `docs/` as the internal source of truth, then curate `apps/public-docs`, `apps/binpm-docs`, and `apps/nodeup-docs` around user-facing behavior, supported workflows, stable public interfaces, and explicitly contracted maintainer-facing paths.
- Write all source and comments in English.
- Follow Toss Design Guidelines for frontend UX/UI decisions across web and mobile apps.
- For new static sites under `apps/`, default to Rsbuild/Rspress-style toolchains and Cloudflare Pages deployment unless a project contract documents a different platform.
- Prefer Rspack-family build tools for app build pipelines when they fit the runtime and deployment target.
- App file upload/download flows should default to Cloudflare R2 plus signed URLs unless the app contract documents a different storage or access pattern.
- If a form has a single critical input, that input must receive focus when the form is shown.
- Dialog UIs must support closing with the `Esc` key.

### Scope in This Domain

- `apps/mpapp`: Expo React Native mobile app.
- `apps/delidev-app`: React/TypeScript/Rsbuild Cloudflare Pages PWA for project `delidev`.
- `apps/devhud`: React/TypeScript/Rsbuild plus Tauri client/native path for project `devhud`; owns the signed-out base shell and all planned Deck/RealQA client, widget, capture, extension, and native-host sources.
- `apps/binpm-docs`: Rspress static documentation app for `binpm`.
- `apps/nodeup-docs`: Rspress static documentation app for `nodeup`.
- `apps/public-docs`: Rspress static public documentation app.

The frontend may persist only `devhud.settings.v1`, `devhud.shortcut-effective-state.v2`, and `devhud.widget-configuration.v1` through record-specific native commands; widget operations and sanitized diagnostics export use separate private standard Tauri Swift/Kotlin plugin boundaries, never a public plugin, path-bearing IPC, generic key/value/filesystem API, or remote transport. Maintained mobile hosts use standard Tauri WKWebView on iOS 17+ and System WebView on Android 10/API 29+ through isolated target features and the independently pinned standard mobile CLI; CEF must never compile into mobile. - Preserve application identifier `dev.deli.devhud`, build-only widget identifier `dev.deli.devhud.widget`, future App Group `group.dev.deli.devhud`, and storage keys `devhud.settings.v1`, `devhud.shortcut-effective-state.v2`, and `devhud.widget-configuration.v1`.

Distribution/publication requires a later explicit change. No CLI, public API, public plugin/tracker SDK, arbitrary deep link, arbitrary remote tool/UI, runtime code download, or remote client/extension telemetry is authorized.
- Keep the inactive RealQA capture/composer foundation platform-neutral and dependency-injected: signed logical geometry and per-display pixel transforms must preserve mixed DPI and negative coordinates; source selections must bind to deterministic hot-plug snapshots; image inputs must cross the decode/re-encode and pixel/encoded/session limits before composer acceptance; and the default platform adapter must fail unavailable until a concrete reviewed backend is injected. Only the exact `realqa-capture` and `realqa-composer` windows may receive their disjoint generated application-command permissions. Fixture backends and capabilities do not activate a production tool.
- Keep the signed-out base shell usable and bundled-only. Use Logto Authorization Code with PKCE only: one-shot random-port desktop loopback at the stable registered `/auth/callback` path and exact verified Deck mobile callback `https://deli.dev/auth/devhud/callback`; the DeliDev static artifact owns that callback route and its exact-path Apple/Android association files. Vault only the authorized features' refresh grants/device-session key and an active or cleanup-pending Deck registration's single-purpose `UnregisterDevice` revocation grant, keep access/ID/forwarded tokens in memory, and allow one active account/device.
- Keep the implemented shared auth boundary native and dependency-injected: frontend session state exposes no credential, URL, generic request, opener, or persistence interface; desktop uses the OS credential vault, iOS uses a this-device-only non-synchronizing Keychain item, and Android uses Keystore-backed encrypted preferences excluded from backup/transfer. Each feature requests, retains, rotates, and validates only its own refresh grant, API permission scopes, and paired delibase forwarding scope; OIDC-only scopes are not API bearer requirements. A signed-in account may incrementally authorize the other feature without losing its active session or prior feature grant on cancellation, failure, success, or rejected account switching, while an actual account switch still requires logout. Startup may rehydrate the account only after an online feature-grant refresh validates issuer, audience, scope, subject, and device binding; request-level transport failures and explicitly retryable OAuth endpoint responses remain a gated prior-session-offline state, and a rotated grant returned before retryable bearer verification fails must be vaulted before that gate. Missing configuration and invalid or revoked refresh grants do not restore a session. Before opening the browser for a signed-out reauthentication, clear a demonstrably malformed or unsupported retained auth record so the successful flow can rebuild it; real vault-access failures and well-formed account bindings remain fail-closed, and switching accounts still requires logout. Desktop reads the public Logto issuer/app ID from its launch environment, while mobile embeds them during Rust compilation and never relies on a runtime shell environment; neither value is a client secret. New auth endpoints must extend the exact issuer-path allowlist and its replay/redaction tests rather than adding frontend HTTP authority.

Authenticated RealQA code may consume the private `@delinoio/devhud-realqa-connect` root/versioned exports only under `apps/devhud`; DeliDev, browser extensions, and plugin code may not consume them. Generated Deck/RealQA clients use the private native Connect transport's closed procedure/origin table; the sole signed-out RPC is native `DeckDeviceService.UnregisterDevice` cleanup using its OS-vault single-registration grant; RealQA upload uses its separate validated signed-PUT operation; and only the authenticated RealQA desktop window receives its closed platform-bounded capture procedures. Except for the typed browser handoff, none accepts arbitrary URLs, methods, headers, redirects, generic requests, or generic screen authority. Provider GitHub/delibase/R2 calls remain server-side. Never add wildcard origins, arbitrary remote resources/UI, client GitHub tokens, remote configuration, or telemetry.
- Keep capabilities split by exact window/platform/command. All webviews including DevTools retain bundled navigation/UI, popup/download denial, and no generic filesystem/process/environment/screen/store/network/opener plugin authority. Authenticated feature windows receive only the native Connect procedures and applicable typed GitHub system-browser actions; RealQA additionally receives only its exact signed upload operation and user-initiated region/window/display/multi-monitor capture procedures with bounded source enumeration, platform permission/portal enforcement, and no continuous or cross-window screen access.
- Deck's only offline PR-data exception is a minimal encrypted widget snapshot; ordinary Deck shows offline state. Deck list rows use server-authored individual/team reviewer identities for grouping, current assignees and labels for removal controls, explicit open/closed/merged lifecycle state independently from draft state, and supported-mutation/merge-method metadata before presenting actions; use `ListPullRequestMutationCandidates` for advertised add-action operands. Before every prospective refresh, `GetRefreshPreflight` must return an opaque short-lived token bound to its UUID v7 identity and origin; only manual confirmation displays the server-derived price, cancellation performs no reservation/provider call/charge, and every new `RefreshView` attempt carries the token. Preserve the refresh identity and token across ambiguous retries so an exact retry can recover the server's durable reservation/provider-dispatch/billing attempt even after preflight expiry or catalog change and cannot run it twice. Do the same for each `RegisterDevice` creation/renewal until exact replay returns the identical registration ID, lease, and revocation grant; initial registration omits an expected revision, while authenticated startup/stale conflict uses `GetDevice` to reload current server-authored state and renewal submits that current revision rather than overwriting state. The planned delibase single-reservation finalization grant is server-only: no DevHud/DeliDev client receives, persists, or submits it, and Deck's billing-only recovery does not require the client to remain connected after a refresh attempt starts. Opaque notification events resolve only for the online authenticated matching registration after current authorization/detail opt-in checks; all other cases use generic text without provider refresh. Logout/reset first unregister server push delivery; offline/ambiguous cleanup disables local/platform delivery and retains only the registration ID, lease expiry, and single-purpose `UnregisterDevice` revocation grant in an OS-vault tombstone retried before later registration even after an account switch. RealQA offline drafts require prior login/device binding, remain encrypted/account-bound, lock on logout, and require online reauthentication to upload; its uploader starts `SubmitIssue` by the server-derived upload deadline with a fresh forwarded bearer, preserves the submission identity across authenticated retries before reservation expiry, and never expects a deadline worker to perform live transfer billing after disconnect. After successful local-draft removal, authenticated paginated `ListSubmissions` exposes only caller-authorized retained submission/asset references needed for later deletion. Preserve the exact reset/disconnect/feature-deletion distinctions in the app and server contracts.
- Deck and RealQA use separate GitHub Apps, GitHub.com only, and disabled production-facing catalog records. RealQA's server-side manifest/adapter/callback/webhook fixtures are implemented but do not grant the app or extension a client-side provider token or generic GitHub navigation/network path.
