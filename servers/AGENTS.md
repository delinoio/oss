### Instructions for `servers/`

- Follow root `AGENTS.md` and the owning project/domain contracts.
- Keep service contracts, ownership, security, retention, and deployment prerequisites in `docs/` before runtime implementation.
- Write Go code and comments in English; use `log/slog` structured logging and never log secrets or sensitive payloads.
- `servers/devhud-api` is a pnpm workspace package for local orchestration and owns its validation, migration, and serve wrapper. Team configuration must use the exact API allowlist in `docs/repository-environment-contract.md`; reject missing/unknown/invalid names, authority-less URLs, public asset paths hidden by parser normalization, and partial upload groups before migrations or startup. Require the migration and serve issuer to match the private API/administrator preflight comparison pin, then construct a sanitized child environment.
- OSS development owns only generated local identity material, safe loopback configuration, and contributor-owned public Logto issuer/audience/client overrides. An issuer override must exactly match the administrator wrapper's package-local value. OSS must leave official R2/Cloudflare uploads unconfigured and must not fabricate Logto users, administrators, applications, or secrets. Production, deployment, sweeper, release, and signing configuration remains outside the team development secret manager.

### Scope in This Domain

- `servers/devhud-api`: implemented stateless Go service for Bootstrap, Settings, Upload, Account, Admin, Diagnostics, embedded administrator assets, and the account/upload/retention sweeper.

### DevHud Rules

- `servers/devhud-api` uses fixed development port `46307`, PostgreSQL, Cloudflare R2 signed uploads, external Logto, Connect RPC, and a non-root OCI artifact.
- Production API serving requires TLS termination at a trusted reverse proxy and a nonempty `DEVHUD_TRUSTED_PROXY_CIDRS`; the plaintext origin listener supports HTTP/1 and h2c so native gRPC is preserved. Invalid credentials return `Unauthenticated`, while transient Logto/JWKS failures return correlated `Unavailable` errors and are logged without credentials.
- It must not proxy GitHub or upload bodies, broker credentials, poll Decks, receive GitHub webhooks, or persist Deck results.
- CreateUpload must atomically reserve the rolling signed-URL issuance quota before issuing a signed URL; failed issuance rolls back the reservation, and FinalizeUpload validates the reservation without charging it again. FinalizeUpload must revalidate ownership/block state and the exact staging object and server-issued upload-group binding, verify size/checksum/image safety, atomically recheck or reserve all other applicable upload quotas, reject replay, and clean invalid staging objects. Publishing and removal rows remain recoverable until the sweeper reconciles their external effects and persists completion; uncertain public replacement and unconfirmed removal-lease release stay pending, and delayed administrator removal audits retain the claim-time actor fingerprint. Deletion and quarantine must replace or remove origin bytes before invalidating public CDN copies; the operation is not effective while the original remains retrievable from a CDN cache. Account purge must remove or irreversibly pseudonymize upload metadata.
- RestoreAccount and final purge must serialize through an atomic account-state transition or row lock: purge claims the account before destructive work, and a successful restore cannot follow irreversible deletion. Purged-identity tombstones use a key-rotation-independent, domain-separated digest so retiring identity HMAC keys cannot recreate a deleted account. The implemented idempotent `devhud-api-sweeper` owns post-recovery purge, staging expiry, deferred upload cleanup, upload-removal reconciliation, and request/audit/crash-report retention; retention transactions remain batch-bounded while each iteration drains repeated batches until all three tables return a partial batch or its deadline ends. Work is coordinated across instances with a database lease or advisory lock; the sweeper PostgreSQL pool must allow at least two connections, and sessions with indeterminate lock acquisition or failed unlock results are discarded.
- Sweeper pool creation and schema readiness use a signal-aware 15-second startup deadline before the existing per-iteration deadline applies.
- CORS must use the exact DevHud development and pinned Tauri origins, with explicit Connect preflight methods and headers, exposed `x-devhud-correlation-id`, and no wildcard origin/header policy. The R2 staging bucket separately allows only those origins, `PUT`/`OPTIONS`, `Content-Type`, and `x-amz-checksum-sha256`, with `ETag` exposure.
- API request handlers must impose the fixed 25-second server execution deadline even when clients omit `Connect-Timeout-Ms`; shorter caller deadlines remain authoritative so PostgreSQL work cannot outlive the request bound.
- `GetBootstrap` is unauthenticated; settings, uploads, diagnostics, and account methods use authenticated user/ownership policies; user upload listing is owner-filtered, user upload deletion verifies ownership, user upload listing is bounded and paginated, and AdminService requires `devhud-admin`.
- Implement the finalized `devhud.v1` contract directly with generated Connect-Go bindings; do not introduce a duplicate REST business API. Every success and Connect error carries its UUID-v7 correlation metadata in the message/detail and `x-devhud-correlation-id` header.
- Settings storage accepts at most 1 MiB RFC 8785 canonical JSON bytes. `ReplaceSettings` accepts only schema v7 and increments revisions exactly once after matching the expected revision and digest. Legacy v1-v6 snapshots are migration inputs only: validate and completely transform their GitHub, Deck, URL-mapping, agent, local-only, and R2 fields, validate and canonicalize the v7 result, increment its revision once, and store the matching digest. Pagination rejects page sizes above 100 and opaque tokens above 2 KiB. Crash reports accept only typed, previewed redacted details with UUID v7 client correlation, bounded duration/related IDs/stack metadata, browser-only unknown architecture, explicit browser and native runtime revision rules, NUL-free 256-byte build identifiers, 64-byte uppercase enum-style error codes, a 4 KiB summary, and a 32 KiB stack; arbitrary absolute paths and raw PAT formats are rejected, each user may retain at most 100 reports, reports expire after 30 days, and they cascade on account purge. Idempotent retries remain available at the cap, while excess fresh submissions return `ResourceExhausted`.
- Bootstrap publishes the native callback, the `desktop`/`ios`/`android`/`admin` public client IDs, and the exact deployment-configured admin redirect; the admin SPA uses PKCE with state/nonce validation. The API deployment serves the signed updater manifest route, and the separate sweeper deployment ships as a signed/provenanced OCI image. RestoreAccount clears deletion state only and never an administrative block.
- Official production hosting remains operator-selected. The coordinated release workflow may provide immutable API/sweeper digests and already signed updater material only through the OIDC-authenticated, provider-neutral interface in `docs/servers-devhud-release-controller-contract.md`; it must not hard-code a hosting provider or pass long-lived provider credentials.
- The unauthenticated desktop updater manifest route is GET/HEAD only, stable-only, target/package allowlisted, bounded, no-store, and backed by operator-provided read-only signed schema-one manifest envelopes. Reject structurally invalid stored envelopes before serving them. Classify its concrete request paths under one fixed low-cardinality observability label. Reject every request carrying a browser `Origin`; never add signing keys, tokens, arbitrary channels/paths, redirects, or frontend CORS access to this service. Follow `docs/apps-devhud-updater-contract.md`.
- Uploads are scoped to a server-owned submission UUID spanning all upload groups, capped at 10 finalized images; signed checksums are 32 raw bytes with standard Base64 conversion only for the R2 header, versioned staging objects are required for conditional promotion, and PNG IHDR dimensions must be rejected above 4096×4096 or 16,777,216 pixels before decoding.
- Administrator handlers require mutation reasons containing non-blank, NUL-free, well-formed UTF-8 text capped at 4 KiB and reject credential, configured public asset locator, and local-path patterns with `InvalidArgument` before persistence. They return only previously validated reasons in the admin-safe user, usage, metadata-only upload, and audit views defined by the schema, and must never populate settings bodies, secrets, DOM, screenshots, public or signed asset locators, Deck results, agent output, or local paths in messages or errors.
- Keep `docs/servers-devhud-api-contract.md`, `docs/protos-devhud-v1-contract.md`, and `docs/project-devhud.md` synchronized with every interface or operational change.
