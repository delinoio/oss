# servers-devhud-api-contract

## Scope

`servers/devhud-api` is an implemented stateless Go service backed by PostgreSQL, Cloudflare R2/CDN controls, and external Logto. It registers `BootstrapService`, `SettingsService`, `UploadService`, `AccountService`, and `DiagnosticsService`; Admin RPC registration, embedded admin assets, and updater serving remain planned. Upload administrator operations are internal metadata-only hooks for the later AdminService slice. Its fixed development port is `46307`. The separate `devhud-api-sweeper` owns bounded post-recovery account/upload purge, R2 staging expiry, and request/audit/crash-report retention cleanup.

## Runtime and Language

Go service using `log/slog`, Connect RPC, embedded migrations, database-independent `/healthz` and schema-aware `/readyz`, OpenTelemetry-compatible traces/metrics, Prometheus `/metrics`, and separate non-root OCI targets for the API and sweeper. Liveness requests are not persisted to PostgreSQL request logs. The implemented REST surface is limited to health/readiness and metrics. Future REST remains limited to embedded admin assets, public CDN behavior, and the signed updater manifest route at `/updates/{channel}/{platform}/{architecture}.json`; the API deployment will serve that route from the fixed `https://devhud.api.delino.io` origin.

Run migrations with `go run ./servers/devhud-api/cmd/devhud-api migrate`, run the API with the `serve` argument, and run the sweeper continuously or once with `--once`. The API image defaults to `serve`, while a runtime argument such as `migrate` replaces that default command. Runtime configuration uses `DEVHUD_DATABASE_URL`, `DEVHUD_PUBLIC_API_URL`, `DEVHUD_LOGTO_ISSUER`, `DEVHUD_LOGTO_AUDIENCE`, the four `DEVHUD_LOGTO_{DESKTOP,IOS,ANDROID,ADMIN}_CLIENT_ID` values, `DEVHUD_ADMIN_REDIRECT_URI`, `DEVHUD_PUBLIC_ASSET_BASE_URL`, and a comma-separated Base64 `DEVHUD_IDENTITY_HMAC_KEYS` key ring whose first value is active. Production additionally requires `DEVHUD_LISTEN_ADDRESS` and at least one `DEVHUD_TRUSTED_PROXY_CIDRS` entry because TLS terminates at a trusted reverse proxy before the plaintext service listener; that origin listener accepts HTTP/1 and h2c so the proxy can preserve native gRPC. The sweeper accepts bounded `DEVHUD_SWEEPER_BATCH_SIZE` (1–500) and `DEVHUD_SWEEPER_INTERVAL` (1 second–1 hour), and its PostgreSQL pool must allow at least two connections so coordinated work retains capacity behind the session-level lock. Sweeper pool creation and schema readiness share a signal-aware 15-second startup deadline; each continuous or `--once` iteration has a fixed 25-second execution deadline and preserves an earlier parent cancellation or deadline. Optional standard OpenTelemetry exporter variables enable OTLP traces. Development rejects any listen address other than `127.0.0.1:46307`.

Upload configuration adds `DEVHUD_R2_ENDPOINT`, `DEVHUD_R2_ACCESS_KEY_ID`, `DEVHUD_R2_SECRET_ACCESS_KEY`, `DEVHUD_R2_STAGING_BUCKET`, `DEVHUD_R2_PUBLIC_BUCKET`, `DEVHUD_CLOUDFLARE_API_TOKEN`, `DEVHUD_CLOUDFLARE_ZONE_ID`, and `DEVHUD_CLOUDFLARE_RATE_LIMIT_RULE_ID`; secrets never enter Bootstrap or logs. Production startup reads the staging CORS policy and named public rate-limit rule and fails unless they match the committed `deploy/` contracts. The sweeper requires the R2/CDN values so it can expire staging and replace account-purged public objects, and it applies the same credential-free HTTPS endpoint policy as the API before constructing its R2 client.

A trusted direct proxy must provide exactly one `X-Forwarded-Proto` value equal to `https`; comma-separated chains and repeated fields are rejected. Direct loopback HTTP is a development-only exemption, so production loopback proxies must also be configured as trusted and provide forwarded HTTPS. API request execution is bounded to 25 seconds even when a client omits `Connect-Timeout-Ms`, while a shorter caller deadline remains authoritative; PostgreSQL repository calls inherit that bound. OIDC verification, including a remote JWKS refresh, is bounded to five seconds or the caller's earlier deadline. Invalid tokens return `Unauthenticated`; transient JWKS timeouts, network failures, rate limits, and upstream server failures are safely logged with correlation/procedure metadata and return `Unavailable` without exposing credentials. Either the standard generic `OTEL_EXPORTER_OTLP_ENDPOINT` or trace-specific `OTEL_EXPORTER_OTLP_TRACES_ENDPOINT` enables OTLP traces, with exporter-defined signal-specific precedence. Release API images pass `VERSION` as a Docker build argument, which is linked into the Bootstrap API version; omitted local builds retain `0.1.0-dev`.

## Users and Operators

DevHud guest/authenticated clients, self-hosting operators, `devhud-admin` operators, and deployment/release operators.

## Interfaces and Contracts

Services in package `devhud.v1`: `BootstrapService.GetBootstrap`; `SettingsService.GetSettings`/`ReplaceSettings`; `UploadService.CreateUpload`/`FinalizeUpload`/`ListUploads`/`DeleteUpload`; `AccountService.GetAccount`/`DeleteAccount`/`RestoreAccount`; `DiagnosticsService.SubmitCrashReport`; and the documented Admin methods. The server registers Bootstrap, Settings, Upload, Account, and Diagnostics. `GetBootstrap` is unauthenticated. Settings, Upload, and Diagnostics require an authenticated user whose block/deletion state is transactionally revalidated; user upload lists are owner-scoped and bounded, and deletion resolves ownership without disclosing another user's record. Bootstrap always advertises crash reports as a static compatibility capability, never a remote feature flag; it advertises `OFFICIAL_UPLOADS` only when its upload adapters are configured.

The server implements the generated Connect-Go handlers directly; no duplicate REST business API is permitted. Service-owned identifiers are canonical lowercase RFC 9562 UUID v7 values and schema versions are unsigned. Every successful response contains `ResponseMetadata` and every Connect error, including handler-generated decoding and protocol errors, carries `ErrorMetadata`; their UUID-v7 correlation ID matches the exposed `x-devhud-correlation-id` header. Bootstrap uses explicit platform client fields and explicit native/admin redirects, and its capability enum values are static compatibility declarations.

Use `Unauthenticated`, `Unavailable`, `PermissionDenied`, `InvalidArgument`, `Aborted`, `ResourceExhausted`, and `FailedPrecondition` for the contracted failure classes. Invalid administrator mutation reasons return `InvalidArgument`. `RestoreAccount` requires authenticated ownership, is idempotent during the 30-day recovery window, cancels only the pending deletion-state block, and never clears an independent `AdminService.SetUserBlocked` administrative block; calls after the window return `FailedPrecondition`. An administrative block continues to gate all operations that require an unblocked user. Attach a UUID v7 correlation ID to every response/log context and return it in the `x-devhud-correlation-id` response header. The API never receives PAT values or GitHub requests, proxies GitHub or R2 upload bodies, stores Deck results, polls Decks, receives webhooks, or acts as a GitHub credential broker. Settings may carry only stable non-secret GitHub profile descriptors, explicit profile references, and pending PAT-removal tombstones; snapshot envelopes and canonical JSON bodies must declare the same schema version.

Settings snapshots are at most 1 MiB of RFC 8785 canonical UTF-8 JSON bytes. No stored snapshot is represented by absence; expected revision zero creates revision one, every matching replacement increments the revision exactly once, and stale writes return `Aborted` with `SettingsRevisionConflict`. List RPCs default to 50 records, reject page sizes above 100, reject opaque tokens above 2 KiB, scope tokens to the authenticated actor plus normalized filters, and order newest-first with UUID descending as the tie-breaker. Invalid page input returns `InvalidArgument`.

The API CORS allowlist is exact: `http://localhost:46305`, `http://127.0.0.1:46305`, `http://localhost:46306`, `http://127.0.0.1:46306`, and the pinned Tauri shell origin `http://tauri.localhost`. The implemented Connect handlers and preflight permit only `POST` and `OPTIONS`; GET may be enabled per procedure only when a read-only handler explicitly declares no-side-effects idempotency. Preflight permits `Content-Type`, `Connect-Protocol-Version`, `Connect-Timeout-Ms`, and `Authorization`, exposes `x-devhud-correlation-id`, and otherwise exposes only required Connect response metadata. Origins, methods, and headers are not wildcarded. The private R2 staging bucket uses the committed separate exact CORS policy with the same five origins, `PUT`, `Content-Type` and `x-amz-checksum-sha256` request headers, and `ETag` response exposure. Cloudflare handles preflight `OPTIONS` implicitly and does not accept `OPTIONS` in the R2 `AllowedMethods` enum. No wildcard is allowed.

Before persistence, `ReplaceSettings` validates the complete supported versioned settings schema, requires the body schema version to match the envelope, rejects unknown/device-local/secret fields and recognizable credential values recursively, and returns `InvalidArgument` without calling the repository on failure.

## Storage

Readiness resolves the migration ledger through the database connection's configured search path and compares the exact ordered embedded migration-name set with that ledger; a missing expected migration or an unknown ledger entry is not current. The restore-retry migration retains an internal copy of the original recovery deadline so retries are idempotent only while that window remains open.

Request logs retain HTTP transport status and, for registered Connect/gRPC procedures, the canonical protocol status independently so gRPC and gRPC-Web failures carried over HTTP 200 remain observable.

The implemented migrations persist users, settings, purged-identity tombstones, request logs, pseudonymized audit events, server-owned submissions/groups, signed-URL reservations, immutable object bindings, operation leases, quota charge timestamps, and upload tombstones. A PUT credential expires after 15 minutes while its independent staging cleanup deadline is 24 hours. `CreateUpload` requires an explicit target: a new submission and first group, a new group in an owned submission, or an existing owned group. It atomically locks the user, reserves the exact rolling-hour URL quota, builds the server identifiers, and invokes signing inside the transaction; any signer failure rolls back every row. Finalization does not charge that quota again. It revalidates account state, ownership, all submitted bindings, object ETag/size/type/checksum, the complete PNG signature/IHDR prefix, and atomically locks the user and submission while enforcing 10 active finalized images, 1 GiB rolling-day bytes, and 20 GiB stored bytes. Equality at each limit is accepted; an operation that crosses it is rejected. Publishing/removal leases make retries recoverable without allowing replay. A publishing row whose public promotion may already have succeeded retains its operation token at staging expiry; the sweeper idempotently reconciles and persists that promotion before deleting staging or permitting metadata expiry. Invalid staging is tombstoned and deleted, but cleanup is not marked complete before its signed PUT expires so a recreated key remains eligible for the 24-hour sweep. The sweeper owns expired/deferred cleanup, gives failed object deletions and promotion reconciliation a bounded retry delay without starving later batches, and preserves existing terminal rejection/removal states. Deleted or quarantined originals are conditionally replaced by the embedded bilingual marker before CDN purge and no-cache revalidation; only then is the tombstone completed and its submission slot freed. Administrator removal completion and its audit event commit atomically after those external effects, so a database failure leaves a recoverable removal lease rather than an unaudited terminal mutation.

The server issues 256-bit base64url public/staging identifiers and returns the exact stable `<public-base>/<43-character-id>.png` URL. The signed request binds `Content-Length`, `Content-Type`, and standard-Base64 `x-amz-checksum-sha256`; the protocol carries checksum bytes raw. Native R2 presigned URLs are otherwise reusable before expiry, so one-use is an application invariant: every reservation has a unique key and one terminal finalization, and conditional inspection/promotion pins the observed ETag and recorded generation. The API reads only a conditional 33-byte PNG prefix and never accepts or proxies screenshot bodies. `UploadReservation.expires_at` is the PUT deadline and `staging_expires_at` is the cleanup deadline.

Retain request logs at most 30 days and accepted crash reports exactly 30 days; retain at most 100 crash reports per user and pseudonymized security/admin audit events at most 180 days. Crash rows carry an owner foreign key only for transactional authorization and account-deletion cascade; that identifier is never emitted into logs, traces, metrics, or responses. Client correlation plus deterministic payload digest provides idempotent retry even when the retained-report cap is full, reusing a client correlation for another payload fails, and a fresh submission above the cap returns `ResourceExhausted`. Per-user submission transactions serialize the eligibility, idempotency, and retained-count checks so concurrent requests cannot cross the cap. Account deletion blocks immediately, permits 30-day recovery, then uses the same marker-replacement/cache-revalidation path for every public upload, deletes remaining staging, and removes upload ownership/keys/checksums/timestamps before the user row is purged. Retained administrator audits keep pseudonymized actor/target fingerprints only. The sweeper performs recovery-complete account purge, staging expiry, deferred staging cleanup, and bounded request/audit/crash-report retention under its multi-instance advisory lock.

## Security

Upload hardening: the first upload request creates a server-owned UUID v7 submission with its first group; later groups and finalizations carry both IDs and the submission owns the maximum of 10 finalized images across all groups. Signed URLs bind the expected 32-byte SHA-256 checksum and versioned staging object. Finalization checks PNG IHDR dimensions before decoding, rejecting width or height above 4096 or total pixels above 16,777,216, and promotes only the recorded version with conditional ETag/checksum validation.

Validate Logto credentials and admin role. Settings validation accepts structured schema-v3 URL-mapping records only when their bounded fields, UUID-v7 IDs, browser-compatible URL-pattern host safety (including rejecting wildcard hosts whose IDNA canonicalization changes DNS-label structure), repository/profile references, priorities, optional concrete HTTP(S) Chrome origins with numeric ports no greater than 65535, 32-or-fewer canonical path segments, 8-or-fewer canonical globstars, and canonical timestamps are valid; every structured mapping profile reference must identify a configured GitHub profile. Schema-v1/v2 prefix-shaped mappings are validated for migration compatibility but cannot select a repository/profile; structured entries are rejected before schema v3. Never persist or log PATs, R2 secrets, Logto tokens, DOM, screenshots outside upload ownership, issue bodies, agent output, or local paths. Official uploads require authenticated, unblocked users. BYO R2 credentials never reach this service.

Crash reports accept schema version 1, a client-generated UUID v7, request/related UUID v7 correlations, duration up to 24 hours, and typed build, platform (including browser), architecture (including Android armv7 and browser-only unknown), component, severity, and enum-style error-code fields. They carry app/build version and OS classification; native reports require an explicit architecture and exact lowercase 40-hex Tauri revision while browser reports require the Tauri revision to be empty, and desktop reports require an exact CEF runtime revision while mobile/browser reports require it to be empty. Related IDs are unique and capped at 32. Build identifier strings are capped at 256 UTF-8 bytes and error codes at 64 uppercase enum-style bytes; error codes are structurally validated classifications and are not scanned as narrative content. User-previewed redacted diagnostic summary is capped at 4 KiB and stack trace at 32 KiB, 64 lines, and 512 bytes per line. Server validation of build and narrative text rejects NUL bytes, credential/token/authorization/PAT/R2/signing patterns, including raw GitHub PAT formats, URL userinfo and decoded credential parameter names or values in URL queries/fragments, browser DOM, screenshots, form values, issue bodies, local-agent prompts/output, child environments, arbitrary Unix/Windows/UNC/home-relative absolute paths, and shortcut keystrokes before storage. Administrator mutation reasons must contain non-whitespace, well-formed Unicode text capped at 4 KiB of UTF-8 and reject credential and local-path patterns before persistence.

## Logging

Use `log/slog` structured logs with request, client, and report UUID v7 correlations and redaction. Diagnostics spans include safe correlation/platform/component attributes, and existing bounded request metrics cover procedure/status/duration without user labels. Request logs and metrics record canonical RPC status separately from HTTP transport status; unexpected authentication, settings, and diagnostics repository failures retain safe causes without exposing bodies. Diagnostics repository failures use bounded PostgreSQL/deadline/cancellation/network/unknown categories and include only validated five-character SQLSTATE values when available, never raw repository error text. Provide safe diagnostics, health/readiness, traces, and metrics without product analytics. Crash reporting is opt-in per exact user-previewed payload and has no persistent setting or remote feature flag.

## Build and Test

Validation covers Go format/vet/unit tests, PostgreSQL migrations/integration, direct-upload header/checksum material, 256-bit identifier shape, encrypted/scoped pagination, every PNG dimension boundary, signer rollback, rolling URL equality, concurrent cross-group submission enforcement, replay rejection, non-double-charging, invalid staging cleanup, removal ordering, exact R2 CORS, and generated-contract freshness. Cloudflare origin/rate policies remain operator-applied artifacts and are live-validated at production startup.

## Dependencies and Integrations

Consumes generated `protos/devhud/v1` bindings and is consumed by `apps/devhud` through `packages/devhud-api-client`. Runtime requires PostgreSQL, Logto, private staging/public R2 buckets, the public asset custom domain, Cloudflare cache/rate controls, public client identifiers, and an HMAC identity key ring. Future Admin work consumes the internal upload hooks and serves `apps/devhud-admin`; this slice deliberately does not register AdminService.

## Change Triggers

Update the project index, protocol/client/admin contracts, root and server `AGENTS.md`, migrations, CI, and release contracts when RPCs, storage, retention, security, quotas, or deployment requirements change.
