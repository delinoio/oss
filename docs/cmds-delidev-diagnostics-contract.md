# DeliDev Read-Only Diagnostics

## Execution startup observations

[Direct startup](cmds-delidev-execution-startup-contract.md) exposes bounded closed phase/code, optional observed native version, executable digest, original job correlation and separate delivery/cleanup facts. The authenticated original Worker reports once against the claimed revision; duplicate receipts do not rerun work. Keep the first startup failure separate from later cleanup uncertainty. No raw native text, prompt, path, URL, credential or environment value enters these reports. Details and metadata copying perform no diagnostic or inference work. Optional machine discovery and Doctor reads retain their independent read-only contracts.

## Model request diagnostics (issue #1103)

`SessionService.ListRequestDiagnostics`, `delidev session diagnostics --id <session> [--execution-id <execution>] [--page-size 1..100] [--page-token <token>]` and the session Diagnostics panel provide separate metadata-only native-input and proxy-HTTP observations. The server advertises `REQUEST_DIAGNOSTICS_V1`. Owner and paired-client authorization is rechecked in the three-second-bounded SQLite read. Pages default to 50, cap at 100 and bind their signed 24-hour cursor to server identity, session, optional exact execution and page size. These are live revisioned observations, not a snapshot or a complete native request inventory. An empty or historical page cannot prove that no inference occurred.

Retained RPC rows require a nonempty original publication UUID. A successful proxy record requires an actual HTTP send claim and status 200; native-input success retains no HTTP evidence. Requested tier permits Anthropic `standard_only`, while the effective-tier allowlist excludes that request-only spelling. Whole-page desktop validation rejects missing or contradictory evidence.

Each record retains original UUID-v7 session/execution/account/connection/provider/model attribution, source, closed operation/state, purpose, original publication request, observation time and optional original identifiers. Current account aliases, native model names and deleted configuration cannot relabel historical attribution. Native binding/input/terminal projections share the original validated Worker publication's state/event/receipt transaction. One native input uses its immutable original turn-request UUID; exact outbox receipt replay cannot duplicate or update the record. Observed native thread/turn and selected versus effective effort/tier remain independent of any HTTP attempt. Historical executions with no original binding record are never backfilled. Native latency and HTTP-attempt fields are unavailable.

Each validated proxy invocation has one distinct generated correlation/record UUID, even for concurrent same-model requests or actual native retries. It commits a metadata-only initial observation before protected credential lookup. Credential lookup failure settles that observation with no HTTP attempt or unguarded request fields. After successful lookup, only the first in-progress, unsent revision may acquire guarded request settings and the original safe caller request ID; every later revision preserves those fields exactly. It commits a separate revision-checked send claim before its single HTTP call. `http_attempted` is the retained send claim: it may not have reached the provider and never proves acceptance. Proxy transport does not retry. The completed observation includes monotonic elapsed milliseconds measured from validated request processing through downstream response delivery, optional original upstream HTTP status, closed error classification and observed provider response settings. Native input settings are never substituted for missing per-response settings. Missing fields are unavailable; zero observed latency is preserved. Safe incoming `X-Client-Request-Id`, protocol-owned upstream request IDs (`X-Request-Id` for OpenAI-shaped APIs and `Request-Id` for Anthropic Messages), and response IDs are retained only when they satisfy the bounded opaque-ID profile and existing raw/decoded/Base64 protected-value guard. Request headers are not forwarded as caller-selected upstream authority.

Only the original lease callback may publish proxy records. Initial/send publications recheck current execution authority; completion updates only the exact retained original revision and immutable attribution, under a separate three-second context inside the original joined lease. Stop/revocation therefore cannot erase an already observed attempt. Proxy publication atomically commits the diagnostic revision, reference-only receipt and a session invalidation event at the unchanged session-state revision; native projection retains the original native session event transaction. Publication failure logs a stable code/correlation; retained in-progress/send-claimed metadata remains uncertain after failure or restart and is never completed or retransmitted by inference. Native cleanup remains separately authoritative. Conflicting provider response identities or observed settings stay unavailable for the rest of that exact HTTP stream; later frames cannot restore certainty.

Schema 27 adds only the private diagnostic table/indexes, using the existing synchronized pre-migration backup. Retain at most 10,000 records per session with 4 KiB per record; new admission fails closed without eviction, while existing records may settle. Session deletion cascades the rows. Durable publication receipts contain only record identity/revision and cannot recreate deleted rows. Retained diagnostics never ingest usage, update pricing/budgets, probe accounts or change Doctor behavior. Requested/effective setting strings use closed effort/tier allowlists; unsupported spellings remain unavailable. No request/response payloads, instructions, credentials, native paths, raw email, original error prose or mutable display labels enter this read model or its logs.

The desktop validates the complete page before display, preserves exact bigint revisions/durations, labels native versus HTTP provenance and provider-acceptance uncertainty, supports an exact execution filter, explicit refresh/pagination, Escape closure and restored trigger focus, and disposes diagnostic queries on close. Reads create no mutation intent or automatic retry. Unsupported server capability remains explicitly unavailable.

## Scope
`cmds/delidev-cli/internal/server/diagnostics.go`, the domain diagnostic report, store capacity measurements and credential inspection boundary implement `delidev doctor` and `SystemService.GetDoctor`. The desktop Settings presentation consumes the same server report. This contract implements bounded metadata and existing protected-reference observations; it does not claim the complete issue's remaining integrations or platform acceptance.

## Runtime and Language
Go owns observations and authorization. TypeScript renders the report through direct authenticated Connect RPC. Native credential and filesystem adapters use the existing server platform boundary; Rust does not inspect account secrets.

## Users and Operators
The single server owner and its authorized paired clients may request diagnostics. Workers supply retained installation/version metadata through their existing authenticated observations; doctor does not start or probe a Worker or an installed harness.

## Interfaces and Contracts
`delidev server overview` and `SystemService.GetOverview` provide a separate lightweight owner/client-only presentation observation. One authorized, three-second-bounded database read counts retained active execution ownership (including uncertain cleanup), current open unanswered interactions in active sessions, all registered Workers and currently connected Workers. Inbox read state does not affect pending counts. A Worker is connected only with an independently sampled live stream, enabled machine, unrevoked Worker device and fresh heartbeat lease; this is not selected-account or harness readiness. An oversized live inventory fails without partial counts. Exact uint64 values preserve zero and large counts. Observation time plus half-open UTC midnight-to-observation usage boundaries let clients request today's existing usage summary without relying on the client clock. No account-store inspection, inference, filesystem work, mutation, source document or credential is involved; ordinary `server status` remains unchanged.

`GetDoctor` keeps its existing empty request and `report_json` response. `delidev doctor` emits the same JSON in the ordinary CLI result envelope. Version 2 adds `schema_version`, UTC observation time, running server/protocol/database schema versions, server platform, storage measurements, Worker observations and account credential observations. The original version, server identity, bound endpoint, database read result, loaded owner credential and `inference_probes: false` remain compatible with legacy consumers. A loaded owner credential is not proof of protected account-store availability.

The request has a 20-second context budget and checks cancellation between native operations. Existing platform calls are synchronous and joined; the budget does not claim it can preempt an uninterruptible OS call. Return at most 1 MiB of JSON. Each inventory includes at most the first 50 canonical-ID-ordered records, with separate `more_machines`/`more_credentials` flags. These partial inventories are not whole-server health summaries; use individual settings/resource reads for remaining records. SQL snapshots, filesystem samples, native reads and stream presence are separate observations, not a globally atomic system snapshot.

Worker records expose opaque machine identity, configured name, last reported version/OS/architecture/contact, disabled state and current server stream presence. An absent stream does not establish process exit; a present stream does not prove native execution health. Include all four harnesses, using `unchecked` for an absent retained observation. Project only version/installation state, retained capabilities, protocol state/verification, observation time and locally reconstructed stable problem code/guidance. Exclude selected/resolved paths and original error bodies. Version discovery, protocol handshake, selected-account readiness and owned cleanup remain distinct.

Credential observations use closed states `observed`, `unavailable`, `unconfigured`, `not-applicable`, `failed` and `superseded`. A connected API account checks exactly its current account/connection/purpose reference and immediately clears the returned plaintext, including failure paths. Successful decryption means only that this saved credential was readable. Keyless connections require no native access; disconnected accounts are unconfigured; current service-native ChatGPT inspection follows the read-only adapter below; native-only Claude, unactivated Grok and retired/unknown subscription shapes remain unsupported. Missing/locked/damaged storage returns a safe code and platform-specific recovery guidance, without key replacement, login, validation or inference. A changed/deleted connection at publication supersedes the original observation without relabeling it as the current connection.

### ChatGPT saved-storage adapter

Doctor selects only explicit service-native ChatGPT accounts with valid server-owned metadata. An idle connected account with a valid saved generation reads exactly its account/generation `AccountLogin` reference, using the existing vault or the non-creating `OpenExisting` path. The connection ID is not the credential generation. Clear every returned plaintext buffer immediately, including partial failure results. Do not parse the bundle, validate tokens, inspect native account files or contact a provider.

Pending lifecycle work, a Worker lease, active or native-started server work, active or uncertain quota/reset-credit work, removal, recovery and unresolved cleanup defer inspection as `unavailable` with the safe `unavailable` code and no protected read. Retired-uncertain observations retain that exclusion. Completed operation history alone does not block an otherwise eligible account. Fully disconnected metadata without a saved generation, identity commitment or retained ownership/fences is `unconfigured`; a retained generation without a connection or a connected account without a valid generation is `unavailable`. A completed failed-initial-login credential cleanup checkpoint can remain as inert history. Never enumerate orphan references or convert a read into cleanup proof.

Retain type/service, connection/authentication, generation, identity commitment and inspection eligibility only in request-local bookkeeping. Recheck those selectors after final authorization before publication. Deletion, replacement, same-connection bundle rotation or eligibility changes supersede the original observation with `conflict`. Alias-only edits do not invalidate it. Neither the generation nor bundle content appears in report JSON or logs. Successful readability establishes no authentication, execution readiness, quota, native cleanup or recovery completion. Existing API/OAuth/keyless inspection remains separate. No report schema, public RPC, protocol allocation, migration or native change is required.

Desktop layout, accessible disclosures, visible failure ownership and opening lifecycle follow the [Diagnostics presentation contract](apps-delidev-diagnostics-contract.md). Presentation does not change this report, authorization or read-only boundary.

## Storage
Doctor never creates mutation receipts/events, repairs SQLite, runs a checkpoint/vacuum, creates missing vault state, reconciles credential scratch files or writes/removes native keys. Read SQLite page count/page size and resource-kind counts in one read transaction. Outside the transaction, inspect private regular database/WAL file sizes and OS filesystem capacity/space available to the server user. A missing optional WAL is zero; failed/unavailable measurements remain absent. Preserve already observed fields after a subsequent measurement failure, with a failed/unavailable result. Counts may also be incomplete on failure. Physical database bytes, WAL bytes and logical database bytes overlap and must not be added or interpreted as reclaimable storage. Backups, workspace disk usage, native history and user files are not recursively scanned.

All uint64 sizes/counts are canonical decimal JSON strings, including zero. The desktop validates their range and formats with BigInt; it must not convert them through floating-point numbers. Missing/invalid fields stay unavailable rather than becoming zero.

## Security
Revalidate paired-client authorization before database/native reads and again before report publication. Serialize each account inspection under the normal account gate, release SQLite transactions before native work and recheck all original connection identities at publication. Reuse the already open protected vault when available. Otherwise use `credentials.OpenExisting`: require the existing private directory, existing regular private lock, exclusive non-creating OS lock and matching server pin; never initialize or repair any state. The temporary vault is read-only and rejects Put/Delete, is closed after inspection, and is never installed as the normal writable server vault.

The report/log boundary retains stable error codes and locally owned guidance only, not raw OS/provider diagnostics, executable paths, secret bytes, prompts or credential enumeration. On macOS, reading an exact protected reference may display an OS-owned Keychain authentication prompt in the server user's session under the credential contract. Approval continues the original read; cancellation or inability to display the prompt returns a safe failure without modifying product records. OS authorization may unlock the Keychain, but Doctor never collects a password or invokes a separate unlock operation. Linux and Windows inspection remains noninteractive. No platform accesses unrelated native entries. Ordinary tests use mock native storage, absent scopes or connected keyless fixture accounts; they do not read the user's credentials.

## Logging
`doctor_observed` logs correlation, storage classification, inventory counts and truncation flags. Existing credential-read failures log only safe operation/owner/purpose/code fields; `AccountLogin` read failures omit the credential reference ID because it is the private subscription generation. API credential reads retain their separate original-reference diagnostics. A diagnostic request may produce operational logs, but it cannot alter product state. No measured content or secret value belongs in logs.

## Build and Test
Run `go test -race ./cmds/delidev-cli/...` and `go vet ./cmds/delidev-cli/...`. Read-only credential tests cover exclusive scope locks, non-creating lock access, missing pins, preserved scratch files, failed writes/deletes and unchanged sealed bytes. Server/store tests cover real temporary SQLite/filesystem measurements, exact secret references and clearing, missing vault preservation, superseded connections, revocation after native access, explicit truncation, cancellation and metadata/secret leak checks. Windows/Linux cross-builds prove compilation only. Run `pnpm test` in `apps/delidev`; component tests cover partial/legacy/unknown reports, precision, stale refresh and inert guidance, and actual temporary Go integration checks the Settings report without user credentials or inference.

## Dependencies and Integrations
Uses existing Connect System service, single-authority store, Worker stream registry and native credential adapters. No external monitoring service/exporter or additional reporting credentials are introduced.

## Change Triggers
Update scoped CLI/desktop AGENTS, the protocol and desktop contracts, project index and validation records in pull requests, issues and CI logs/artifacts when report schemas, scope, limits, native access or presentation guarantees change. New credential families require their own exact ownership and read-only inspection contract before doctor may access them.

### Codex native Fast tier — issue #1961

Original Codex native input records preserve exact selected/effective `fast` through the closed native tier filter. This applies only to original Codex native source evidence; other native harnesses and provider HTTP observations retain their existing tier domains. Unknown values stay unavailable/redacted. The server projection uses the immutable execution configuration and original applied-setting event, never current Worker settings or requested-to-effective substitution. Frontend validation retains the same source/harness boundary. Native Fast observations grant no billing, acceleration, entitlement, account or retry authority.
