# apps-devhud-foundation

## Scope

`apps/devhud` contains the implemented deterministic bilingual React/TypeScript frontend and target-isolated Rust/Tauri desktop, mobile, and widget hosts for `devhud`. Desktop uses pinned CEF; iOS and Android reuse the same frontend through system webviews, with native WidgetKit and AppWidgetProvider extensions. The shell implements the complete guest/Logto identity and schema-versioned Settings boundary against the generated Connect client, explicit Home, mobile RealQA-unavailable, populated Deck, Settings, Account, Diagnostics, Loading, Empty, Offline, Blocked, and Error compositions, a closed first-party registry, a direct-client GitHub.com issue/pull-request provider, accessible credential setup, and a versioned native bridge. Desktop capture, the bilingual editor, encrypted draft recovery, official/BYO direct image uploads, direct GitHub issue submission, Deck synchronization, and home-screen Deck widgets are implemented; other populated product-result surfaces remain planned.

## Runtime and Language

- Desktop: Tauri `tauri-runtime-cef` from `https://github.com/tauri-apps/tauri`, pinned to `c8c75b1f7f43e7cb1e7d773ed2f6f96fad2fe975`; CEF renders bundled resources only with restrictive CSP and no arbitrary navigation, popups, or downloads. For bundled resources, the default packaged policy denies connections and the host replaces only the `connect-src` response directive with the validated selected API, fixed `https://api.github.com`, and same-origin Logto discovery endpoint for the active session. Pinned CEF does not apply that response rewrite to the external Rsbuild development URL, so the package-owned frontend wrapper validates the exact Logto issuer from the administrator configuration path and Rsbuild emits a fixed development header that permits only `'self'`, `http://127.0.0.1:46307`, `https://devhud.api.delino.io`, `https://api.github.com`, the validated issuer origin, and `ws://127.0.0.1:46305`; it separately permits Rsbuild's injected inline styles and the fixed RealQA image schemes. Arbitrary custom API origins remain a packaged-session capability. Future signed-upload origins require the same explicit validation before entering a session policy.
- Mobile: Tauri/Wry using WKWebView on iOS and Android System WebView, with no CEF runtime or bundled browser engine. WidgetKit on iOS and AppWidgetProvider on Android make direct GitHub requests without a broker.
- Targets: macOS 13+, Windows 10 22H2+, Ubuntu 24.04 LTS on X11, iOS 16+ arm64 device and arm64/x64 simulators, Android 10/API 29+ arm64/armv7 production and x64 emulator; Android i686 is excluded.
- Bundle ID: `io.delino.devhud`; deep-link scheme: `devhud`. Fixed frontend port: `46305`.
- English source and Korean/English user-facing UI. Language and System/Light/Dark theme are authoritative synchronized settings for authenticated users and local guest settings otherwise; the shell mirrors the last applied appearance locally only to avoid an incorrect initial render before identity state loads. The resolved language updates localized content and tray labels, while the resolved theme sets the document color scheme so native controls follow the selected appearance. The shell follows Toss Design Guidelines and includes WCAG 2.2 AA-oriented checks for named controls, deterministic focus, reduced motion, high-contrast tokens, and Escape closure for its command palette; formal accessibility qualification remains pending.

## Users and Operators

Guest users, authenticated individual users, maintainers, and platform release operators. RealQA is desktop-only; Deck is desktop/mobile.

## Implemented Desktop Host

- The desktop Tauri wrapper rejects caller `-t`/`--target` overrides and stages the exact Native Messaging host executable path reported by Cargo under the artifact's effective target triple, with its artifact-derived executable suffix, so custom target directories and cross-target Cargo configuration cannot select or name a missing or stale sidecar.
- `apps/devhud/src-tauri` is a root Cargo workspace member. It uses authoritative upstream Tauri git dependencies at revision `c8c75b1f7f43e7cb1e7d773ed2f6f96fad2fe975`; the sole root patch redirects official crates.io `tauri`, `tauri-plugin`, and `tauri-utils` dependencies to that same revision so the official desktop deep-link plugins share one CEF runtime type graph. Branch dependencies, `feat/cef`, forks, every other Cargo patch, and vendored upstream modifications are forbidden and mechanically checked.
- `apps/devhud/cef-pins.json` records the resolved Tauri package versions (`tauri` 2.11.5, `tauri-build` 2.6.3, `tauri-cli` 2.11.4, and `tauri-runtime-cef` 0.1.0), CEF Rust crates `cef` and `cef-dll-sys` `151.8.1+151.3.24`, `download-cef` 2.3.2, their registry checksums, upstream source revisions, and every platform archive SHA-1. The verifier owns independent immutable copies of the CEF Rust and download-helper versions, checksums, revisions, and the six archive names and hashes. The runtime archive version is CEF `151.3.24+g2384915+chromium-151.0.7922.174`.
- The CEF Rust sandbox feature remains compiled. The selected runtime requires process sandboxing on macOS/Linux and uses the explicit Windows executable-host exception; compile-time features do not prove a process sandbox is active. The executable uses Tauri's CEF entry point so renderer, GPU, plugin, and other helper processes cannot enter browser-process application initialization. Production startup preflights the platform-specific CEF library, ICU/resource packs, locale, sandbox/bootstrap files, and macOS helper applications relative to the installed executable; Linux package resources are resolved from `<prefix>/share/DevHUD` next to `<prefix>/bin`. Missing material produces a structured `cef_fatal_initialization` diagnostic with bounded actionable reason classifications and exit code 78 before the browser starts, without logging resolved host paths.
- Navigation is restricted to bundled `http://tauri.localhost` content in production and exact `http://127.0.0.1:46305` content in development. Popups and downloads are denied. The Rsbuild development launcher binds only `127.0.0.1:46305`, preflights collisions, and never chooses another port. The Tauri command wrapper rejects all `-c` and `--config` overrides, including attached short values, so callers cannot replace the pinned application configuration; it injects the repository-owned desktop bundle overlay and, for AppImages, a generated file mapping for the checksum-verified pinned launcher, the locally compiled checksum-verified anylinux source, and its original MIT license before invoking the bundler, while the shared desktop/mobile configuration remains sidecar-free. It forwards `SIGINT` and `SIGTERM`, mirrors signal-based exits, and on every supported desktop platform terminates and awaits the complete Cargo, Tauri CLI, desktop-host, and Rsbuild process tree. Timed-out platform smokes use the same complete-tree termination on every supported desktop platform before temporary cache and log cleanup.
- Structured diagnostics cover platform/display selection, resource discovery, frontend readiness, renderer termination, fatal initialization, smoke shutdown, clean host shutdown, external-opener failures, tray hide/restore failures, tray-language update failures, and capture failures identified only by action, adapter platform, and stable error code. After React mounts, it changes the document title to `DevHUD` and invokes the native `frontend_ready` command; the host atomically accepts that CEF-supported readiness signal before dispatching smoke behavior. An independent five-second wall-clock watchdog emits `frontend_readiness_timeout` and terminates with exit code 1 if readiness does not complete. Every packaged macOS, Windows and Linux launch uses the typed CEF renderer-termination callback. The deliberate `Page.crash` request and its watchdog remain exclusive to the renderer-crash smoke. Desktop release hosts retain timestamped, redacted JSON diagnostics in UTC-daily `devhud.YYYY-MM-DD.jsonl` files under `%LOCALAPPDATA%\io.delino.devhud\logs` on Windows, `~/Library/Logs/io.delino.devhud` on macOS, and `${XDG_STATE_HOME:-~/.local/state}/io.delino.devhud/logs` on Linux, keeping at most seven daily files while preserving stderr output for managed launches and smoke capture; destructive diagnostic cleanup closes the active file sink, removes only exact app JSONL names, and reopens the sink before later events. Operator `RUST_LOG` filters may tune dependency verbosity, but cannot suppress error-level DevHUD diagnostics. Debug builds and CEF subprocesses remain stderr-only; a file-sink setup failure falls back to stderr without logging the resolved path while retaining that directory for later destructive cleanup.

- Each fresh supported desktop process requests native CEF maximization for its manually created main window, not fullscreen, while retaining native decorations, work-area bounds, a 960×640 restored inner size, and a 640×480 minimum inner size. Tray, forwarded deep-link, and shortcut restoration operate only on an existing window by unminimizing, showing, and focusing it; they never maximize it or reset dimensions after user interaction.

## Interfaces and Contracts

### Internal UI and responsive shell

- The DevHud frontend owns its UI foundation in `apps/devhud`; it is not a public package and adds no UI or icon dependency. - The shell derives one exact viewport layout without changing `SurfaceId`, `ActionId`, or either closed registry. Widths of 1024px and above use a fixed 232px sidebar containing Home, RealQA, Deck, Settings, Account, and Diagnostics, with internally scrollable destinations that keep the palette control reachable on short viewports and main content capped at 1280px. Widths from 701px through 1023px use a fixed 72px icon rail with the same six destinations, a compact visual mark whose heading retains the full localized accessible app name, and localized tooltips exposed on pointer hover and keyboard focus. Widths of 700px and below use a compact safe-area-aware top app bar and a fixed bottom navigation containing exactly Home, Deck, Settings, Account, and More. The app identity remains the single level-one heading in every layout, above each surface's level-two heading hierarchy.
- More is internal navigation metadata, not a surface or action identifier. It opens a modal sheet containing RealQA and Diagnostics, leaves the selected surface unchanged until an entry is activated, remains current while either grouped surface is selected, closes through Escape or its localized back control, contains keyboard focus, and restores focus to its opener. An incoming consumed Deck link closes the sheet without restoring that opener before selecting Deck. More is unavailable while a screen-owned modal confirmation is open, so the sheet cannot displace that modal's focus containment. Mobile-runtime RealQA entries retain the existing `Desktop only` guidance and never expose capture controls; a narrow desktop retains its advertised capture capability.
- A localized skip link focuses the real main-content target. The command palette uses the shared dialog while preserving capability filtering, search and action behavior, contained focus, Escape close, trigger restoration, and the Account API-origin focus exception. Shared dialog and sheet behavior owns initial focus, forward/reverse focus containment, Escape dismissal, and optional opener restoration; screen-specific modal migrations remain owned by their surface work.
- Home contains only existing-tool cards for RealQA, Deck, Settings, and Diagnostics. It introduces no feed, analytics, product data, surface, action, or persistence. RealQA discovery copy remains availability-neutral because the same summary appears on supported and unsupported desktop shells; unavailable desktop surfaces retain their explicit notice. On mobile runtimes the RealQA card is labeled `Desktop only` and opens the existing unavailable guidance.
- The UI token contract uses semantic light/dark canvas, surface, text, border, primary, focus, success, warning, danger, and information colors; 8px spacing increments; 12px control and 16px panel radii; and at least 44px interactive targets. Selected, hover, pressed, disabled, and focus-visible states remain distinguishable without color alone. Layouts preserve safe areas, dynamic text wrapping, 320px minimum width, 200% zoom, reduced motion, and increased contrast without horizontal page overflow or fixed-navigation overlap. The mobile shell measures the rendered fixed bottom navigation and shares its current height with main-content and floating-confirmation offsets, retaining the nominal safe-area-aware height until measurement is available. Measured rail-tooltip coordinates and navigation height use CSP-permitted individual CSSOM property assignments rather than React `style` values or `cssText`.
- `StatePanel` is the shared Loading, Empty, Offline, Blocked, and Error presentation. The existing `ContentState` union remains authoritative, including `status` versus `alert` roles, polite loading announcement, retry eligibility and callback, last-success timestamp, local blocked guidance, and safe correlation identifiers. The shared visual layer does not alter server limits or error classification.
- Deck is scan-first: its primary workspace contains the selected Deck, Create Deck, manual Refresh, last successful refresh, refresh-state cue, known rate-limit reset time, and grouped GitHub-order PR rows. Existing Deck selection remains available while creating a new Deck. Rows retain repository, number, title, author, state/draft, review, checks, labels, and updated time with textual status badges as well as icons; a drafts-hidden state does not claim that GitHub returned no pull requests. Result status badges stack below the row details through mobile, rail, and constrained lower-sidebar layouts, and individual badges wrap their own localized text, so the 320px minimum-width contract does not clip them. The results expose one localized Pull requests landmark. At sidebar and rail widths its unchanged configuration editor is a right panel; rail and constrained lower-sidebar tracks stay bounded and shrinkable so enlarged text cannot overflow the page. Deck headers stack from the available Deck container width rather than a viewport cutoff. At mobile width it is opened only through a named focus-managed sheet that discards unsubmitted values when dismissed. Unsubmitted existing-Deck drafts are also discarded before any selector, creation, or native-link departure; submitted existing-Deck drafts persist across Deck switches until reset or successful adoption. A responsive presentation move retains an in-flight submission state and its outcome, so its form remains unavailable until that save completes and a failed save stays visible after reopening. An open mobile settings sheet closes as it transfers focus to its desktop editor, while moving a focused desktop creation editor to mobile opens and focuses its creation sheet, whose ordinary Back or Escape dismissal restores the persistent Create control. Create remains unavailable until a pending creation settles, including after selecting another Deck; a linked sheet closes only for a new linked-Deck arrival; and completed creates as well as existing Deck saves preserve focus inside an open sheet. Every concrete Chrome origin must be covered by its URL mapping scheme, host, and normalized port before the synchronized setting is accepted or published. Settings validation projects the complete IPC and Chrome response envelopes and rejects an oversized Native Messaging configuration before persistence; native validation retains the same 256 KiB checks as defense in depth. Renderer publications serialize in invocation order so an older replacement cannot finish after newer settings, retry the latest snapshot with capped backoff after transient bridge failures, and abandon stale retries when settings or identity changes; every changed valid replacement clears cached context and rotates the opaque configuration revision required by capture requests, while a rejected renderer replacement also rotates that revision and clears prior native authorization.

Release desktop launches register the packaged Chrome host; development launches never replace the installed canonical registration. The pairing UI refreshes status while a pairing code is active, clears transient status failures after a successful poll, then clears the code and stops polling when its native-returned lifetime expires. IPC uses distinct host and app HMAC proofs, with the app proof bound to the challenge and session ID; a host whose authenticated connection has gone idle reauthenticates and retries the pending request once while preserving that request's pairing nonce.

- Desktop owns the Native Messaging security boundary and registration lifecycle. It stages `devhud-native-messaging-host` as a desktop-only Tauri sidecar and enables that sidecar only through the pinned desktop bundle overlay, registers its exact one-origin Chrome manifest on launch, and starts the authenticated `v1` listener without entering the mobile dependency or artifact closure. The Settings surface publishes only mapping origin/non-secret mapping ID pairs and resolved language, starts a two-minute one-time pairing gesture, exposes paired/unpaired status bilingually, and degrades every extension or listener failure to manual repository selection.
- The listener uses the exact per-user socket/pipe paths and authorization in the extension/host contracts. It authenticates a secure-storage pairing secret with a fresh challenge, one-time pairing nonce, exact compiled extension identity/origin, schema versions, per-request HMAC proof and nonces, five-second deadlines, and replay guards. Unix accept failures retry with capped backoff that resets after a successful accept, while host connection establishment and authentication share one absolute five-second deadline. Pairing completion is serialized with secret rotation and requires the authenticated session generation to remain current. Logout, secure purge, account removal, explicit unpair, or host unregister deletes the pairing secret and invalidates established sessions; unregister uses an authenticated IPC-only control that is not available to Chrome requests and must receive the app's revocation result before reporting success. It accepts only the contracted redacted browser-context shape and never logs payloads.

- `NativeBridgeV1` is a closed tagged request/response contract with one native event stream. It covers runtime/lifecycle, non-destructive pending-auth-callback inspection followed by exact one-shot consumption, validated Deck deep links, bounded non-enumerable secure values and internal API-origin-scoped GitHub PAT associations, local notification consent and Deck-change delivery, store-managed update status/opening, signed desktop updater status/approval operations, structured desktop shortcut status/permission/application, bounded desktop capture/editor/draft operations, and widget status/enable/snapshot/disable operations. Notification consent is refreshed whenever the app returns active; expected native consent-request failures keep the shell usable and expose bilingual inline retry feedback; each Deck-change request keeps its own notification identity, while Deck cancellation removes every associated notification. It returns stable safe error codes and no arbitrary URL, native command, filesystem, networking, or raw-key access. Desktop/browser widget calls return typed `unsupported`; mobile widget calls validate configuration and bounded cache before crossing the native boundary, with configuration and snapshot queries using the same 4,096 UTF-16-code-unit bound as synchronized Settings.
- Mobile registers only `devhud` and accepts only `devhud://auth/callback`, optionally with OAuth query parameters, plus canonical `devhud://deck/<deck-id>` links. Native handlers reject other hosts, paths, ports, credentials, fragments, and malformed inputs without logging callback content. Cold-start delivery is bounded and consumed once; foreground delivery uses the typed bridge event.

Native secure storage is non-enumerable to the frontend but supports scoped and complete internal deletion. A synchronized profile reference with no local secret always enters setup rather than selecting another profile. Authenticated settings caching is best-effort when Web Storage is unavailable, and online or offline startup that finds no authenticated session clears the prior origin's authenticated settings snapshot before another user can reuse it. Auto-save unsubmitted captures as encrypted drafts for 30 days with a default 10 GiB quota; never evict before deadline and reject new saves recoverably when full. Delete drafts after successful issue creation, explicit deletion, or logout. Synchronized settings contain no secrets or device state. UUID v7 is the default for Decks, credential profiles, submissions, drafts, and other new persisted entities.

A changed valid Native Messaging configuration clears cached browser context and invalidates the prior active session generation, including when mappings change within the same identity scope. The renderer also supplies a fresh opaque scope UUID whenever the API-origin or account identity scope changes; changing that UUID clears context and invalidates the prior active session generation even when the derived configuration bytes are identical. A rejected or oversized replacement additionally clears the prior native authorization snapshot and invalidates in-flight sessions. Logout and account deletion invalidate in-memory pairing state and active session generations before secure-storage cleanup is attempted.

Every native GitHub PAT read requires the matching API-origin/profile association. A failed desktop or iOS PAT write restores the prior association state so it cannot introduce an orphan marker that retains or exposes another origin's credential.

## Security

Logout deletes every local Logto/GitHub/R2 credential, cached settings, Deck data, clones, drafts, permission records, and extension pairing item while preserving the selected API origin and completed-onboarding marker. Account deletion blocks access immediately and deletes PAT/R2 credentials plus account-local data except unsubmitted RealQA drafts, which remain encrypted through recovery, while retaining only the current Logto session required for authenticated `RestoreAccount`; clients retry that local cleanup whenever they observe a pending deletion. Pending-deletion Web Storage enumeration and removal are best-effort and cannot prevent the authoritative native PAT/R2 purge, but incomplete cleanup remains retryable. Logout instead requires contracted Web Storage cleanup to complete before native secure-store purge, leaving the secure session and logout action available when the local wipe must be retried; diagnostic event and correlation writers remain suppressed from the initial local wipe through completion of logout and purge-claimed irreversible cleanup transactions. Explicit logout and recovery expiry delete the recovery session. A purge-claimed account never exposes Restore or authenticated product access, but retains its Logto session solely as a restart-safe cleanup marker until contracted Web Storage cleanup succeeds; only then does irreversible native purge complete and the shell transition to signed-out. Invalid Logto credentials clear the session and return the shell to signed-out. Restore reloads synchronized data, clears only deletion state, and preserves an independent administrative block. Deletion allows 30-day recovery, then purges synchronized data and official image bytes. Deletion/quarantine replaces the origin object before purging or revalidating the public CDN URL and is not effective while a cached original remains retrievable. Public-image warnings are localized.

Local agents are an implemented desktop-only, default-disabled boundary. The adapters accept only Codex `0.147.0`, Claude Code `2.1.233`, and OpenCode `1.18.18`, discovered from `PATH` or an explicit absolute executable; Windows discovery follows `PATHEXT`, including standard npm `.cmd` shims. DevHUD reports the path source, exact version, and typed health but never installs or updates an agent. Repository prompts include the configured issue tracker and remain device-local after explicit save; schema v7 strips them from every synchronized body and rehydrates them only from the device cache. Every invocation uses an argv array plus stdin rather than a shell-built command, a cleared allowlisted environment, an immutable prompt envelope that fixes repository, labels, images, diagnostics, repository prompt, and UUID-v7 marker, and a 15-minute timeout with atomically purge-gated registration and process-tree cancellation. Draft mode uses read-only/no-tool-network controls, returns strict `title`/`body` JSON for review, and leaves GitHub creation to DevHUD. Direct mode requires a strong settings warning and a fresh per-submission confirmation, but all three adapters remain read-only and credential-free, return strict marker readiness, and receive no `GH_TOKEN`, `GH_CONFIG_DIR`, issue-input file, writer command, or credential-bearing environment/argument. Only after readiness does DevHUD resolve the selected PAT from secure storage and run one exact argv-based `gh api` write over its private input file. Definite failures before that host writer starts delete finalized official uploads, retaining failed deletions for retry; failures after it starts remain write-ambiguous and preserve uploads. Every successful result also requires marker-search reconciliation. Every failure preserves the encrypted draft and offers the same explicit retry or manual path; it never falls back automatically.

Agent work never uses a user's working copy. DevHUD maintains full-history clones under its private data directory, fetches and refreshes `origin/HEAD` before hard-resetting/cleaning reuse, preserves a valid empty checkout for never-pushed repositories, skips LFS smudging and submodule recursion, creates a second disposable full clone for each run, and caps only the managed clone cache at 50 GiB. Oldest unprotected entries are evicted first; malformed or oversized entries are deleted and recloned, unrecorded directories from interrupted publication are removed during manifest reconciliation, and a disposable-clone failure invalidates and reclones the managed entry once before reporting `clone-failure`. Private HTTPS cloning uses an ephemeral askpass subprocess and an empty private global Git configuration with credential helpers disabled; PATs never enter repository URLs, argv, logs, or Git configuration. HTTPS public image URLs and development-only loopback HTTP image URLs are accepted without credentials, queries, or fragments. Prompts, output, child environments, and full paths are excluded from diagnostics, and the UI warns users never to include secrets in issue or repository-prompt text.

## Logging

Use redacted structured diagnostics. The recursive boundary drops tokens, authorization/PAT/R2/signing values, request/response headers and bodies, private repository data, browser DOM, screenshots, URLs and fragments, form values, issue bodies, local-agent prompts/output, child environments, arbitrary full paths, and shortcut keystrokes. It retains only safe enum classifications, UUID v7 correlations, app/build version, platform/architecture, OS classification, exact pinned Tauri revision on native hosts (empty for browser), exact desktop CEF revision (empty for mobile system webviews and browser), timestamps, bounded durations, and at most 64 path-free stack function names. Local events remain offline under `devhud.diagnostics.v1.*` for at most 7 days, 500 events, 1 MiB, and 128 Connect correlation breadcrumbs; application startup and later reads rewrite or remove expired, invalid, and over-limit persisted collections so retention is physical. Events and correlation breadcrumbs retain those bounds in session memory when Web Storage writes fail, persist when it recovers, and clear from both storage layers during destructive cleanup. Desktop JSONL logs remain capped at seven daily files. Logout, account-deletion cleanup, and contracted local-data deletion remove diagnostics; API-origin changes preserve them, and native cleanup removes only exact app diagnostic JSONL filenames before reopening its active sink.

Crash reporting has no persistent enablement state and is off by default. Guests may preview the exact redacted export and explicitly choose its destination, and only one destination request may remain active at a time; desktop logout and account-deletion purge invalidate any older pending destination result before purge completes, returning cancellation without writing the captured bundle. Imported and persisted local event strings are normalized and recursively redacted only after percent-encoded octets are decoded and rescanned to a bounded fixed point for prohibited locators and sensitive content; input still changing beyond that bound is rejected. Authenticated and unblocked users may submit only after previewing the exact request and granting per-payload consent, and blocked/deletion-pending users cannot submit. Submissions use `DiagnosticsService.SubmitCrashReport` with typed build/platform/component/severity/code fields; build identifiers are at most 256 UTF-8 bytes, error codes are uppercase enum-style classifications of at most 64 bytes, the redacted summary is at most 4 KiB, the redacted stack trace is at most 32 KiB/64 lines/512 bytes per line, related correlations are capped at 32, and duration is capped at 24 hours. Error-code classification is structural and does not apply narrative-content matching to enum names. The server revalidates the complete boundary and retains accepted reports for exactly 30 days. No analytics or remote feature flag participates in diagnostics.

Team secrets remain in service-owned wrappers, while GitHub PATs and BYO R2 credentials remain in DevHud secure storage. ## CI execution boundary

PR validation executes the full frontend test command, native-script fixtures, clean desktop/mobile output verification, static mobile/widget checks, and CEF pins. The aggregate frontend `test` task is non-cacheable because it checks consecutive clean builds and external contracts. The shared repository change plan schedules Windows/Linux desktop and Android packaging on related main changes; full manual dispatch retains all desktop and mobile entries. `CI Result` accepts only explicitly planned skips and event-specific matrices; consult `docs/repository-workflow-contract.md` for comparison ranges and cache ownership.

Shared Tauri CLI installation follows [prebuilt dependencies](repository-prebuilt-dependencies-contract.md). Desktop selection uses the direct `tauri-runtime-cef` dependency and runtime-owned entry point; mobile DevHud uses the direct `tauri-runtime-wry` dependency. macOS/Linux require Chromium sandboxing. Windows permits the owner-approved unsandboxed Chromium exception until executable-host broker support is available upstream. Linux GTK initialization uses GTK4; file dialogs use XDG portal/Tokio and confirmation dialogs use `zenity`. IPC restrictions, private profile ownership and shutdown-before-purge rules are retained.

- CEF Debian packaging installs the main executable in `/usr/share/DevHUD` and the Native Messaging sidecar in `/usr/bin`; startup resolves that exact installed layout without searching PATH. Linux Xvfb CI uses an explicit session-local StatusNotifierWatcher fixture because the new ksni tray backend requires a tray host. This fixture proves application startup and renderer handling; it does not prove desktop-panel icon rendering or interactions.

Linux Debian packages require the XDG portal service, an installed portal implementation, and `zenity` so the new dialog backend is available after installation. AppImage hosts must provide these services and `zenity`; the archive does not supply a system D-Bus portal service.
