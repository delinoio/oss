# apps-devhud-foundation

## Scope

`apps/devhud` contains the implemented deterministic bilingual React/TypeScript frontend and target-isolated Rust/Tauri desktop and mobile hosts for `devhud`. Desktop uses pinned CEF; iOS and Android reuse the same frontend through system webviews. The shell implements the complete guest/Logto identity and schema-versioned Settings boundary against the generated Connect client, explicit Home, mobile RealQA-unavailable, Deck, Settings, Account, Diagnostics, Loading, Empty, Offline, Blocked, and Error compositions, a closed first-party registry, a direct-client GitHub.com issue/pull-request provider foundation, accessible credential setup, and a versioned native bridge. Desktop capture, the bilingual editor, and encrypted draft recovery are implemented; issue submission, other populated product-result surfaces, and native widgets remain planned.

## Runtime and Language

- Desktop: Tauri `tauri-runtime-cef` from `https://github.com/tauri-apps/tauri`, pinned to `4af26a3f7f8b692d62cca549bbacd93f5ce90b41`; CEF renders bundled resources only with restrictive CSP and no arbitrary navigation, popups, or downloads. The default packaged policy denies connections; the host replaces only the `connect-src` response directive with the validated selected API, fixed `https://api.github.com`, and same-origin Logto discovery endpoint for the active session. The fixed development server additionally permits only its `ws://127.0.0.1:46305` HMR endpoint and Rsbuild's injected inline styles. Future signed-upload origins require the same explicit validation before entering a session policy.
- Mobile: Tauri/Wry using WKWebView on iOS and Android System WebView, with no CEF runtime or bundled browser engine. Native widgets are not part of this foundation.
- Targets: macOS 13+, Windows 10 22H2+, Ubuntu 22.04 LTS on X11, iOS 16+ arm64 device and arm64/x64 simulators, Android 10/API 29+ arm64/armv7 production and x64 emulator; Android i686 is excluded.
- Bundle ID: `io.delino.devhud`; deep-link scheme: `devhud`. Fixed frontend port: `46305`.
- English source and Korean/English user-facing UI. Language and System/Light/Dark theme are authoritative synchronized settings for authenticated users and local guest settings otherwise; the shell mirrors the last applied appearance locally only to avoid an incorrect initial render before identity state loads. The resolved language updates localized content and tray labels, while the resolved theme sets the document color scheme so native controls follow the selected appearance. The shell follows Toss Design Guidelines and includes WCAG 2.2 AA-oriented checks for named controls, deterministic focus, reduced motion, high-contrast tokens, and Escape closure for its command palette; formal accessibility qualification remains pending.

## Users and Operators

Guest users, authenticated individual users, maintainers, and platform release operators. RealQA is desktop-only; Deck is desktop/mobile.

## Implemented Desktop Host

- `apps/devhud/src-tauri` is a root Cargo workspace member. It uses authoritative upstream Tauri git dependencies at revision `4af26a3f7f8b692d62cca549bbacd93f5ce90b41`; the sole root patch redirects official crates.io `tauri`, `tauri-plugin`, and `tauri-utils` dependencies to that same revision so the official desktop deep-link plugins share one CEF runtime type graph. Branch dependencies, `feat/cef`, forks, every other Cargo patch, and vendored upstream modifications are forbidden and mechanically checked.
- `apps/devhud/cef-pins.json` records the resolved Tauri package versions (`tauri` 2.11.5, `tauri-build` 2.6.3, `tauri-cli` 2.11.4, and `tauri-runtime-cef` 0.1.0), CEF Rust crates `cef` and `cef-dll-sys` `150.0.0+150.0.10`, `download-cef` 2.3.2, their registry checksums, upstream source revisions, and every platform archive SHA-1. The verifier owns independent immutable copies of the CEF Rust and download-helper versions, checksums, revisions, and the six archive names and hashes. The runtime archive version is CEF `150.0.10+g8042e43+chromium-150.0.7871.101`.
- The runtime's default sandbox feature remains enabled. The executable uses Tauri's CEF entry point so renderer, GPU, plugin, and other helper processes cannot enter browser-process application initialization. Production startup preflights the platform-specific CEF library, ICU/resource packs, locale, sandbox/bootstrap files, and macOS helper applications relative to the installed executable; Linux package resources are resolved from `<prefix>/share/DevHUD` next to `<prefix>/bin`. Missing material produces a structured `cef_fatal_initialization` diagnostic with bounded actionable reason classifications and exit code 78 before the browser starts, without logging resolved host paths.
- Navigation is restricted to bundled `http://tauri.localhost` content in production and exact `http://127.0.0.1:46305` content in development. Popups and downloads are denied. The Rsbuild development launcher binds only `127.0.0.1:46305`, preflights collisions, and never chooses another port. The Tauri command wrapper rejects all `-c` and `--config` overrides, including attached short values, so callers cannot replace the pinned application configuration; it forwards `SIGINT` and `SIGTERM`, mirrors signal-based exits, and on every supported desktop platform terminates and awaits the complete Cargo, Tauri CLI, desktop-host, and Rsbuild process tree. Timed-out platform smokes use the same complete-tree termination on every supported desktop platform before temporary cache and log cleanup.
- Structured diagnostics cover platform/display selection, resource discovery, frontend readiness, renderer termination, fatal initialization, smoke shutdown, clean host shutdown, external-opener failures, tray hide/restore failures, tray-language update failures, and capture failures identified only by action, adapter platform, and stable error code. After React mounts, it changes the document title to `DevHUD` and invokes the native `frontend_ready` command; the host atomically accepts that CEF-supported readiness signal before dispatching smoke behavior. An independent five-second wall-clock watchdog emits `frontend_readiness_timeout` and terminates with exit code 1 if readiness does not complete. macOS uses the typed CEF renderer-termination callback; every packaged Windows and Linux launch enables the CEF Inspector domain and registers the DevTools protocol crash listener, while the deliberate `Page.crash` request and its watchdog remain exclusive to the renderer-crash smoke. Desktop release hosts retain timestamped, redacted JSON diagnostics in UTC-daily `devhud.YYYY-MM-DD.jsonl` files under `%LOCALAPPDATA%\io.delino.devhud\logs` on Windows, `~/Library/Logs/io.delino.devhud` on macOS, and `${XDG_STATE_HOME:-~/.local/state}/io.delino.devhud/logs` on Linux, keeping at most seven daily files while preserving stderr output for managed launches and smoke capture; destructive diagnostic cleanup closes the active file sink, removes only exact app JSONL names, and reopens the sink before later events. Operator `RUST_LOG` filters may tune dependency verbosity, but cannot suppress error-level DevHUD diagnostics. Debug builds and CEF subprocesses remain stderr-only; a file-sink setup failure falls back to stderr without logging the resolved path while retaining that directory for later destructive cleanup.

## Interfaces and Contracts

- `NativeBridgeV1` is a closed tagged request/response contract with one native event stream. It covers runtime/lifecycle, non-destructive pending-auth-callback inspection followed by exact one-shot consumption, bounded non-enumerable secure values and internal API-origin-scoped GitHub PAT associations, local notification consent and Deck-change delivery, store-managed update status/opening, structured desktop shortcut status/permission/application, bounded desktop capture/editor/draft operations, and future widget snapshot replacement/clearing. A consumed callback is removed from renderer state before callback processing continues so later identity resets cannot reuse it. Notification consent is refreshed whenever the app returns active; expected native consent-request failures keep the shell usable and expose bilingual inline retry feedback; each Deck-change request keeps its own notification identity, while Deck cancellation removes every associated notification. It returns stable safe error codes and no arbitrary URL, native command, filesystem, networking, or raw-key access. Widget calls return `unsupported` until widget targets and their shared entitlements are implemented.
- Mobile registers only `devhud` and accepts only `devhud://auth/callback`, optionally with OAuth query parameters. Native handlers reject other hosts, paths, ports, credentials, fragments, and malformed inputs without logging callback content. Cold-start delivery is bounded and consumed once; foreground delivery uses the typed bridge event.
- Desktop updates are implemented through the closed native updater described in `apps-devhud-updater-contract.md`. They use no bootstrap override or token, do not block startup, keep updater networking outside frontend navigation/CSP, preserve the installed version on every failure, and require three explicit approvals. Mobile retains only store-managed update operations.
- iOS secrets use non-synchronizing shared-access-group Keychain items; upgrades retain temporary access to the legacy application group so reads migrate values and every write, removal, logout, API change, or account deletion removes legacy copies. Android uses Keystore-backed encrypted app-private values excluded from backup; a legacy no-AAD value is accepted only after successful GCM authentication and is immediately rewritten with setting-key AAD. Neither platform offers enumeration. Mobile updates are delegated to App Store/Google Play; the bridge cannot download or install an update.
- Android release manifests grant only System WebView networking and local notification permissions. Native authentication accepts configured issuer paths and loopback HTTP development issuers after the same origin validation used by the shared frontend.

- First-party mini-app IDs: `realqa`, `deck`. Action IDs include the five `realqa.capture.*` identifiers defined in the project index. The registry is closed and enum-backed, includes navigation/settings actions, filters actions by platform capability before rendering navigation or the command palette, and cannot load third-party mini-apps.
- Desktop shortcuts use the six closed enum actions: command palette and the five contracted `realqa.capture.*` actions. Settings persist only `{ enabled, modifiers, key }` enum values. `right-primary` resolves to physical right Command on macOS and physical right Control on Windows/X11; left Control and left Meta/Command remain independent native pressed states. Defaults are right-primary+`K` and bare `1`–`5`. Candidate bindings reject unknown fields and are rejected before persistence for malformed values, duplicate chords, reserved OS chords (including Windows Alt+Tab), registration failures, and permission denial; a candidate is staged before persistence and activates only after the snapshot succeeds, while a failed persistence or rollback leaves the last valid binding active. An additional unconfigured right Control on macOS or right Meta on Windows/X11 invalidates a chord without being persisted, bridged, or diagnosed. The always-mounted desktop boundary waits for authenticated settings to resolve from a valid snapshot or cache before native hydration, suspends matching after explicit or automatic session cleanup and suspends previously active guest matching during authenticated hydration gaps, and prevents guest or native defaults from overriding persisted settings; it loads the authenticated cache before blocked-user hydration. A failed native apply makes the command-palette trigger unavailable, while a platform-reserved synchronized binding reapplies the native backend's last platform-valid map without rewriting shared settings and displays that active map. Recoverable listener failures use capped backoff, clear transient pressed modifiers before the replacement listener accepts events, and retain staged current bindings across recovery. Command-palette, selection, and toolbar shortcuts restore and focus the main window before their events are emitted; display, active-window, and all-display shortcuts remain UI-independent. Capture shortcuts dispatch the closed RealQA action IDs on supported desktop runtimes and remain visibly unavailable on mobile and browser-only development runtimes. The event matcher retains no raw events and emits only a configured closed action; diagnostics contain only redacted failure categories.
- The command palette opens only for its active localized visible binding after first-run onboarding, contains its keyboard focus while open, and offers only capability-available actions. Repeated shortcut events leave it open. It restores focus to its trigger on Escape and normal completion, except that Account completion preserves focus for the API-origin input. The resolved local language and theme are applied to the document before the initial localized React content renders; while the language preference is System, operating-system language changes synchronize rendered copy, document language, and tray labels. Capture and service actions remain visibly unavailable on runtimes that do not advertise their corresponding capabilities.
- macOS shortcut setup presents localized Accessibility and Input Monitoring guidance. Linux shortcut setup presents localized X11/XWayland, `DISPLAY`, and X authority guidance; native Wayland is unsupported. Windows requires no additional privacy permission for this contracted backend.
- Local shell links and Logto authorization use the system browser only through native closed validation: native session policy retains the complete normalized configured issuer, the authorization request must name that exact issuer, and its destination must remain on the same origin at the issuer path or a descendant path. CSP still derives only the validated issuer origin, while other openers remain limited to the contracted fine-grained PAT form, classic PAT form, and project issue destination. Fine-grained creation preselects Metadata read, Pull requests read, Issues write, and Contents read without setting `target_name`, so owner/repository selection remains visible; classic creation preselects only `repo`. The shell recommends repository-scoped fine-grained credentials. The shell confirms desktop dispatch in a background worker with a five-second timeout before reporting a link as opened; Linux uses GIO dispatch rather than waiting on the launched browser's lifetime. Unsuccessful, timed-out, or unobservable dispatches return an error and record a structured diagnostic. Documentation remains unavailable until a curated public DevHud destination exists. Arbitrary browser navigation is rejected.
- First run exposes editable `https://devhud.api.delino.io`, Sign in, and Continue locally; the post-onboarding Account Bootstrap-error recovery exposes Retry and Continue locally as well. Non-loopback endpoints require HTTPS; loopback HTTP, including the bracketed IPv6 literal `[::1]`, is allowed; no TLS bypass. Equivalent bare and trailing-slash API roots normalize to one origin and do not clear or remount identity state, while API origins reject credentials, non-root paths, queries, fragments (including empty delimiters), and whitespace before native validation or session-CSP use; signed-upload origins are validated from the server response. Each Account opener action supersedes prior pending opener status, and API-origin edits or continuing locally invalidate pending actions so delayed completions cannot reset the selected surface. Continue locally also keeps guest settings writable when an already-started Bootstrap attempt later fails; an explicit identity retry or Sign in opts back into identity handling. If Web Storage is unavailable, a complete in-memory Web Storage implementation keeps onboarding and local cleanup usable for the current session without persistence.
- First run and every custom-origin edit explain in English and Korean that the selected API controls authentication discovery and synchronized non-secret settings. An origin change requires confirmation, discards any queued native authentication callback before deleting the prior origin's Logto transaction/session and authenticated cache, preserves unrelated GitHub/R2 profiles, and restarts bootstrap and import selection.
- The Diagnostics surface previews the exact immutable `SubmitCrashReport` payload and explicitly exports a bounded redacted JSON bundle through a user-selected native/browser destination. Native snapshots report the installed operating-system version rather than the compile-time target label. Browser execution uses its own platform classification, reports architecture from User-Agent Client Hints when available and otherwise leaves it unknown, and uses empty Tauri/CEF revisions rather than claiming a desktop runtime. It reports confirmed save, cancellation, initiated-but-unconfirmed browser download, and failure without exposing a destination path; desktop writes are atomic, browser failures abort pending writes, and mobile temporary/partial files are cleaned on failure, startup, logout, and account deletion, but not an API-origin change. iOS temporary-copy and Android destination cleanup failures return the stable storage failure, remain pending, and are retried on startup, before another export, or during the next destructive purge instead of reporting a saved or cancelled export while retaining diagnostic data. Android retains only its app-private backup-excluded destination URI and persistable write grant until deletion is confirmed, and excludes the complete System WebView data directory containing local diagnostic events from cloud backup and device transfer. Guests retain preview/export but have no submit control. The initial surface does not claim that retained events are absent before Preview inspects storage. Authenticated users receive one submission control only after checking consent for that exact SHA-256-bound preview; successful submission clears that consent, and a completion from a superseded preview cannot update the current submission state or correlation. Blocked/deletion-pending users are denied, offline users retain local preview/export with submission disabled, and typed submission failures render safe classifications plus correlation IDs without raw server text. Expected native notification-consent and app-store-opening failures remain inline, bilingual, recoverable, and do not replace the shell with a global error state.
- Logto uses system-browser Authorization Code with PKCE and the exact native callback URI `devhud://auth/callback`; one provider-owned in-flight guard prevents overlapping PKCE transactions from either Sign in surface. The official desktop deep-link runtime registers the scheme, forwards Windows/Linux secondary launches into the primary instance, and delivers cold-start and foreground callbacks through the same validated pending-callback boundary. Callbacks received before bootstrap remain queued through issuer-policy reloads and are consumed when the session becomes ready. Bootstrap must identify `PROJECT_ID_DEVHUD` before discovery fields are consumed; protocol schema version controls compatibility, while API version is opaque deployment metadata. The issuer may contain a path and may use HTTP only on loopback in development, the audience is a nonblank configured resource value, and public client IDs remain keyed as `desktop`, `ios`, `android`, and `admin`. Browser/API requests use the documented exact development and pinned Tauri CORS origins and Connect preflight policy. Packaged session CSP permits styles only from `'self'`; the inline-style exception is development-only. A secure-session read failure retains non-destructive retry for transient platform errors and exposes an explicit device-local session reset for malformed or permanently unreadable values. Missing authentication and terminal `invalid_grant` refresh failures clear the invalid session, while network and temporary refresh failures preserve it for retry.
- Local guest settings and authenticated synchronized settings use whole-snapshot import choice, matching envelope/canonical-body schema versions, monotonic revision, expected-revision writes, typed conflict, and explicit reapply. Snapshot-choice dialogs close on Escape or Close without clearing the pending choice and expose a control to reopen it. Offline authenticated settings are read-only.
- Synchronized settings cross the wire as at most 1 MiB of RFC 8785 canonical UTF-8 JSON bytes. The client validates every fetched and replacement snapshot envelope schema and canonical bytes before updating or caching state; invalid snapshots and query failures preserve the last valid state as read-only and surface a recoverable typed synchronization error with correlation metadata. Revision zero means no stored snapshot; a create expects zero and returns one, and each successful replacement increments once. The app must surface `SettingsRevisionConflict` for an explicit reload/reapply decision and must not silently overwrite or retry.
- Settings schema version 3 contains only appearance language/theme; Deck definitions and query/builder/display/refresh/notification state; GitHub.com repository and issue-tracker configuration; stable UUID-v7 GitHub profile descriptors (`id`, display `name`, and fine-grained/classic `kind`), explicit nullable profile references, and bounded unique pending PAT-removal tombstones; URL mappings; per-platform shortcuts; local-agent enablement/kind/mode/repository prompts and non-secret profile references; and upload-provider selection plus non-secret BYO R2 metadata. Schema version 1 snapshots migrate deterministically with no profiles, no tombstones, and every GitHub profile reference unselected; schema version 2 carries the same profile fields with prefix URL mappings. URL-mapping prefixes and R2 endpoint/public-base URLs reject credentials, queries, and fragments, including empty delimiters, and shortcut actions reject prototype-sensitive names. Unknown fields, duplicate or active-profile tombstones, duplicate GitHub profile IDs, and every secret or device-local field are rejected before local persistence or synchronization.
- URL mappings are structured schema-v3 settings capped at 100 entries: each uses a UUID v7, credential-profile reference, owner/name repository, integer priority, optional concrete HTTP(S) Chrome origin with a numeric port no greater than 65535 when present, timestamp, and scheme/host/port/path glob. Schema-v1 and schema-v2 prefix mappings are validated then discarded during migration because they cannot safely select a repository/profile; structured mappings are accepted only in schema v3, which older clients treat as unsupported/read-only. A canonical mapping path has at most 32 segments and 8 globstars, bounding synchronous overlap analysis. New mapping drafts begin visibly unselected and require explicit configured-profile selection; newly assigned or changed repository/profile pairs resolve that profile's device-local PAT and validate GitHub access before saving. Matching ignores query/fragment, rejects authority backslashes and every host the browser URL parser rejects, canonicalizes literal paths and internationalized concrete DNS hosts (including terminal DNS root labels) while preserving trailing/repeated empty path segments and distinct serialized escapes, handles bracketed IPv6 literals, treats HTTP(S) default ports as portless, and deterministically selects priority, literal specificity, then newest update. Dirty mapping drafts retain their base revision through refreshes and submit against it, surfacing the standard revision conflict instead of silently rebasing remote mapping changes; drafts and intermediate priority text otherwise survive in-app surface navigation and null-to-current-account hydration for the current app session, reset after server adoption, a successfully applied snapshot, an invalid session, logout, or a confirmed account change, and surface overlap warnings; browser permissions and pairing remain device-local.
- Internal provider registry version 1 contains only `github.com` for issue tracking and pull requests. Its injected-fetch adapter fixes requests to `https://api.github.com` with API version `2026-03-10` and defines typed repository validation, paged label lookup, idempotency-marker search, issue creation/reconciliation, pull-request search/detail enrichment, ETag/rate metadata, and exact canonical GitHub issue/pull URL ownership. Issue creation uses `<!-- devhud-submission:<uuid-v7> -->`, checks both indexed search and the repository's recent issue list before POST, and reconciles an ambiguous network result from the non-search issue list or returns a typed ambiguous-write result without issuing a second POST.
- Each referenced repository names exactly one profile or remains visibly unselected; the client never falls back to another profile. Selection and explicit validation resolve only that profile's PAT from platform secure storage and validate Metadata, Pull requests, Issues, and Contents access for every referenced repository. A root Contents `404` is accepted only when repository metadata reports `pushed_at: null`, proving a never-pushed empty repository; the same response for a previously pushed repository retains the typed permission/restriction failure. Fine-grained validation proves Issues write access with a non-creating invalid issue request that must reach GitHub's validation response before reporting the permission as present. Missing local PATs remain distinct from typed recoverable secure-storage failures. Safe failures distinguish invalid PAT, missing permissions/classic `repo` scope, fine-grained repository restriction, organization policy/SSO denial, rate limiting, and network failure. Provider errors and diagnostics retain only enum operation/code, numeric status, ETag/rate metadata where applicable, and omit credentials, authorization/request/response headers, URL queries/fragments, bodies, repository-private response content, and underlying exception text.
- The first authenticated session after guest use always shows a complete recursively redacted local/server snapshot diff. Upload-local uses the server's current revision, including zero; replace-local adopts the server snapshot or schema defaults when none exists. A stale write displays the latest server/local diff and requires either adopting the server or explicitly reapplying the unchanged local snapshot against the returned revision.
- RealQA supports display/window/all-display/region/toolbar capture, editing, encrypted drafts, URL mappings, optional sanitized Chrome context, GitHub issue creation, official/BYO R2, and explicit Codex/Claude Code/OpenCode draft/direct modes. The first `CreateUpload` creates a server-owned UUID v7 submission and upload group for one issue workflow; later groups and finalizations must carry that submission, with at most 10 finalized images across it. Upload checksums are 32 raw bytes and are encoded as standard Base64 only for the R2 checksum header. The server reserves the signed-URL issuance quota before returning each URL and finalization does not charge that reservation again. It excludes mobile capture, screen recording, full-page/console/network/cookie/storage capture, comments, assignees, milestones, projects, and updating existing issues.
- The implemented capture slice is desktop-only and dependency-injected: `MacOsCaptureAdapter`, `WindowsCaptureAdapter`, and `X11CaptureAdapter` expose signed logical bounds, backing-pixel sizes, per-display scales, pointer position, front-to-back windows, and still-image capture. Pointer-display selection, negative origins, mixed-scale region stitching, one-result-per-display ordering, active/window capture, hotplug retry, protected-content errors, cancellable timers, cursor compositing, floating previews, toolbar mode, Space region/window switching, Escape, and supported macOS shadow removal share one closed bridge. Selection and toolbar dialogs refresh topology before opening, remain inside the viewport with internal scrolling, hide any pointer-interactive floating preview, restore focus to their opener after dismissal, and validate finite coordinates plus positive dimensions with localized inline guidance. The command palette also suppresses the floating preview while it is modal. The capture controller remains mounted across desktop surface navigation so in-flight completion and the five-second floating confirmation survive, and the confirmation action returns to RealQA. Pointer lookup is required only for pointer-dependent targeting or compositing, and shadow trimming adjusts captured logical bounds before cursor placement. Region coordinates are clipped to the current virtual desktop, use checked fallible allocation, and share rounded output edges across every composed piece; topology comparison includes complete logical bounds and each source frame is validated before composition. Window enumeration skips targets that disappear during metadata reads. A cancellable delay completes before a focused DevHUD window is hidden for every capture mode; region/toolbar window selection then waits a cancellable two seconds before resolving the pointer target. Restoration failures never turn an already persisted capture into a failed result. Repeated capture shortcuts are ignored while one request is active, and delayed completions do not replace later editor navigation. Space retains its standard activation behavior on focused dialog controls. The macOS system capture purpose string is packaged in English and Korean. No recording API is called.
- The region picker expresses dynamic virtual-desktop geometry through SVG attributes and static classes so the production `style-src 'self'` policy does not collapse it. Fully opaque black window frames from the macOS and Windows adapters are treated as protected content before persistence; opaque-black display and X11 captures remain valid.
- Direct display/window/all-display shortcuts keep a hidden or minimized DevHud window out of acquisition and restore it only after the attempt so confirmation and recoverable errors are visible. Cancellation is checked after staging encrypted create/append data and immediately before the atomic commit point; a cancelled stage is removed. Successful explicit deletion is not relabeled as failed when list reconciliation fails, and a capture shortcut dismisses the command palette before RealQA can open another modal.
- The React 19 editor composes provider-injected state with accessible English/Korean controls for crop, arrow, rectangle, drawing, text, blur, opaque redaction, undo/redo, and image/layer move/remove. Its SVG preview uses the same arrowhead geometry, Gaussian blur radius, and bundled Noto Sans KR face as native flattening, and every blur samples the accumulated preceding layer state. Revision-checked editor, flatten, open-draft append, and readable-draft deletion operations share one per-draft queue against the latest returned revision; persisted editor actions are unavailable during an active append, completed in-flight revisions reconcile into the draft list without reopening a dismissed editor, authoritative deletion cannot be reversed by a late response, and floating previews retain the first newly captured image while resolving the current listed draft revision. Removing the selected image explicitly selects the first remaining image, and removal is disabled when it would remove the final active image. Text input is capped at the native 2,048-Unicode-scalar limit before submission. Pointer-derived bounded annotation geometry clamps to the final in-raster pixel with defensive raster clipping, and native line rasterization preserves requested even and odd widths, while the bundled unmodified OFL-licensed font makes English and Korean previewed and flattened text independent of optional system fonts and is emitted only in desktop frontend builds, including exclusion from the direct x64 iOS simulator frontend prerequisite. Persisted undo/redo retains at most 100 combined snapshots and prunes the farthest snapshots further under quota pressure so shrinking edits remain recoverable. Every flatten runs off the asynchronous runtime worker, rasterizes edits, and emits metadata-minimized RGBA8 sRGB PNG. A draft may contain at most 10 active images; output larger than 4096 pixels per side or 50 MiB is proportionally downscaled until compatible and the editor announces that change.
- Manual annotation coordinates are validated against the active image with localized inline guidance before Add can submit. Text preview font metrics come from a static CSP-compatible class, blur inputs are clipped before filtering so outside pixels cannot bleed across native crop boundaries, and Strict Mode effect replay restores the editor activity guard during setup.
- Draft sources, manifests, history, and flattened outputs remain device-local AES-256-GCM ciphertext with random per-payload nonces and draft/role AAD; each flattened entry additionally authenticates its draft revision. The 32-byte master key is created and retained only by macOS Keychain, Windows Credential Manager, or Linux Secret Service, survives recoverable account deletion with its drafts, and is included in the authoritative logout purge. Atomic replace plus startup transaction cleanup provide crash recovery only after the desktop process has claimed primary-instance ownership. All images flattened for one revision are staged and committed through one revision-specific bundle replacement, so a failed flatten preserves the complete previous set. Retention is 30 days from the last successful saved revision; the default quota is 10 GiB of encrypted bytes, no unexpired draft is evicted, and a full quota rejects the attempted save without removing existing drafts. Removed source ciphertext remains while an undo or redo state can restore it and is reclaimed before later quota-growing writes once that history expires; a manifest revision commits before its prior flattened bundle is removed, so a failed mutation preserves the current revision's output and successful revisions make stale bundles unreachable before cleanup. Unreadable manifests remain retained but are surfaced by UUID as delete-only entries so users can explicitly reclaim their quota. Draft listing remains available when capture status is temporarily unavailable; list cards lazy-load their full-resolution previews, and opening a listed draft revalidates it natively before mounting the editor. Logout and account deletion invalidate and join in-flight captures while holding the secure credential purge boundary, but only logout also purges drafts and their key; failed draft deletion stops credential purge, while successful logout clears the mounted draft controller before returning to Account. Escape, renderer exit, and app exit preserve saved drafts. Only expiry, explicit deletion, confirmed issue creation, or logout delete them. Diagnostics carry IDs, dimensions, counts, and typed codes only; the flattened-output bridge may additionally return its SHA-256 checksum. Neither surface carries pixels, cryptographic material, annotation text, or issue bodies.
- Editor mutations run recovery before their quota-checked manifest write, so image payloads are reclaimed as soon as no current, undo, or redo state references them rather than waiting for another list, append, flatten, or process restart.
- Deck calls GitHub directly, preserves queries containing a standalone positive `is:pr` token and appends that qualifier when only substrings or negative qualifiers are present, caches at most 100 results/Deck, permits 25 Decks/user, and offers 1/5/15/30-minute refresh intervals while a desktop or mobile client is active and able to poll. Only configured chords are processed, each shortcut key emits once until released, and every binding is editable/disableable with conflicts diagnosed. The browser-only frontend development runtime has no global-hook bridge, so it displays desktop shortcuts as unavailable.
- Server state uses the service-specific Connect Query exports from `@delinoio/devhud-api-client`. The implemented API exposes Bootstrap, Settings, Upload, Account, Admin, and Diagnostics. Every successful message and typed error preserves response correlation metadata, including failed Settings writes and diagnostics submissions rendered with their safe correlation IDs; the app renders the typed crash-report quota classification and server-provided retained-report limit separately from transient submission failures. First-run and post-onboarding Bootstrap failures remain bilingual and explicitly retryable. Pagination uses the default 50/maximum 100 and 2 KiB opaque-token bounds, and upload creation explicitly selects new submission, new group, or existing group before retaining the returned immutable reservation and staging-generation bindings through finalization.

## Storage

Persist tokens, PATs, and R2 keys only in platform secure storage. GitHub PAT profile values never enter synchronized JSON, Web Storage, Connect requests, or `devhud-api`; only stable non-secret profile descriptors, references, and pending-removal tombstones synchronize. Profile removal commits the descriptor deletion and tombstone together, retries native PAT deletion while the tombstone remains, and clears it only after secure deletion succeeds. The always-mounted identity/settings boundary reconciles internal API-origin-scoped GitHub PAT associations through the closed native bridge whenever a valid settings snapshot is observed, regardless of the active product surface, deleting an orphaned PAT only after its last origin scope releases it and without exposing credential enumeration to the frontend. Origin-scoped associations preserve unrelated credentials across API-origin changes. Silent tombstone cleanup and user settings edits apply as functional updates to the latest local snapshot, and a failed rollback after a PAT write remains explicitly retryable. A newly written PAT remains available while its proposed profile snapshot awaits revision-conflict resolution; reapplying retains it and adopting the server causes reconciliation to remove it. Keep API origins, agent paths/versions, autostart, drafts, clone caches, Deck result caches, window/widget state, Native Messaging pairing, permission records, and browser permissions device-local, encrypting sensitive drafts and cached content as their contracts require. Desktop secure storage fails closed through macOS Keychain, Windows Credential Manager, or the Linux Secret Service and never falls back to plaintext. Windows stores logical secure values and their internal enumeration index through alternating versioned credential-chunk generations whose physical UTF-8 byte chunks are at most 1,024 bytes, reads legacy single-entry values and version-one string chunks, restores the prior logical credential if index maintenance fails, and removes active or stale chunks at every scoped deletion boundary. iOS uses non-synchronizing Keychain items in `$(AppIdentifierPrefix)io.delino.devhud.shared` plus App Group `group.io.delino.devhud`; Android uses Keystore-backed authenticated encryption excluded from backup and device transfer. Native secure storage is non-enumerable to the frontend but supports scoped and complete internal deletion. A synchronized profile reference with no local secret always enters setup rather than selecting another profile. Authenticated settings caching is best-effort when Web Storage is unavailable, and online or offline startup that finds no authenticated session clears the prior origin's authenticated settings snapshot before another user can reuse it. Auto-save unsubmitted captures as encrypted drafts for 30 days with a default 10 GiB quota; never evict before deadline and reject new saves recoverably when full. Delete drafts after successful issue creation, explicit deletion, or logout. Synchronized settings contain no secrets or device state. UUID v7 is the default for Decks, credential profiles, submissions, drafts, and other new persisted entities.

Every native GitHub PAT read requires the matching API-origin/profile association. A failed desktop or iOS PAT write restores the prior association state so it cannot introduce an orphan marker that retains or exposes another origin's credential.

## Security

Logout deletes every local Logto/GitHub/R2 credential, cached settings, Deck data, clones, drafts, permission records, and extension pairing item while preserving the selected API origin and completed-onboarding marker. Account deletion blocks access immediately and deletes PAT/R2 credentials plus account-local data except unsubmitted RealQA drafts, which remain encrypted through recovery, while retaining only the current Logto session required for authenticated `RestoreAccount`; clients retry that local cleanup whenever they observe a pending deletion. Pending-deletion Web Storage enumeration and removal are best-effort and cannot prevent the authoritative native PAT/R2 purge, but incomplete cleanup remains retryable. Logout instead requires contracted Web Storage cleanup to complete before native secure-store purge, leaving the secure session and logout action available when the local wipe must be retried; diagnostic event and correlation writers remain suppressed from the initial local wipe through completion of logout and purge-claimed irreversible cleanup transactions. Explicit logout and recovery expiry delete the recovery session. A purge-claimed account never exposes Restore or authenticated product access, but retains its Logto session solely as a restart-safe cleanup marker until contracted Web Storage cleanup succeeds; only then does irreversible native purge complete and the shell transition to signed-out. Invalid Logto credentials clear the session and return the shell to signed-out. Restore reloads synchronized data, clears only deletion state, and preserves an independent administrative block. Deletion allows 30-day recovery, then purges synchronized data and official image bytes. Deletion/quarantine replaces the origin object before purging or revalidating the public CDN URL and is not effective while a cached original remains retrievable. Public-image warnings are localized. Local-agent direct mode requires per-submission consent, isolated managed clones, ephemeral `GH_TOKEN`, a 15-minute limit, schema validation, and no automatic fallback.

## Logging

Use redacted structured diagnostics. The recursive boundary drops tokens, authorization/PAT/R2/signing values, request/response headers and bodies, private repository data, browser DOM, screenshots, URLs and fragments, form values, issue bodies, local-agent prompts/output, child environments, arbitrary full paths, and shortcut keystrokes. It retains only safe enum classifications, UUID v7 correlations, app/build version, platform/architecture, OS classification, exact pinned Tauri revision on native hosts (empty for browser), exact desktop CEF revision (empty for mobile system webviews and browser), timestamps, bounded durations, and at most 64 path-free stack function names. Local events remain offline under `devhud.diagnostics.v1.*` for at most 7 days, 500 events, 1 MiB, and 128 Connect correlation breadcrumbs; application startup and later reads rewrite or remove expired, invalid, and over-limit persisted collections so retention is physical. Events and correlation breadcrumbs retain those bounds in session memory when Web Storage writes fail, persist when it recovers, and clear from both storage layers during destructive cleanup. Desktop JSONL logs remain capped at seven daily files. Logout, account-deletion cleanup, and contracted local-data deletion remove diagnostics; API-origin changes preserve them, and native cleanup removes only exact app diagnostic JSONL filenames before reopening its active sink.

Crash reporting has no persistent enablement state and is off by default. Guests may preview the exact redacted export and explicitly choose its destination, and only one destination request may remain active at a time; desktop logout and account-deletion purge invalidate any older pending destination result before purge completes, returning cancellation without writing the captured bundle. Imported and persisted local event strings are normalized and recursively redacted only after percent-encoded octets are decoded and rescanned to a bounded fixed point for prohibited locators and sensitive content; input still changing beyond that bound is rejected. Authenticated and unblocked users may submit only after previewing the exact request and granting per-payload consent, and blocked/deletion-pending users cannot submit. Submissions use `DiagnosticsService.SubmitCrashReport` with typed build/platform/component/severity/code fields; build identifiers are at most 256 UTF-8 bytes, error codes are uppercase enum-style classifications of at most 64 bytes, the redacted summary is at most 4 KiB, the redacted stack trace is at most 32 KiB/64 lines/512 bytes per line, related correlations are capped at 32, and duration is capped at 24 hours. Error-code classification is structural and does not apply narrative-content matching to enum names. The server revalidates the complete boundary and retains accepted reports for exactly 30 days. No analytics or remote feature flag participates in diagnostics.

## Build and Test

Package-local commands are:

The package-level Turbo configuration disables caching for DevHud's native `build` task because its executable and installer outputs live under the root Cargo `target/` directory and must be regenerated rather than restored as frontend-only output.

- `pnpm --filter devhud dev` — launch the pinned Tauri CLI and strict-port frontend.
- `pnpm --filter devhud build` — produce a production desktop build with bundled frontend and CEF material.
- `pnpm --filter devhud test` — type-check, reject Tauri CLI configuration overrides, validate English/Korean locale selection and light/dark eyebrow contrast, and compare two clean frontend builds by path, mode, and SHA-256 while rejecting remote HTML, JavaScript, and CSS loads, including protocol-relative references and WebSocket, EventSource, XMLHttpRequest, Worker, SharedWorker, and Beacon connections.
- GitHub adapter and setup tests use committed deterministic fixtures for public/private and never-pushed empty repositories, fine-grained/classic PATs, issue-write probing, repository restrictions, organization denial, missing scopes/tokens, secure-storage failure, conflict-safe profile removal, read-only PAT controls, replacement retention, API-origin-scoped reconciliation, concurrent guest cleanup/settings writes, failed rollback retry, platform-aware PAT links, pagination, labels, ETags/rate limits, search-index-lag marker reconciliation, and pull-request enrichment. Isolation assertions prove synchronized JSON contains only profile IDs/descriptors, every adapter request targets `api.github.com`, and no server transport observes a PAT or GitHub operation.
- `pnpm --filter devhud verify:pins` — verify exact git revisions, registry checksums, archive hashes, frontend versions, production CSP directives, all-target Cargo features, exact CI target/runner pairs, and the source of every resolved dependency reachable from DevHUD so branch, fork, and patch dependencies cannot enter the protected graph.
- `pnpm --filter devhud smoke:platform` — validate helper/resource discovery, sandboxed browser startup, three independent startup/shutdown cycles, renderer-failure diagnostics, fatal missing-resource diagnostics, and every expected marker in an isolated persisted JSONL sink against a production artifact. Linux requires `--artifact` to reference an installed or root-prepared package layout whose CEF SUID sandbox is owned by `root:root` with mode `4755`; macOS and Windows retain their default production-artifact paths.
- `pnpm --filter devhud mobile:generate` / `mobile:check` — materialize ignored Apple/Android project output from pinned Tauri plus committed platform definitions, or byte-verify the deterministic overlays without requiring both vendor toolchains.
- `pnpm --filter devhud build:ios`, `build:ios:sim:arm64`, `build:ios:sim:x64`, `build:android`, `build:android:arm64`, `build:android:armv7`, and `build:android:emulator:x64` — build only the contracted fixed device/simulator/emulator architecture sets. The x64 iOS command builds its frontend with `TAURI_ENV_PLATFORM=ios`, keeps a pinned-Tauri project-open process alive for the generated Xcode phase's CLI-owned options, and has Xcode build the generated workspace explicitly against the x64 simulator SDK instead of Tauri's device-oriented archive path. Android builds copy each requested APK/AAB to `target/devhud-mobile/android/<tauri-target>/`, preserving both production architectures across the aggregate command.
- `pnpm --filter devhud verify:mobile` — assert the complete immutable target tuples and resolved production-default normal-dependency closure hashes, minimum versions, identity, deep-link registration, permissions, Android secure-setting backup exclusions, shared-frontend parity, system-webview use, and the absence of CEF, desktop-hook, extension, updater-downloader, push, and unintended networking material.

`.github/workflows/CI.yml` provides native x64 and arm64 build/smoke definitions for macOS, Windows, and Ubuntu 22.04 X11. Mobile contract, iOS, and Android jobs use the same workflow-dispatch-or-relevant-DevHUD-path gate as desktop validation; Android production rows build and inspect both APK and Google Play AAB output, while the x64 emulator row remains APK-only. Ubuntu jobs validate that the Debian archive records `chrome-sandbox` as `root:root` with mode `4755` before repairing ownership solely in the non-root smoke extraction. Credential-free macOS development and CI bundles use Tauri's ad hoc signing identity with hardened runtime disabled so CEF helpers can execute; release signing remains a separate release gate that must override that identity and supply the production hardened-runtime entitlements. Root Rust validation remains `cargo fmt --all --check`, `cargo clippy --workspace --all-targets --all-features -- -D warnings`, and `cargo test --workspace --all-targets`.

Current proven limitations are deliberate: GitHub issue submission, populated issue/Deck result surfaces, widget targets, and Deck deep links are not implemented. The desktop updater and platform package handoff are implemented, but production update publication remains blocked until the production release public key replaces the explicit placeholder and platform signing/qualification succeeds. Identity, Settings, GitHub.com provider/setup, dynamic session CSP, exact auth callback transport, secure credential adapters, capture, and shortcut registration/matching are implemented boundaries; packaged platform-hook qualification, minimum-version device qualification, and signed store release remain release gates.
