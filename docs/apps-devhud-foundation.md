# apps-devhud-foundation

## Scope

`apps/devhud` contains the implemented deterministic bilingual React/TypeScript frontend and target-isolated Rust/Tauri desktop, mobile, and widget hosts for `devhud`. Desktop uses pinned CEF; iOS and Android reuse the same frontend through system webviews, with native WidgetKit and AppWidgetProvider extensions. The shell implements the complete guest/Logto identity and schema-versioned Settings boundary against the generated Connect client, explicit Home, mobile RealQA-unavailable, populated Deck, Settings, Account, Diagnostics, Loading, Empty, Offline, Blocked, and Error compositions, a closed first-party registry, a direct-client GitHub.com issue/pull-request provider, accessible credential setup, and a versioned native bridge. Desktop capture, the bilingual editor, encrypted draft recovery, official/BYO direct image uploads, direct GitHub issue submission, Deck synchronization, and home-screen Deck widgets are implemented; other populated product-result surfaces remain planned.

## Runtime and Language

- Desktop: Tauri `tauri-runtime-cef` from `https://github.com/tauri-apps/tauri`, pinned to `4af26a3f7f8b692d62cca549bbacd93f5ce90b41`; CEF renders bundled resources only with restrictive CSP and no arbitrary navigation, popups, or downloads. The default packaged policy denies connections; the host replaces only the `connect-src` response directive with the validated selected API, fixed `https://api.github.com`, and same-origin Logto discovery endpoint for the active session. The fixed development server additionally permits only its `ws://127.0.0.1:46305` HMR endpoint and Rsbuild's injected inline styles. Future signed-upload origins require the same explicit validation before entering a session policy.
- Mobile: Tauri/Wry using WKWebView on iOS and Android System WebView, with no CEF runtime or bundled browser engine. WidgetKit on iOS and AppWidgetProvider on Android make direct GitHub requests without a broker.
- Targets: macOS 13+, Windows 10 22H2+, Ubuntu 22.04 LTS on X11, iOS 16+ arm64 device and arm64/x64 simulators, Android 10/API 29+ arm64/armv7 production and x64 emulator; Android i686 is excluded.
- Bundle ID: `io.delino.devhud`; deep-link scheme: `devhud`. Fixed frontend port: `46305`.
- English source and Korean/English user-facing UI. Language and System/Light/Dark theme are authoritative synchronized settings for authenticated users and local guest settings otherwise; the shell mirrors the last applied appearance locally only to avoid an incorrect initial render before identity state loads. The resolved language updates localized content and tray labels, while the resolved theme sets the document color scheme so native controls follow the selected appearance. The shell follows Toss Design Guidelines and includes WCAG 2.2 AA-oriented checks for named controls, deterministic focus, reduced motion, high-contrast tokens, and Escape closure for its command palette; formal accessibility qualification remains pending.

## Users and Operators

Guest users, authenticated individual users, maintainers, and platform release operators. RealQA is desktop-only; Deck is desktop/mobile.

## Implemented Desktop Host

- The desktop Tauri wrapper rejects caller `-t`/`--target` overrides and stages the exact Native Messaging host executable path reported by Cargo under the artifact's effective target triple, with its artifact-derived executable suffix, so custom target directories and cross-target Cargo configuration cannot select or name a missing or stale sidecar.
- `apps/devhud/src-tauri` is a root Cargo workspace member. It uses authoritative upstream Tauri git dependencies at revision `4af26a3f7f8b692d62cca549bbacd93f5ce90b41`; the sole root patch redirects official crates.io `tauri`, `tauri-plugin`, and `tauri-utils` dependencies to that same revision so the official desktop deep-link plugins share one CEF runtime type graph. Branch dependencies, `feat/cef`, forks, every other Cargo patch, and vendored upstream modifications are forbidden and mechanically checked.
- `apps/devhud/cef-pins.json` records the resolved Tauri package versions (`tauri` 2.11.5, `tauri-build` 2.6.3, `tauri-cli` 2.11.4, and `tauri-runtime-cef` 0.1.0), CEF Rust crates `cef` and `cef-dll-sys` `150.0.0+150.0.10`, `download-cef` 2.3.2, their registry checksums, upstream source revisions, and every platform archive SHA-1. The verifier owns independent immutable copies of the CEF Rust and download-helper versions, checksums, revisions, and the six archive names and hashes. The runtime archive version is CEF `150.0.10+g8042e43+chromium-150.0.7871.101`.
- The runtime's default sandbox feature remains enabled. The executable uses Tauri's CEF entry point so renderer, GPU, plugin, and other helper processes cannot enter browser-process application initialization. Production startup preflights the platform-specific CEF library, ICU/resource packs, locale, sandbox/bootstrap files, and macOS helper applications relative to the installed executable; Linux package resources are resolved from `<prefix>/share/DevHUD` next to `<prefix>/bin`. Missing material produces a structured `cef_fatal_initialization` diagnostic with bounded actionable reason classifications and exit code 78 before the browser starts, without logging resolved host paths.
- Navigation is restricted to bundled `http://tauri.localhost` content in production and exact `http://127.0.0.1:46305` content in development. Popups and downloads are denied. The Rsbuild development launcher binds only `127.0.0.1:46305`, preflights collisions, and never chooses another port. The Tauri command wrapper rejects all `-c` and `--config` overrides, including attached short values, so callers cannot replace the pinned application configuration; it injects the repository-owned desktop bundle overlay after staging the Native Messaging sidecar, while the shared desktop/mobile configuration remains sidecar-free. It forwards `SIGINT` and `SIGTERM`, mirrors signal-based exits, and on every supported desktop platform terminates and awaits the complete Cargo, Tauri CLI, desktop-host, and Rsbuild process tree. Timed-out platform smokes use the same complete-tree termination on every supported desktop platform before temporary cache and log cleanup.
- Structured diagnostics cover platform/display selection, resource discovery, frontend readiness, renderer termination, fatal initialization, smoke shutdown, clean host shutdown, external-opener failures, tray hide/restore failures, tray-language update failures, and capture failures identified only by action, adapter platform, and stable error code. After React mounts, it changes the document title to `DevHUD` and invokes the native `frontend_ready` command; the host atomically accepts that CEF-supported readiness signal before dispatching smoke behavior. An independent five-second wall-clock watchdog emits `frontend_readiness_timeout` and terminates with exit code 1 if readiness does not complete. macOS uses the typed CEF renderer-termination callback; every packaged Windows and Linux launch enables the CEF Inspector domain and registers the DevTools protocol crash listener, while the deliberate `Page.crash` request and its watchdog remain exclusive to the renderer-crash smoke. Desktop release hosts retain timestamped, redacted JSON diagnostics in UTC-daily `devhud.YYYY-MM-DD.jsonl` files under `%LOCALAPPDATA%\io.delino.devhud\logs` on Windows, `~/Library/Logs/io.delino.devhud` on macOS, and `${XDG_STATE_HOME:-~/.local/state}/io.delino.devhud/logs` on Linux, keeping at most seven daily files while preserving stderr output for managed launches and smoke capture; destructive diagnostic cleanup closes the active file sink, removes only exact app JSONL names, and reopens the sink before later events. Operator `RUST_LOG` filters may tune dependency verbosity, but cannot suppress error-level DevHUD diagnostics. Debug builds and CEF subprocesses remain stderr-only; a file-sink setup failure falls back to stderr without logging the resolved path while retaining that directory for later destructive cleanup.

## Interfaces and Contracts

Every concrete Chrome origin must be covered by its URL mapping scheme, host, and normalized port before the synchronized setting is accepted or published. Settings validation projects the complete IPC and Chrome response envelopes and rejects an oversized Native Messaging configuration before persistence; native validation retains the same 256 KiB checks as defense in depth. Renderer publications serialize in invocation order so an older replacement cannot finish after newer settings, retry the latest snapshot with capped backoff after transient bridge failures, and abandon stale retries when settings or identity changes; every changed valid replacement clears cached context and rotates the opaque configuration revision required by capture requests, while a rejected renderer replacement also rotates that revision and clears prior native authorization.

Release desktop launches register the packaged Chrome host; development launches never replace the installed canonical registration. The pairing UI refreshes status while a pairing code is active, clears transient status failures after a successful poll, then clears the code and stops polling when its native-returned lifetime expires. IPC uses distinct host and app HMAC proofs, with the app proof bound to the challenge and session ID; a host whose authenticated connection has gone idle reauthenticates and retries the pending request once while preserving that request's pairing nonce.

- Desktop owns the Native Messaging security boundary and registration lifecycle. It stages `devhud-native-messaging-host` as a desktop-only Tauri sidecar and enables that sidecar only through the pinned desktop bundle overlay, registers its exact one-origin Chrome manifest on launch, and starts the authenticated `v1` listener without entering the mobile dependency or artifact closure. Rsbuild selects a separate desktop entry for the renderer integration, so Native Messaging modules and command paths are absent from Android/iOS frontend artifacts. The Settings surface publishes only mapping origin/non-secret mapping ID pairs and resolved language, starts a two-minute one-time pairing gesture, exposes paired/unpaired status bilingually, and degrades every extension or listener failure to manual repository selection.
- The listener uses the exact per-user socket/pipe paths and authorization in the extension/host contracts. It authenticates a secure-storage pairing secret with a fresh challenge, one-time pairing nonce, exact compiled extension identity/origin, schema versions, per-request HMAC proof and nonces, five-second deadlines, and replay guards. Unix accept failures retry with capped backoff that resets after a successful accept, while host connection establishment and authentication share one absolute five-second deadline. Pairing completion is serialized with secret rotation and requires the authenticated session generation to remain current. Logout, secure purge, account removal, explicit unpair, or host unregister deletes the pairing secret and invalidates established sessions; unregister uses an authenticated IPC-only control that is not available to Chrome requests and must receive the app's revocation result before reporting success. It accepts only the contracted redacted browser-context shape and never logs payloads.

- `NativeBridgeV1` is a closed tagged request/response contract with one native event stream. It covers runtime/lifecycle, non-destructive pending-auth-callback inspection followed by exact one-shot consumption, validated Deck deep links, bounded non-enumerable secure values and internal API-origin-scoped GitHub PAT associations, local notification consent and Deck-change delivery, store-managed update status/opening, signed desktop updater status/approval operations, structured desktop shortcut status/permission/application, bounded desktop capture/editor/draft operations, and widget status/enable/snapshot/disable operations. A consumed callback is removed from renderer state before callback processing continues so later identity resets cannot reuse it. Notification consent is refreshed whenever the app returns active; expected native consent-request failures keep the shell usable and expose bilingual inline retry feedback; each Deck-change request keeps its own notification identity, while Deck cancellation removes every associated notification. It returns stable safe error codes and no arbitrary URL, native command, filesystem, networking, or raw-key access. Desktop/browser widget calls return typed `unsupported`; mobile widget calls validate configuration and bounded cache before crossing the native boundary, with configuration and snapshot queries using the same 4,096 UTF-16-code-unit bound as synchronized Settings.
- Mobile registers only `devhud` and accepts only `devhud://auth/callback`, optionally with OAuth query parameters, plus canonical `devhud://deck/<deck-id>` links. Native handlers reject other hosts, paths, ports, credentials, fragments, and malformed inputs without logging callback content. Cold-start delivery is bounded and consumed once; foreground delivery uses the typed bridge event.
- Desktop updates are implemented through the closed native updater described in `apps-devhud-updater-contract.md`. They use no bootstrap override or token, do not block startup, keep updater networking outside frontend navigation/CSP, preserve the installed version for pre-install failures and successful rollbacks, expose restart-only recovery after committed or potentially committed installs and failed AppImage rollback, require three explicit approvals, and hand off both single-instance ownership and the Unix Native Messaging listener before a replacement can acknowledge health. Mobile retains only store-managed update operations.
- iOS app secrets use non-synchronizing main-app Keychain items; upgrades retain temporary access to the former shared group so reads migrate values and every write, removal, logout, API change, or account deletion removes legacy copies. The signed containing app owns the contracted App Group plus main/shared Keychain entitlements, and the widget receives only the explicitly selected PAT under the distinct `io.delino.devhud.widget-credential.v1` service in the shared group. Non-secret widget configuration, snapshots, transaction state, and foreground reload deadlines live in coordinated, atomically replaced App Group files; their directories and every replacement file are verified backup-excluded after each write, and migration writes the excluded files before erasing legacy App Group defaults and recording completion. A transaction marker blocks widget credential reads across interrupted configuration/Keychain updates, and startup reconciliation removes interrupted or orphaned widget credentials before clearing the marker. Android app secrets and widget credentials use separate Keystore AES-GCM aliases and separate app-private preference files; an app-private transaction marker likewise blocks interrupted widget credential reads, and widget-store initialization retains a failed reconciliation for retry while status and mutations fail as storage errors until it succeeds. Copied widget PAT replacement advances an opaque native credential revision on both platforms, and a refresh may persist or publish its result only while the revision read with its PAT remains current. Every secret and widget state file is excluded from cloud backup and device transfer. A legacy app-secret value without AAD is accepted only after successful GCM authentication and is immediately rewritten with setting-key AAD. Neither platform offers secret enumeration. Mobile updates are delegated to App Store/Google Play; the bridge cannot download or install an update.
- Android release manifests grant only System WebView networking and local notification permissions. Native authentication accepts configured issuer paths and loopback HTTP development issuers after the same origin validation used by the shared frontend.

- First-party mini-app IDs: `realqa`, `deck`. Action IDs include the five `realqa.capture.*` identifiers defined in the project index. The registry is closed and enum-backed, includes navigation/settings actions, filters actions by platform capability before rendering navigation or the command palette, and cannot load third-party mini-apps.
- Desktop shortcuts use the six closed enum actions: command palette and the five contracted `realqa.capture.*` actions. Settings persist only `{ enabled, modifiers, key }` enum values. `right-primary` resolves to physical right Command on macOS and physical right Control on Windows/X11; left Control and left Meta/Command remain independent native pressed states. Defaults are right-primary+`K` and bare `1`–`5`. Candidate bindings reject unknown fields and are rejected before persistence for malformed values, duplicate chords, reserved OS chords (including Windows Alt+Tab), registration failures, and permission denial; a candidate is staged before persistence and activates only after the snapshot succeeds, while a failed persistence or rollback leaves the last valid binding active. An additional unconfigured right Control on macOS or right Meta on Windows/X11 invalidates a chord without being persisted, bridged, or diagnosed. The always-mounted desktop boundary waits for authenticated settings to resolve from a valid snapshot or cache before native hydration, suspends matching after explicit or automatic session cleanup and suspends previously active guest matching during authenticated hydration gaps, and prevents guest or native defaults from overriding persisted settings; it loads the authenticated cache before blocked-user hydration. A failed native apply makes the command-palette trigger unavailable, while a platform-reserved synchronized binding reapplies the native backend's last platform-valid map without rewriting shared settings and displays that active map. Recoverable listener failures use capped backoff, clear transient pressed modifiers before the replacement listener accepts events, and retain staged current bindings across recovery. Command-palette, selection, and toolbar shortcuts restore and focus the main window before their events are emitted; display, active-window, and all-display shortcuts remain UI-independent. - Local guest settings and authenticated synchronized settings use whole-snapshot import choice, matching envelope/canonical-body schema versions, monotonic revision, expected-revision writes, typed conflict, and explicit reapply. - Synchronized settings cross the wire as at most 1 MiB of RFC 8785 canonical UTF-8 JSON bytes. The client validates every fetched and replacement snapshot envelope schema and canonical bytes before updating or caching state; invalid snapshots and query failures preserve the last valid state as read-only and surface a recoverable typed synchronization error with correlation metadata. - Settings schema version 5 retains schema-v4 appearance, Deck, GitHub, URL-mapping, shortcut, and agent fields and adds upload-provider selection plus non-secret BYO R2 metadata. Schema-v1 and schema-v2 prefix mappings, plus the prefix-shaped schema-v3 collision form, are validated then discarded during migration because they cannot safely select a repository/profile; structured mappings in the schema-v3 collision form migrate forward. New mapping drafts begin visibly unselected and require explicit configured-profile selection; newly assigned or changed repository/profile pairs resolve that profile's device-local PAT and validate GitHub access before saving. Matching ignores query/fragment, rejects authority backslashes and every host the browser URL parser rejects, canonicalizes literal paths and internationalized concrete DNS hosts (including terminal DNS root labels) while preserving trailing/repeated empty path segments and distinct serialized escapes, handles bracketed IPv6 literals, treats HTTP(S) default ports as portless, and deterministically selects priority, literal specificity, then newest update. ## Storage

Persist tokens, PATs, and R2 keys only in platform secure storage. GitHub PAT profile values never enter synchronized JSON, Web Storage, Connect requests, or `devhud-api`; only stable non-secret profile descriptors, references, and pending-removal tombstones synchronize. Profile removal commits the descriptor deletion and tombstone together, retries native PAT deletion while the tombstone remains, and clears it only after secure deletion succeeds. The always-mounted identity/settings boundary reconciles internal API-origin-scoped GitHub PAT associations and publishes the current bounded non-secret Native Messaging mapping configuration regardless of the active product surface. It deletes an orphaned PAT only after its last origin scope releases it and without exposing credential enumeration to the frontend. Origin-scoped associations preserve unrelated credentials across API-origin changes. Silent tombstone cleanup and user settings edits apply as functional updates to the latest local snapshot, and a failed rollback after a PAT write remains explicitly retryable. A newly written PAT remains available while its proposed profile snapshot awaits revision-conflict resolution; reapplying retains it and adopting the server causes reconciliation to remove it. Keep API origins, agent paths/versions, autostart, drafts, clone caches, Deck result caches, window/widget state, Native Messaging pairing, permission records, and browser permissions device-local, encrypting sensitive drafts and cached content as their contracts require. Desktop secure storage fails closed through macOS Keychain, Windows Credential Manager, or the Linux Secret Service and never falls back to plaintext. Windows stores logical secure values and their internal enumeration index through alternating versioned credential-chunk generations whose physical UTF-8 byte chunks are at most 1,024 bytes, reads legacy single-entry values and version-one string chunks, restores the prior logical credential if index maintenance fails, and removes active or stale chunks at every scoped deletion boundary. iOS uses non-synchronizing Keychain items in `$(AppIdentifierPrefix)io.delino.devhud.shared` plus App Group `group.io.delino.devhud`; Android uses Keystore-backed authenticated encryption excluded from backup and device transfer. Native secure storage is non-enumerable to the frontend but supports scoped and complete internal deletion. A synchronized profile reference with no local secret always enters setup rather than selecting another profile. Authenticated settings caching is best-effort when Web Storage is unavailable, and online or offline startup that finds no authenticated session clears the prior origin's authenticated settings snapshot before another user can reuse it. Auto-save unsubmitted captures as encrypted drafts for 30 days with a default 10 GiB quota; never evict before deadline and reject new saves recoverably when full. Delete drafts after successful issue creation, explicit deletion, or logout. Synchronized settings contain no secrets or device state. UUID v7 is the default for Decks, credential profiles, submissions, drafts, and other new persisted entities.

A changed valid Native Messaging configuration clears cached browser context and invalidates the prior active session generation, including when mappings change within the same identity scope. The renderer also supplies a fresh opaque scope UUID whenever the API-origin or account identity scope changes; changing that UUID clears context and invalidates the prior active session generation even when the derived configuration bytes are identical. A rejected or oversized replacement additionally clears the prior native authorization snapshot and invalidates in-flight sessions. Logout and account deletion invalidate in-memory pairing state and active session generations before secure-storage cleanup is attempted.

Every native GitHub PAT read requires the matching API-origin/profile association. A failed desktop or iOS PAT write restores the prior association state so it cannot introduce an orphan marker that retains or exposes another origin's credential.

## Security

Logout deletes every local Logto/GitHub/R2 credential, cached settings, Deck data, clones, drafts, permission records, and extension pairing item while preserving the selected API origin and completed-onboarding marker. Account deletion blocks access immediately and deletes PAT/R2 credentials plus account-local data except unsubmitted RealQA drafts, which remain encrypted through recovery, while retaining only the current Logto session required for authenticated `RestoreAccount`; clients retry that local cleanup whenever they observe a pending deletion. Pending-deletion Web Storage enumeration and removal are best-effort and cannot prevent the authoritative native PAT/R2 purge, but incomplete cleanup remains retryable. Logout instead requires contracted Web Storage cleanup to complete before native secure-store purge, leaving the secure session and logout action available when the local wipe must be retried; diagnostic event and correlation writers remain suppressed from the initial local wipe through completion of logout and purge-claimed irreversible cleanup transactions. Explicit logout and recovery expiry delete the recovery session. A purge-claimed account never exposes Restore or authenticated product access, but retains its Logto session solely as a restart-safe cleanup marker until contracted Web Storage cleanup succeeds; only then does irreversible native purge complete and the shell transition to signed-out. Invalid Logto credentials clear the session and return the shell to signed-out. Restore reloads synchronized data, clears only deletion state, and preserves an independent administrative block. Deletion allows 30-day recovery, then purges synchronized data and official image bytes. Deletion/quarantine replaces the origin object before purging or revalidating the public CDN URL and is not effective while a cached original remains retrievable. Public-image warnings are localized. Local-agent direct mode requires per-submission consent, isolated managed clones, ephemeral `GH_TOKEN`, a 15-minute limit, schema validation, and no automatic fallback.

## Logging

Use redacted structured diagnostics. The recursive boundary drops tokens, authorization/PAT/R2/signing values, request/response headers and bodies, private repository data, browser DOM, screenshots, URLs and fragments, form values, issue bodies, local-agent prompts/output, child environments, arbitrary full paths, and shortcut keystrokes. It retains only safe enum classifications, UUID v7 correlations, app/build version, platform/architecture, OS classification, exact pinned Tauri revision on native hosts (empty for browser), exact desktop CEF revision (empty for mobile system webviews and browser), timestamps, bounded durations, and at most 64 path-free stack function names. Local events remain offline under `devhud.diagnostics.v1.*` for at most 7 days, 500 events, 1 MiB, and 128 Connect correlation breadcrumbs; application startup and later reads rewrite or remove expired, invalid, and over-limit persisted collections so retention is physical. Events and correlation breadcrumbs retain those bounds in session memory when Web Storage writes fail, persist when it recovers, and clear from both storage layers during destructive cleanup. Desktop JSONL logs remain capped at seven daily files. Logout, account-deletion cleanup, and contracted local-data deletion remove diagnostics; API-origin changes preserve them, and native cleanup removes only exact app diagnostic JSONL filenames before reopening its active sink.

Crash reporting has no persistent enablement state and is off by default. Guests may preview the exact redacted export and explicitly choose its destination, and only one destination request may remain active at a time; desktop logout and account-deletion purge invalidate any older pending destination result before purge completes, returning cancellation without writing the captured bundle. Imported and persisted local event strings are normalized and recursively redacted only after percent-encoded octets are decoded and rescanned to a bounded fixed point for prohibited locators and sensitive content; input still changing beyond that bound is rejected. Authenticated and unblocked users may submit only after previewing the exact request and granting per-payload consent, and blocked/deletion-pending users cannot submit. Submissions use `DiagnosticsService.SubmitCrashReport` with typed build/platform/component/severity/code fields; build identifiers are at most 256 UTF-8 bytes, error codes are uppercase enum-style classifications of at most 64 bytes, the redacted summary is at most 4 KiB, the redacted stack trace is at most 32 KiB/64 lines/512 bytes per line, related correlations are capped at 32, and duration is capped at 24 hours. Error-code classification is structural and does not apply narrative-content matching to enum names. The server revalidates the complete boundary and retains accepted reports for exactly 30 days. No analytics or remote feature flag participates in diagnostics.

## Build and Test

Package-local commands are:

The package-level Turbo configuration disables caching for DevHud's native `build` task because its executable and installer outputs live under the root Cargo `target/` directory and must be regenerated rather than restored as frontend-only output.

- `pnpm --filter devhud dev` — launch the pinned Tauri CLI and strict-port frontend.
- `pnpm --filter devhud build` — produce a production desktop build with bundled frontend and CEF material.
- `pnpm --filter devhud test` — type-check, reject Tauri CLI configuration overrides, validate English/Korean locale selection and light/dark eyebrow contrast, and compare two clean frontend builds by path, mode, and SHA-256 while rejecting remote HTML, JavaScript, and CSS loads, including protocol-relative references and WebSocket, EventSource, XMLHttpRequest, Worker, SharedWorker, and Beacon connections.
- GitHub adapter and setup tests use committed deterministic fixtures for public/private and never-pushed empty repositories, fine-grained/classic PATs, issue-write probing, repository restrictions, organization denial, missing scopes/tokens, secure-storage failure, conflict-safe profile removal, read-only PAT controls, replacement retention, API-origin-scoped reconciliation, concurrent guest cleanup/settings writes, failed rollback retry, platform-aware PAT links, pagination, labels, ETags/rate limits, search-index-lag marker reconciliation, and pull-request enrichment. Isolation assertions prove synchronized JSON contains only profile IDs/descriptors, every adapter request targets `api.github.com`, and no server transport observes a PAT or GitHub operation.
- `pnpm --filter devhud verify:pins` — verify exact git revisions, registry checksums, archive hashes, frontend versions, production CSP directives, all-target Cargo features, exact CI target/runner pairs, and the source of every resolved dependency reachable from DevHUD so branch, fork, and patch dependencies cannot enter the protected graph.
- `pnpm --filter devhud smoke:platform` — validate helper/resource discovery, sandboxed browser startup, three independent startup/shutdown cycles, renderer-failure diagnostics, fatal missing-resource diagnostics, and every expected marker in an isolated persisted JSONL sink against a production artifact. Linux requires `--artifact` to reference an installed or root-prepared package layout whose CEF SUID sandbox is owned by `root:root` with mode `4755`; macOS and Windows retain their default production-artifact paths.
- `pnpm --filter devhud mobile:generate` / `mobile:check` — materialize ignored Apple/Android project output from pinned Tauri plus committed platform definitions, or byte-verify the deterministic overlays without requiring both vendor toolchains.
- `pnpm --filter devhud build:ios`, `build:ios:sim:arm64`, `build:ios:sim:x64`, `build:android`, `build:android:arm64`, `build:android:armv7`, and `build:android:emulator:x64` — build only the contracted fixed device/simulator/emulator architecture sets. The x64 iOS command builds its frontend with `TAURI_ENV_PLATFORM=ios`, keeps a pinned-Tauri project-open process alive for the generated Xcode phase's CLI-owned options, and has Xcode build the generated workspace explicitly against the x64 simulator SDK instead of Tauri's device-oriented archive path. Android builds copy each requested APK/AAB to `target/devhud-mobile/android/<tauri-target>/`, preserving both production architectures across the aggregate command.
- `pnpm --filter devhud verify:mobile` — assert the complete immutable target tuples and resolved production-default normal-dependency closure hashes, minimum versions, identity, deep-link registration, permissions, Android secure-setting backup exclusions, shared-frontend parity, system-webview use, and the absence of CEF, desktop-hook, extension, updater-downloader, push, and unintended networking material.

`.github/workflows/CI.yml` provides native x64 and arm64 build/smoke definitions for macOS, Windows, and Ubuntu 22.04 X11. Mobile contract, iOS, and Android jobs use the same workflow-dispatch-or-relevant-DevHUD-path gate as desktop validation; Android production rows build and inspect both APK and Google Play AAB output, while the x64 emulator row remains APK-only. Ubuntu jobs validate that the Debian archive records `chrome-sandbox` as `root:root` with mode `4755` before repairing ownership solely in the non-root smoke extraction. Credential-free macOS development and CI bundles use Tauri's ad hoc signing identity with hardened runtime disabled so CEF helpers can execute; release signing remains a separate release gate that must override that identity and supply the production hardened-runtime entitlements. Root Rust validation remains `cargo fmt --all --check`, `cargo clippy --workspace --all-targets --all-features -- -D warnings`, and `cargo test --workspace --all-targets`.

Current proven limitations are deliberate: populated issue result surfaces beyond the confirmed canonical link and production installers/signing are not implemented. The desktop updater and platform package handoff are implemented, but production update publication remains blocked until the production release public key replaces the explicit placeholder and platform signing/qualification succeeds. Identity, Settings, GitHub.com provider/setup and direct issue creation, dynamic session CSP, exact auth callback transport, secure credential adapters, capture, direct official/BYO image upload, shortcut registration/matching, populated Deck results, Deck deep links, and native widget targets are implemented boundaries; packaged platform-hook qualification, minimum-version device qualification, and signed store release remain release gates.
