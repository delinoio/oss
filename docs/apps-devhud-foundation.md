# apps-devhud-foundation

## Scope

`apps/devhud` contains the implemented deterministic bilingual React/TypeScript frontend and target-isolated Rust/Tauri desktop and mobile hosts for `devhud`. Desktop uses pinned CEF; iOS and Android reuse the same frontend through system webviews. The shell implements the complete guest/Logto identity and schema-versioned Settings boundary against the generated Connect client, explicit Home, mobile RealQA-unavailable, Deck, Settings, Account, Diagnostics, Loading, Empty, Offline, Blocked, and Error compositions, a closed first-party registry, and a versioned native bridge. Capture, GitHub product data, and native widgets remain planned.

## Runtime and Language

- Desktop: Tauri `tauri-runtime-cef` from `https://github.com/tauri-apps/tauri`, pinned to `4af26a3f7f8b692d62cca549bbacd93f5ce90b41`; CEF renders bundled resources only with restrictive CSP and no arbitrary navigation, popups, or downloads. The default packaged policy denies connections; the host replaces only the `connect-src` response directive with the validated selected API and same-origin Logto discovery endpoint for the active session. The fixed development server additionally permits only its `ws://127.0.0.1:46305` HMR endpoint and Rsbuild's injected inline styles. Future GitHub and signed-upload origins require the same explicit validation before entering a session policy.
- Mobile: Tauri/Wry using WKWebView on iOS and Android System WebView, with no CEF runtime or bundled browser engine. Native widgets are not part of this foundation.
- Targets: macOS 13+, Windows 10 22H2+, Ubuntu 22.04 LTS on X11, iOS 16+ arm64 device and arm64/x64 simulators, Android 10/API 29+ arm64/armv7 production and x64 emulator; Android i686 is excluded.
- Bundle ID: `io.delino.devhud`; deep-link scheme: `devhud`. Fixed frontend port: `46305`.
- English source and Korean/English user-facing UI. Language and System/Light/Dark theme are authoritative synchronized settings for authenticated users and local guest settings otherwise; the shell mirrors the last applied appearance locally only to avoid an incorrect initial render before identity state loads. The resolved language updates localized content and tray labels, while the resolved theme sets the document color scheme so native controls follow the selected appearance. The shell follows Toss Design Guidelines and includes WCAG 2.2 AA-oriented checks for named controls, deterministic focus, reduced motion, high-contrast tokens, and Escape closure for its command palette; formal accessibility qualification remains pending.

## Users and Operators

Guest users, authenticated individual users, maintainers, and platform release operators. RealQA is desktop-only; Deck is desktop/mobile.

## Implemented Desktop Host

- `apps/devhud/src-tauri` is a root Cargo workspace member. It uses authoritative upstream Tauri git dependencies at revision `4af26a3f7f8b692d62cca549bbacd93f5ce90b41`; the sole root patch redirects official crates.io `tauri`, `tauri-plugin`, and `tauri-utils` dependencies to that same revision so the official desktop deep-link plugins share one CEF runtime type graph. Branch dependencies, `feat/cef`, forks, every other Cargo patch, and vendored upstream modifications are forbidden and mechanically checked.
- `apps/devhud/cef-pins.json` records the resolved Tauri package versions (`tauri` 2.11.5, `tauri-build` 2.6.3, `tauri-cli` 2.11.4, and `tauri-runtime-cef` 0.1.0), CEF Rust crates `cef` and `cef-dll-sys` `150.0.0+150.0.10`, `download-cef` 2.3.2, their registry checksums, upstream source revisions, and every platform archive SHA-1. The verifier owns independent immutable copies of the CEF Rust and download-helper versions, checksums, revisions, and the six archive names and hashes. The runtime archive version is CEF `150.0.10+g8042e43+chromium-150.0.7871.101`.
- The runtime's default sandbox feature remains enabled. The executable uses Tauri's CEF entry point so renderer, GPU, plugin, and other helper processes cannot enter browser-process application initialization. Production startup preflights the platform-specific CEF library, ICU/resource packs, locale, sandbox/bootstrap files, and macOS helper applications relative to the installed executable; Linux package resources are resolved from `<prefix>/share/DevHUD` next to `<prefix>/bin`. Missing material produces a structured `cef_fatal_initialization` diagnostic and exit code 78 before the browser starts.
- Navigation is restricted to bundled `http://tauri.localhost` content in production and exact `http://127.0.0.1:46305` content in development. Popups and downloads are denied. The Rsbuild development launcher binds only `127.0.0.1:46305`, preflights collisions, and never chooses another port. The Tauri command wrapper rejects all `-c` and `--config` overrides, including attached short values, so callers cannot replace the pinned application configuration; it forwards `SIGINT` and `SIGTERM`, mirrors signal-based exits, and on every supported desktop platform terminates and awaits the complete Cargo, Tauri CLI, desktop-host, and Rsbuild process tree. Timed-out platform smokes use the same complete-tree termination on every supported desktop platform before temporary cache and log cleanup.
- Structured diagnostics cover platform/display selection, resource discovery, frontend readiness, renderer termination, fatal initialization, smoke shutdown, clean host shutdown, external-opener failures, tray hide/restore failures, and tray-language update failures. After React mounts, it changes the document title to `DevHUD` and invokes the native `frontend_ready` command; the host atomically accepts that CEF-supported readiness signal before dispatching smoke behavior. An independent five-second wall-clock watchdog emits `frontend_readiness_timeout` and terminates with exit code 1 if readiness does not complete. macOS uses the typed CEF renderer-termination callback; every packaged Windows and Linux launch enables the CEF Inspector domain and registers the DevTools protocol crash listener, while the deliberate `Page.crash` request and its watchdog remain exclusive to the renderer-crash smoke. Desktop release hosts retain timestamped, redacted JSON diagnostics in UTC-daily `devhud.YYYY-MM-DD.jsonl` files under `%LOCALAPPDATA%\io.delino.devhud\logs` on Windows, `~/Library/Logs/io.delino.devhud` on macOS, and `${XDG_STATE_HOME:-~/.local/state}/io.delino.devhud/logs` on Linux, keeping at most seven daily files while preserving stderr output for managed launches and smoke capture; operator `RUST_LOG` filters may tune dependency verbosity but cannot suppress error-level DevHUD diagnostics. Debug builds and CEF subprocesses remain stderr-only, and a file-sink setup failure falls back to stderr without logging the resolved path.

The architecture definitions in `apps/devhud/platforms.json` are authoritative for the desktop foundation:

| Platform | Architectures | Product minimum | Native CI definition |
| --- | --- | --- | --- |
| macOS | x64, arm64 | 13.0 | `macos-15-intel`, `macos-15` |
| Windows | x64, arm64 | 10 22H2 | `windows-2022`, `windows-11-arm` |
| Ubuntu X11 | x64, arm64 | 22.04 LTS | `ubuntu-22.04`, `ubuntu-22.04-arm` |

XWayland is best effort. Native Wayland is unsupported and rejected before CEF initialization. CI hosts newer than the macOS and Windows product minimums prove current native build/smoke compatibility, not the exact minimum OS; release qualification on macOS 13 and Windows 10 22H2 remains required. Ubuntu smoke certification is intentionally limited to Ubuntu 22.04+ with an X11 `DISPLAY`.

## Interfaces and Contracts

- `NativeBridgeV1` is a closed tagged request/response contract with one native event stream. It covers runtime/lifecycle, non-destructive pending-auth-callback inspection followed by exact one-shot consumption, bounded non-enumerable secure values, local notification consent and Deck-change delivery, store-managed update status/opening, structured desktop shortcut status/permission/application, and future widget snapshot replacement/clearing. A consumed callback is removed from renderer state before callback processing continues so later identity resets cannot reuse it. Notification consent is refreshed whenever the app returns active; expected native consent-request failures keep the shell usable and expose bilingual inline retry feedback; each Deck-change request keeps its own notification identity, while Deck cancellation removes every associated notification. It returns stable safe error codes and no arbitrary URL, native command, filesystem, networking, or raw-key access. Widget calls return `unsupported` until widget targets and their shared entitlements are implemented.
- Mobile registers only `devhud` and accepts only `devhud://auth/callback`, optionally with OAuth query parameters. Native handlers reject other hosts, paths, ports, credentials, fragments, and malformed inputs without logging callback content. Cold-start delivery is bounded and consumed once; foreground delivery uses the typed bridge event.
- iOS secrets use non-synchronizing shared-access-group Keychain items; upgrades retain temporary access to the legacy application group so reads migrate values and every write, removal, logout, API change, or account deletion removes legacy copies. Android uses Keystore-backed encrypted app-private values excluded from backup; a legacy no-AAD value is accepted only after successful GCM authentication and is immediately rewritten with setting-key AAD. Neither platform offers enumeration. Mobile updates are delegated to App Store/Google Play; the bridge cannot download or install an update.
- Android release manifests grant only System WebView networking and local notification permissions. Native authentication accepts configured issuer paths and loopback HTTP development issuers after the same origin validation used by the shared frontend.

- First-party mini-app IDs: `realqa`, `deck`. Action IDs include the five `realqa.capture.*` identifiers defined in the project index. The registry is closed and enum-backed, includes navigation/settings actions, filters actions by platform capability before rendering navigation or the command palette, and cannot load third-party mini-apps.
- Desktop shortcuts use the six closed enum actions: command palette and the five contracted `realqa.capture.*` actions. Settings persist only `{ enabled, modifiers, key }` enum values. `right-primary` resolves to physical right Command on macOS and physical right Control on Windows/X11; left/right are distinct at the native event boundary. Defaults are right-primary+`K` and bare `1`–`5`. Candidate bindings reject unknown fields and are rejected before persistence for malformed values, duplicate chords, reserved OS chords, registration failures, and permission denial; a candidate is staged before persistence and activates only after the snapshot succeeds, while a failed persistence or rollback leaves the last valid binding active. The always-mounted desktop boundary waits for authenticated settings to resolve from a valid snapshot or cache before native hydration, keeping shortcuts inactive through onboarding and preventing guest or native defaults from overriding persisted settings. A platform-reserved synchronized binding reapplies the native backend's last platform-valid map without rewriting shared settings. Recoverable listener failures use capped backoff, clear transient pressed modifiers before the replacement listener accepts events, and retain staged current bindings across recovery. A command-palette shortcut restores and focuses the main window before its event is emitted. Capture shortcuts remain visibly unavailable and non-editable until capture integration exists. The event matcher retains no raw events and emits only a configured closed action; diagnostics contain only redacted failure categories.
- The command palette opens only for its active localized visible binding after first-run onboarding, contains its keyboard focus while open, and offers only capability-available actions. Repeated shortcut events leave it open. It restores focus to its trigger on Escape and normal completion, except that Account completion preserves focus for the API-origin input. The resolved local language and theme are applied to the document before the initial localized React content renders; while the language preference is System, operating-system language changes synchronize rendered copy, document language, and tray labels. Capture and service actions remain visibly unavailable until their native/service integrations exist.
- macOS shortcut setup presents localized Accessibility and Input Monitoring guidance. Linux shortcut setup presents localized X11/XWayland, `DISPLAY`, and X authority guidance; native Wayland is unsupported. Windows requires no additional privacy permission for this contracted backend.
- Local shell links and Logto authorization use the system browser only through native closed validation: native session policy retains the complete normalized configured issuer, the authorization request must name that exact issuer, and its destination must remain on the same origin at the issuer path or a descendant path. CSP still derives only the validated issuer origin, while other openers remain limited to the approved GitHub PAT and issue destinations. The shell confirms desktop dispatch in a background worker with a five-second timeout before reporting a link as opened; Linux uses GIO dispatch rather than waiting on the launched browser's lifetime. Unsuccessful, timed-out, or unobservable dispatches return an error and record a structured diagnostic. Documentation remains unavailable until a curated public DevHud destination exists. Arbitrary browser navigation is rejected.
- First run exposes editable `https://devhud.api.delino.io`, Sign in, and Continue locally. Non-loopback endpoints require HTTPS; loopback HTTP, including the bracketed IPv6 literal `[::1]`, is allowed; no TLS bypass. Equivalent bare and trailing-slash API roots normalize to one origin and do not clear or remount identity state, while API origins reject credentials, non-root paths, queries, fragments (including empty delimiters), and whitespace before native validation or session-CSP use; signed-upload origins are validated from the server response. Each Account opener action supersedes prior pending opener status, and API-origin edits or continuing locally invalidate pending actions so delayed completions cannot reset the selected surface. Continue locally also keeps guest settings writable when an already-started Bootstrap attempt later fails; an explicit identity retry or Sign in opts back into identity handling. If Web Storage is unavailable, a complete in-memory Web Storage implementation keeps onboarding and local cleanup usable for the current session without persistence.
- First run and every custom-origin edit explain in English and Korean that the selected API controls authentication discovery and synchronized non-secret settings. An origin change requires confirmation, discards any queued native authentication callback before deleting the prior origin's Logto transaction/session and authenticated cache, preserves unrelated GitHub/R2 profiles, and restarts bootstrap and import selection.
- The Diagnostics surface states that redacted host diagnostics are recorded locally but are not yet viewable in the shell; it must not claim that the current packaged session has no records. Expected native notification-consent and app-store-opening failures remain inline, bilingual, recoverable, and do not replace the shell with a global error state.
- Logto uses system-browser Authorization Code with PKCE and the exact native callback URI `devhud://auth/callback`; one provider-owned in-flight guard prevents overlapping PKCE transactions from either Sign in surface. The official desktop deep-link runtime registers the scheme, forwards Windows/Linux secondary launches into the primary instance, and delivers cold-start and foreground callbacks through the same validated pending-callback boundary. Callbacks received before bootstrap remain queued through issuer-policy reloads and are consumed when the session becomes ready. Bootstrap must identify `PROJECT_ID_DEVHUD` before discovery fields are consumed; protocol schema version controls compatibility, while API version is opaque deployment metadata. The issuer may contain a path and may use HTTP only on loopback in development, the audience is a nonblank configured resource value, and public client IDs remain keyed as `desktop`, `ios`, `android`, and `admin`. Browser/API requests use the documented exact development and pinned Tauri CORS origins and Connect preflight policy. Packaged session CSP permits styles only from `'self'`; the inline-style exception is development-only. A secure-session read failure retains non-destructive retry for transient platform errors and exposes an explicit device-local session reset for malformed or permanently unreadable values. Missing authentication and terminal `invalid_grant` refresh failures clear the invalid session, while network and temporary refresh failures preserve it for retry.
- Local guest settings and authenticated synchronized settings use whole-snapshot import choice, schema version, monotonic revision, expected-revision writes, typed conflict, and explicit reapply. Snapshot-choice dialogs close on Escape or Close without clearing the pending choice and expose a control to reopen it. Offline authenticated settings are read-only.
- Synchronized settings cross the wire as at most 1 MiB of RFC 8785 canonical UTF-8 JSON bytes. The client validates every fetched and replacement snapshot envelope schema and canonical bytes before updating or caching state; invalid snapshots and query failures preserve the last valid state as read-only and surface a recoverable typed synchronization error with correlation metadata. Revision zero means no stored snapshot; a create expects zero and returns one, and each successful replacement increments once. The app must surface `SettingsRevisionConflict` for an explicit reload/reapply decision and must not silently overwrite or retry.
- Settings schema version 1 contains only appearance language/theme; Deck definitions and query/builder/display/refresh/notification state; GitHub repository and issue-tracker configuration; URL mappings; per-platform shortcuts; local-agent enablement/kind/mode/repository prompts and non-secret profile references; and upload-provider selection plus non-secret BYO R2 metadata. Legacy v1 arbitrary shortcut string maps are validated then upgraded to the documented structured defaults; desktop shortcut storage is otherwise a fixed, closed action map of structured modifier/key enums. It never stores platform scan codes, raw key records, or display strings. URL-mapping prefixes and R2 endpoint/public-base URLs reject credentials, queries, and fragments, including empty delimiters, and shortcut actions reject prototype-sensitive names. Unknown fields and every secret or device-local field are rejected before local persistence or synchronization.
- The first authenticated session after guest use always shows a complete recursively redacted local/server snapshot diff. Upload-local uses the server's current revision, including zero; replace-local adopts the server snapshot or schema defaults when none exists. A stale write displays the latest server/local diff and requires either adopting the server or explicitly reapplying the unchanged local snapshot against the returned revision.
- RealQA supports display/window/all-display/region/toolbar capture, editing, encrypted drafts, URL mappings, optional sanitized Chrome context, GitHub issue creation, official/BYO R2, and explicit Codex/Claude Code/OpenCode draft/direct modes. The first `CreateUpload` creates a server-owned UUID v7 submission and upload group for one issue workflow; later groups and finalizations must carry that submission, with at most 10 finalized images across it. Upload checksums are 32 raw bytes and are encoded as standard Base64 only for the R2 checksum header. The server reserves the signed-URL issuance quota before returning each URL and finalization does not charge that reservation again. It excludes mobile capture, screen recording, full-page/console/network/cookie/storage capture, comments, assignees, milestones, projects, and updating existing issues.
- Deck calls GitHub directly, preserves raw `is:pr` queries, caches at most 100 results/Deck, permits 25 Decks/user, and offers 1/5/15/30-minute refresh intervals while a desktop or mobile client is active and able to poll. Widgets and local notifications use the operating system's best-effort background schedule; WidgetKit or the Android scheduler may delay refreshes and cannot honor an app-selected one- or five-minute interval while the app is suspended. The iOS widget target is `io.delino.devhud.widget`; it shares App Group `group.io.delino.devhud` and Keychain access group `$(AppIdentifierPrefix)io.delino.devhud.shared` with the main app, and both targets must provision those entitlements. Widgets show one Deck and three PRs, deep-link to `devhud://deck/<deck-id>`, and visibly show the last successful refresh when data is stale. Notifications must not imply that suspended-widget data is current.
- Keyboard hooks distinguish right Command/Control; default shortcuts are right modifier + `K`, then `1`–`5`. Only configured chords are processed; every binding is editable/disableable and conflicts are diagnosed.
- Server state uses the service-specific Connect Query exports from `@delinoio/devhud-api-client`. The currently deployed API foundation exposes Bootstrap, Settings, and Account; Upload, Diagnostics, and Admin remain planned. Every successful message and typed error preserves response correlation metadata, including failed Settings writes rendered with their safe correlation ID; first-run and post-onboarding Bootstrap failures remain bilingual and explicitly retryable. Pagination uses the default 50/maximum 100 and 2 KiB opaque-token bounds, and future upload creation explicitly selects new submission, new group, or existing group before retaining the returned immutable reservation and staging-generation bindings through finalization.

## Storage

Persist tokens, PATs, and R2 keys only in platform secure storage. Keep API origins, agent paths/versions, autostart, drafts, clone caches, Deck result caches, window/widget state, Native Messaging pairing, permission records, and browser permissions device-local, encrypting sensitive drafts and cached content as their contracts require. Desktop secure storage fails closed through macOS Keychain, Windows Credential Manager, or the Linux Secret Service and never falls back to plaintext. Windows stores logical secure values and their internal enumeration index through alternating versioned credential-chunk generations whose physical UTF-8 byte chunks are at most 1,024 bytes, reads legacy single-entry values and version-one string chunks, restores the prior logical credential if index maintenance fails, and removes active or stale chunks at every scoped deletion boundary. iOS uses non-synchronizing Keychain items in `$(AppIdentifierPrefix)io.delino.devhud.shared` plus App Group `group.io.delino.devhud`; Android uses Keystore-backed authenticated encryption excluded from backup and device transfer. Native secure storage is non-enumerable to the frontend but supports scoped and complete internal deletion. A synchronized profile reference with no local secret always enters setup rather than selecting another profile. Authenticated settings caching is best-effort when Web Storage is unavailable, and online or offline startup that finds no authenticated session clears the prior origin's authenticated settings snapshot before another user can reuse it. Auto-save unsubmitted captures as encrypted drafts for 30 days with a default 10 GiB quota; never evict before deadline and reject new saves recoverably when full. Delete drafts after successful issue creation, explicit deletion, or logout. Synchronized settings contain no secrets or device state. UUID v7 is the default for Decks, submissions, drafts, and other new persisted entities.

## Security

Logout deletes every local Logto/GitHub/R2 credential, cached settings, Deck data, clones, drafts, permission records, and extension pairing item while preserving the selected API origin and completed-onboarding marker. Account deletion blocks access immediately and deletes PAT/R2 credentials plus account-local data while retaining only the current Logto session required for authenticated `RestoreAccount`; clients retry that local cleanup whenever they observe a pending deletion. Web Storage enumeration and removal are best-effort and cannot prevent the authoritative native secure-store purge. Explicit logout, recovery expiry, or a purge-claimed account deletes the recovery session, and purge-claimed accounts never expose Restore. Invalid Logto credentials clear the session and return the shell to signed-out. Restore reloads synchronized data, clears only deletion state, and preserves an independent administrative block. Deletion allows 30-day recovery, then purges synchronized data and official image bytes. Deletion/quarantine replaces the origin object before purging or revalidating the public CDN URL and is not effective while a cached original remains retrievable. Public-image warnings are localized. Local-agent direct mode requires per-submission consent, isolated managed clones, ephemeral `GH_TOKEN`, a 15-minute limit, schema validation, and no automatic fallback.

## Logging

Use redacted structured diagnostics. Never log tokens, headers, DOM, screenshots, URL fragments, form values, full paths, agent environments, or issue bodies. Crash reports are off by default, previewed/redacted, authenticated, and retained 30 days. Submissions use typed build/platform/component/severity/code fields; build/code identifier strings are at most 256 UTF-8 bytes, the redacted summary is at most 4 KiB, and the redacted stack trace is at most 32 KiB. No crash string may contain credential or local-path patterns.

## Build and Test

Package-local commands are:

The package-level Turbo configuration disables caching for DevHud's native `build` task because its executable and installer outputs live under the root Cargo `target/` directory and must be regenerated rather than restored as frontend-only output.

- `pnpm --filter devhud dev` — launch the pinned Tauri CLI and strict-port frontend.
- `pnpm --filter devhud build` — produce a production desktop build with bundled frontend and CEF material.
- `pnpm --filter devhud test` — type-check, reject Tauri CLI configuration overrides, validate English/Korean locale selection and light/dark eyebrow contrast, and compare two clean frontend builds by path, mode, and SHA-256 while rejecting remote HTML, JavaScript, and CSS loads, including protocol-relative references and WebSocket, EventSource, XMLHttpRequest, Worker, SharedWorker, and Beacon connections.
- `pnpm --filter devhud verify:pins` — verify exact git revisions, registry checksums, archive hashes, frontend versions, production CSP directives, all-target Cargo features, exact CI target/runner pairs, and the source of every resolved dependency reachable from DevHUD so branch, fork, and patch dependencies cannot enter the protected graph.
- `pnpm --filter devhud smoke:platform` — validate helper/resource discovery, sandboxed browser startup, three independent startup/shutdown cycles, renderer-failure diagnostics, fatal missing-resource diagnostics, and every expected marker in an isolated persisted JSONL sink against a production artifact. Linux requires `--artifact` to reference an installed or root-prepared package layout whose CEF SUID sandbox is owned by `root:root` with mode `4755`; macOS and Windows retain their default production-artifact paths.
- `pnpm --filter devhud mobile:generate` / `mobile:check` — materialize ignored Apple/Android project output from pinned Tauri plus committed platform definitions, or byte-verify the deterministic overlays without requiring both vendor toolchains.
- `pnpm --filter devhud build:ios`, `build:ios:sim:arm64`, `build:ios:sim:x64`, `build:android`, `build:android:arm64`, `build:android:armv7`, and `build:android:emulator:x64` — build only the contracted fixed device/simulator/emulator architecture sets. The x64 iOS command keeps a pinned-Tauri project-open process alive for the generated Xcode phase's CLI-owned options, while Xcode builds the generated workspace explicitly against the x64 simulator SDK instead of Tauri's device-oriented archive path. Android builds copy each requested APK/AAB to `target/devhud-mobile/android/<tauri-target>/`, preserving both production architectures across the aggregate command.
- `pnpm --filter devhud verify:mobile` — assert the complete immutable target tuples and resolved production-default normal-dependency closure hashes, minimum versions, identity, deep-link registration, permissions, Android secure-setting backup exclusions, shared-frontend parity, system-webview use, and the absence of CEF, desktop-hook, extension, updater-downloader, push, and unintended networking material.

`.github/workflows/CI.yml` provides native x64 and arm64 build/smoke definitions for macOS, Windows, and Ubuntu 22.04 X11. Mobile contract, iOS, and Android jobs use the same workflow-dispatch-or-relevant-DevHUD-path gate as desktop validation; Android production rows build and inspect both APK and Google Play AAB output, while the x64 emulator row remains APK-only. Ubuntu jobs validate that the Debian archive records `chrome-sandbox` as `root:root` with mode `4755` before repairing ownership solely in the non-root smoke extraction. Credential-free macOS development and CI bundles use Tauri's ad hoc signing identity with hardened runtime disabled so CEF helpers can execute; release signing remains a separate release gate that must override that identity and supply the production hardened-runtime entitlements. Root Rust validation remains `cargo fmt --all --check`, `cargo clippy --workspace --all-targets --all-features -- -D warnings`, and `cargo test --workspace --all-targets`.

Current proven limitations are deliberate: capture execution, installers/signing, widget targets, and Deck deep links are not implemented. Shortcut registration/matching contracts are implemented, while packaged platform-hook qualification remains a release gate. Identity, Settings, dynamic session CSP, exact auth callback transport, and secure credential adapters are implemented boundaries; minimum-version device qualification and signed store release remain release gates.

## Dependencies and Integrations

Consumes `protos/devhud/v1` through `packages/devhud-api-client`; talks to `servers/devhud-api` only for bootstrap, settings, uploads, account, diagnostics, and administration. GitHub and user-owned R2 are direct client integrations. Native capture, widgets, and Native Messaging are platform integrations.
