# clibox fspy workflow contract

## Scope

Issue [#971](https://github.com/delinoio/oss/issues/971) defines seven local file-access workflows: `record`, `compare`, `autowatch`, `assetcov`, `latencylab`, `min-repro`, and `fbreak`. This document records their implementation boundary; the issue remains the acceptance contract. The private, Apache-2.0 `clibox-fspy` crate owns the command family, execution, records, analysis, and controls. `clibox` owns only root command composition and redacted parser errors. The existing fspy source fork and its MIT notices remain separate.

## Observation boundary

The current fspy `PathAccess` result is an attempted path-access classification. It cannot establish a successful content read, operation result, duration, or pre-operation intervention. No workflow may promote it to such evidence. A complete execution requires a new operation stream with paired start/completion events and supervised descendant cleanup. Linux must observe syscall entry and exit with ptrace; macOS and Windows extend their injected hooks. A failed injection, lost event, surviving owned descendant, or unavailable tracer makes the execution incomplete. Neither mmap nor asynchronous I/O is in the supported guarantee.

The Linux ptrace supervisor uses `PTRACE_GET_SYSCALL_INFO` to pair selected syscall entries and completions, follows fork/clone/vfork descendants, waits for only its owned tracee TIDs, serializes local sessions, and bounds cancellation, timeout, and surviving-descendant cleanup. It rejects a foreign syscall ABI rather than silently decoding it using the build target's syscall numbers. Its callback may hold the calling thread before a syscall. Callback and event-limit failures run owned-process cleanup before returning. The Linux capture layer decodes selected syscall paths while the tracee is stopped and pairs native results into version-one records, including actual read bytes and descriptor identity. It charges a conservative encoded-size bound before retaining each decoded operation so the byte limit stops collection during execution; final serialization still checks exact encoded size. All native path classifiers retain attempted paths below a regular-file ancestor even when native lookup reports `NotADirectory`; that ordinary failed attempt does not invalidate the whole trace. Native release dry runs execute the GNU and musl x64/arm64 cases; these remain source behavior until a separate publication.

Linux also resolves and classifies the initial executable before `Command::spawn`, because ptrace attaches after its root `exec`. PATH resolution emits bounded failed executable pairs for candidates before the selected executable, retaining project-local absent paths as watch dependencies. The synthetic successful pair is admitted under the trace-session lock and execution deadline, carries the spawned root PID, and can be delayed or held by `--op exec` before any child code runs. Linux launches the exact pre-resolved executable with the original argv zero and arguments, so a PATH change during admission cannot make the child run a different candidate. Project-local root executables therefore enter watch dependencies and reproduction input selection.
Linux root selection checks regular-file type and kernel `faccessat2(X_OK, AT_EACCESS)` authority before admission, including effective-user permissions, ACLs and mount policy. It continues PATH search after `EACCES`, `ENOENT` and `ENOTDIR`, retaining each bounded failed candidate with its native errno before a later selected image. An all-denied search or explicit denied pathname returns a permission failure before child construction; unexpected errors and unavailable kernel checks fail closed without mode-bit or probe-execution fallback. PATH resolution remains bound to the original cwd and command environment, and the selected pathname, original argv zero, arguments, cancellation, limits and image validation retain their existing ownership.


The macOS injected preload sends paired open/read/write/close, scalar and vector positional I/O, descriptor-only truncation, metadata and access checks, directory and pathname-mutation results, including readlink, cwd changes, and stdio open, with before-operation acknowledgment. It is dormant outside an explicit clibox socket and excluded from pnport mode. Once the legacy injected client initializes, each side-channel connection sends a process hello and waits until the receiver records its process start identity before continuing; a forked child opens a new framed connection. A complete candidate requires a hello from the root and every process that emitted operations, so a stripped or failed root injection cannot appear as a valid empty trace. The bounded receiving service accepts injected thread connections through a private temporary socket, rejects malformed frames, invalid native outcomes, duplicate or unpaired events, and exhausted event, byte, or connection limits, and reports receiver failure to its caller. It classifies paths and file identities at operation start while the calling thread awaits acknowledgment; descriptor calls on pipes, sockets, and invalid descriptors do not enter the file record. Interposed caller pathnames are copied through bounded, page-aware Mach reads before either recorder inspects them; invalid and unterminated pointers remain unchanged for the native call and produce paired failed operations with unavailable paths. Internal pathname resolution suppresses recursive interposed calls; native tests include relative project paths. The record assembler carries receipt sequence, outcomes, ancestry, path identity, and native bytes through the strict version-one parser. macOS execution supervision creates a new owned process group, records the start identity of every injected process hello, bounds timeout and cancellation cleanup across both the group and identity-checked descendants that call `setsid`, requires the legacy injection channel to complete, and rejects any tracked child left alive after the root exits. A delay policy holds the matching calling thread before acknowledgment; records distinguish requested and observed delay, while a zero-delay baseline records zero injected delay. Native fixtures confirm scalar/vector I/O, readlink, metadata, directory, and rename results, pipe exclusion, spawned-descendant ancestry, timeout cleanup, stray-descendant rejection, and pre-operation delay accounting. The source CLI composes the workflow handlers; publication requires separate release validation.

Linux pathname decoding carries a closed final-symlink policy per syscall argument. `readlink`/`readlinkat`, `lstat`, supported `AT_SYMLINK_NOFOLLOW` metadata arguments and native entry mutations retain the final entry after resolving ancestors for containment. `linkat` follows only its source when `AT_SYMLINK_FOLLOW` is present; rename/unlink and link destinations retain entry semantics. Open calls with `O_NOFOLLOW` retain entry observations without granting a successful read. Raw terminal separator/dot/parent lookup semantics, descriptor identities and bounded argument reads remain authoritative. Self/dangling and external-target final entries remain project watch inputs, while following accesses and reproduction containment keep their restrictions. Portable Unix resolution/watch fixtures and Linux handler/libc fixtures are distinct from actual native Linux capture/autowatch acceptance; the public record schema is unchanged.

The private macOS metadata start carries a closed final-symlink policy for `readlink`, `readlinkat`, `lstat`, and `fstatat(AT_SYMLINK_NOFOLLOW)`. The receiver resolves parent components for containment and retains the final entry's nofollow device/inode, including self, dangling, internal-target, and external-target links. Raw logical pathname bytes remain intact; a trailing separator, `.` or `..` retains native directory lookup semantics. Ordinary `stat` and `open` still follow the target. A selected project link entry remains an autowatch dependency without reading its external target; reproduction collection still rejects selected escaping links. The public version-one record format is unchanged.
macOS synchronous hooks remain active during application TLS destruction. If Rust has already destroyed the cached thread transport, a late operation opens a fresh hello-admitted connection and retains that exact socket from start through completion. Reentrancy guards and PID-scoped correlation counters use destructor-free cells, and pathname mutation tokens belong to the native call's stack. Late connections retain process-image binding, before-operation acknowledgment, receiver resource limits and native errno; failed transport marks the execution incomplete while forwarding the native call. The fallback does not reconnect an already-started pair or skip a late file close in a complete record. pnport-mode exclusion is unchanged.
Ordinary C `close` and `close$NOCANCEL` have independent interpose entries on macOS x64 and arm64. The preload binds ordinary `close` explicitly rather than using Rust libc's x64 declaration, which redirects to `close$NOCANCEL`. The standalone TLS teardown regression covers both Rust-owned file drops and explicit native closes, including errno preservation and subsequent pathname mutation.

macOS executable evidence includes a supervised, prelaunch root pair charged against the total event limit before child launch, paired `posix_spawn` results, and `execve`-family replacement starts completed by either a native failure or the successor image's hello after successful replacement. Each process image generates a fresh 128-bit hello nonce shared by its thread connections; the receiver binds later frames to that connection's hello and completes replacement only when a same-PID hello has a different nonce. A late hello from an old-image thread leaves replacement pending. A replacement without successor injection remains incomplete. The root pair is admitted before launch for delay and breakpoint controls, then receives the spawned PID before record assembly. Project-local root executables enter reproduction input selection.

The Windows injected DLL has an opt-in paired loopback channel for NT open, synchronous read/write, close, metadata, directory, pathname mutation, and executable hooks. The client sends a process hello, waits for pre-operation acknowledgment, and reports the returned NTSTATUS and actual synchronous I/O byte count. Descriptor operations carry the final path and file identity obtained from the live handle, so the receiver classifies exclusive-share and renamed handles without reopening their pathnames. The receiver validates framed UTF-16 paths, pairing, token, bounds, and result structure; it classifies paths before release and assembles records. Pathname mutation frames carry both source and destination paths with checked byte lengths. Descriptor mutation frames carry one handle-resolved path and the live handle identity, including end-of-file changes; either successful or failed native results remain paired. The private decoder selects the path encoding by its marker and rejects malformed identity lengths and malformed two-path payloads. It preserves native NT device names, treats nonfile device handles as external accesses, and maps mounted volume device names to DOS volume paths before project classification. Transport timeouts cannot reset a partially read frame. Rust TLS teardown must not panic through a native detour or discard a paired operation; a guarded late-thread transport remains available until process exit. The paired interval ends at `ExitProcess` entry, before DLL process-detach callbacks can invoke file hooks after socket shutdown. The supervisor admits and records a resolved root executable pair before launch, then assigns the suspended root to a kill-on-close Windows job before resuming it and checks owned-process cleanup and side-channel completeness. Windows ARM64 Detours supports the observed larger PE section count. Native Windows x64 and ARM64 workflow tests remain a release gate. The GNU cross-check omits an MSVC-specific Detours export directive solely to type-check this private code; the supported release targets remain Windows MSVC x64 and arm64.

The macOS and Windows receivers charge a conservative encoded-size bound for every hello, start, and completion before retaining it, including classified logical, resolved, and project-relative paths and both paths of a mutation. Final record serialization still checks the exact encoded byte limit.

The macOS receiver preserves its first typed failure through connection joins and supervision: event and byte exhaustion report `event_limit` and `byte_limit`, while malformed or failed IPC reports `trace_loss`. Incomplete record summaries retain these existing classifications. A genuine cleanup failure remains primary and incomplete; redacted supervisor diagnostics retain the original cause using stable classifications only. Hello/root reservations, conservative pre-retention charging, final encoding bounds and cleanup deadlines remain enforced.

The source command module implements six execution commands on each native backend and platform-neutral `compare`. The macOS and Windows backends apply delay in the pre-operation acknowledgment path and report the same paired-run timing fields as Linux. The macOS reproduction snapshot validates opened file descriptors with `F_GETPATH` and descriptor metadata and publishes bundles with atomic `RENAME_EXCL`. The Windows reproduction path checks the opened handle's final path before copying selected files, captures expected stderr from a private pipe, stages only observed inputs, and publishes a new bundle through a nonreplacing same-volume move. The macOS breakpoint handler admits only a real control TTY and uses the side-channel acknowledgment to stop a rejected native call before it executes. The Windows breakpoint handler opens the real console input and output independent of redirected child streams, retains processed input so Ctrl+C reaches its cancellation handler, restores the prior console mode, and uses the side-channel quit acknowledgment to stop the native call. The Windows watch path recognizes native NT missing-path statuses. Source integration tests exercise the handlers; no release or published-package availability is implied.
After successful Unix report publication, `record`, `assetcov`, and `fbreak` reproduce a child's terminating signal through the process default handler so parent processes observe signal termination rather than a numeric exit. `fbreak` restores its control terminal before reproducing the signal.

## Record and analysis

Records are explicit, versioned NDJSON outputs, bounded by event count and encoded size. The header declares a UUID-v7 execution ID, backend, root, and exact observation coverage. Each start/completion pair carries a correlation ID, process/thread and ancestry, lossless native path representation, operation kind, receipt sequence, monotonic time, result, byte count when applicable, and requested/observed injected delay. Successful opens that may create or truncate a file carry an optional `open_mutates` start flag; older records default it to false. The terminal summary states completeness, child outcome, counts, and stable failure classification. Receipt sequence is not a global execution order across threads. A parser rejects unknown versions, malformed or unpaired events, exceeded limits, missing summaries, and incomplete executions before analysis.

The private Linux `record` handler publishes a two-line, validly framed incomplete header and terminal failure summary when capture fails and the output limit permits it. The parser rejects that artifact for analysis. If the configured byte limit cannot fit even those two lines, the handler reports failure without emitting a truncated record.

Paths are encoded as native Unix bytes or Windows UTF-16 code units; a display string must never replace the native identity. Project paths retain both logical and resolved identities so internal aliases can be counted once. External accesses remain distinguishable. Records never contain file contents, full argv, or environment values. Product artifacts intentionally contain access paths; `tracing` diagnostics must not.
Windows high-resolution file IDs use exactly 32 lowercase hexadecimal digits in records. JSON numeric encoding cannot round-trip the full 128-bit identity through the strict parser, so numeric Windows file IDs are rejected.

A failed native call may supply a null, invalid, or overlong pathname pointer, or an invalid relative directory descriptor. The Linux decoder records the paired native result with an explicit `path_unavailable` marker instead of inventing a path or turning that ordinary failed call into an incomplete trace. Path-based workflows cannot select such an operation as a project input.
An ordinary empty Linux pathname is unavailable rather than a path to the current directory or directory descriptor. For native `AT_EMPTY_PATH` calls that operate on a descriptor, including `statx` and `newfstatat`, the decoder uses that descriptor's path and file identity, or the current directory when the argument is `AT_FDCWD`.
Linux final-entry nofollow classification probes the entry lookup for search-permission denial before appending the leaf to its resolved parent; resolving the parent alone does not prove that its children can be searched. This probe never follows the final link. When a path cannot be resolved because an ancestor denies search permission, all three native backends retain the paired operation with `path_unavailable` instead of aborting the trace or guessing whether a symlink escapes the project. Other classified paths in a multi-path mutation remain available; the unresolved path is not eligible for selection.

`compare` uses the default event and byte parse limits unless its positive `--max-events` and `--max-bytes` overrides are supplied. The overrides apply independently to both input records so a valid record created with raised capture limits remains analyzable without removing parser bounds.
All result-producing commands reject `--force` with stdout (`--output -`) at entry with invalid-input status 2, before launching a child or publishing a reproduction bundle. Explicit report destinations are preflighted for existence, type, and parent writability before execution, then rechecked at publication to catch races. Only a single-link regular file output may be replaced; symbolic-link and multiply-linked destinations are rejected.

The pre-execution asset denominator walks the selected root, follows only internal symlinks, and deduplicates file identities, including hard links, without holding one open descriptor per file. A read completion must carry the opened file's identity and actual byte count; the analyzer cannot recover it reliably from a pathname after the execution. A missing identity cannot cover a selected file.

The reproduction path copies eligible selected regular files before execution into a private directory, retaining only internal link mappings and their targets. Mutating opens are output events and do not select reproduction inputs. A successful observed directory query selects eligible snapshot files and internal directory entries beneath that directory, including empty directories and nested directory names; staging and the manifest preserve those directories for enumeration-only dependencies. Successful metadata and non-mutating open operations also select an eligible snapshot directory itself, without selecting its unobserved contents. A read of a selected file created after the snapshot is accepted only when a successful write completion to that path precedes the read in receipt sequence. It applies the fixed credential-like path denylist, including hard-link aliases of blocked regular files, file/byte limits, source-descriptor containment checks, and hashes required inputs again before staging an observed subset. When multiple observed paths name one file identity, staging preserves their hard-link relationship in both the candidate and published bundle, and the manifest lists each hard-link alias and its target. The private handler installs command-scoped cancellation before snapshotting and polls it through bounded copying, source rechecks, staging, result walks, and bundle publication; temporary directories are dropped on cancellation. It checks the original failure, reruns a candidate in a separate working directory, and executes a selected project-local root executable from its staged candidate path while retaining the original Unix argv zero and arguments. It rejects original-tree and uncollected content reads, checks result limits, and atomically publishes a clean bundle with a file/hash manifest, link map, external accesses, and rerun guidance. Native Linux, macOS, and Windows tests cover verified, blocked, original-tree, and metadata outcomes. Publication of the command family remains a separate release action.
The original cwd must resolve within the selected root. Candidate verification recreates the same root-relative cwd, and the published bundle records it in `manifest.json` for manual reruns; an outside-root cwd is rejected before execution.
Candidate-generated files count as available to later reads only when a successful write completion precedes the read start in the record's global receipt sequence; process-local monotonic clocks cannot establish cross-process order.

For a selected observed path, reproduction stages that logical alias when its current file identity matches the captured identity. The captured identity must match the pre-execution snapshot entry, including through an internal alias, and the live identity must still match that entry during verification; a replacement with identical bytes fails as unstable input. Identity-only alias selection is a fallback for an otherwise unselected or unavailable logical path, so an unrelated selected hard link cannot replace the path actually used by the command.
Selected nofollow metadata link observations validate the captured inode against the original link entry only when the recorded resolved path denotes that entry. The snapshot retains the entry identity independently of its target, and required-source verification rejects entry replacement even when the target spelling and bytes are unchanged. Following metadata, open/content and executable observations still require the original target identity; records without captured identity retain their existing compatibility. Original target/hash, ancestor-link, containment and credential checks remain mandatory, and escaping link targets remain excluded from reproduction. No public record schema changes are needed.

Internal file symlinks retain the exact target pathname when the link consumes the complete selected path; snapshot lookup, copying, verification and staging append only nonempty suffixes. Internal directory links continue to resolve their remaining path components, and selected aliases retain target identity/hash validation, blocked-target rejection and external containment.

Standalone snapshot directories use the same include-union-minus-exclude eligibility as files. A successful directory query validates a present captured identity against the selected snapshot directory before expanding its eligible descendants, including selected internal directory aliases. A mismatched identity fails as unstable input even if the original directory was restored before the live recheck. Records without directory identity, root queries and expansion from unselected ancestors retain their existing compatibility. Expansion includes only eligible snapshot entries below the queried path. Selected observed empty directories are staged and listed in the manifest; excluded or unrelated standalone directories are omitted. Required structural parents and internal directory-alias targets are recreated and retain identity validation without becoming independently eligible inputs or consuming the selected-entry budget. Selected files, selected directories and required links remain bounded by the snapshot entry limit, and result file/link limits remain unchanged. Walking unselected directories continues to check cancellation and blocked file identities.

## Workflow semantics

- `autowatch` runs once immediately, then watches observed project inputs, including successful executable accesses, directory queries, and absent paths, including failed executable lookups. It runs serially, debounces by 200 ms by default, checks cancellation throughout a configured debounce wait, replaces dependencies after success, unions new dependencies after child failure, and rejects an empty or unsafe watch set. Confirmed self-writes alone cannot trigger a rerun.
  The macOS and Windows supervisors include failed root `PATH` candidates as bounded synthetic executable attempts before the selected root image so a newly available earlier candidate invalidates the watch set.
  Internal logical aliases and their resolved project targets are both watched so a symlink replacement invalidates the recorded input.
  Selected inputs also retain each root-contained symlink traversed in their ancestor components and link-target chains, including before a missing leaf. Extraction walks only those components with at most 40 link expansions; each link keeps its own nonrecursive parent anchor and exact-entry relevance, so unrelated siblings do not become dependencies. Successful runs replace these links and targets; failed runs union them with prior inputs. Child writes retain logical and resolved mutation paths even when an ancestor does not match the input selector, preserving explicit self-write ambiguity failures for overlapping notifications.
  Nonrecursive anchors also observe the lexical parent of each symlinked suffix component, so replacing a directory link itself invalidates descendants rather than only watching the resolved target. Equivalent root-prefix spellings are accepted only when an ancestor resolves to the captured canonical root; extraction retains every component below the outermost verified prefix, including internal aliases, without changing raw record paths. Unverifiable prefixes cannot add logical watch dependencies, and external accesses remain excluded.
  Dependency installation emits a debug-only handoff acknowledgment after the replacement anchors are installed and the discovery watcher is released. Native watch fixtures wait for this acknowledgment separately from child output completion; a parent-owned teardown gate proves the distinction without a fixed readiness sleep. On macOS, a test-owned observer starts before setup and waits for every original setup symlink creation notification before launching autowatch; this separates pending setup history from supervised discovery without dropping its events. A gated link replacement during capture must still trigger exactly one subsequent run. macOS CLI rerun fixtures use static input-content tokens over stdout rather than project-local control files, await completed dependency installation before parent writes, publish initial input creation before launch, and retain an owned child guard for cancellation and failure cleanup. Debug invalidation diagnostics record watcher generations, event kind, path depth and self-write classification without path text or native content. Default output and watch filtering are unchanged.
  A successful creating or truncating open is classified as an output even when no write syscall follows it; output-only opens do not become input dependencies.

The current Linux watch path installs a temporary recursive discovery watch during each child execution and replaces an idle watch with nonrecursive anchors of observed dependencies. It has real-process tests for changed and newly created inputs. A path with both an observed child write and an overlapping native change event is classified as ambiguous and fails instead of claiming that the child alone caused it; causal self-write suppression remains to be completed.
Windows watch relevance and self-write checks compare path components with Windows ordinal case-insensitive semantics, so a created file can satisfy a differently cased missing lookup.
- `assetcov` uses one human formatter on all platforms, with the count/percentage line and deterministic covered and uncovered path lists under separate headings. Paths use the existing native display escaping. Quiet suppresses stdout while explicit report files retain complete reports; JSON, thresholds and child-status priority remain unchanged. It fixes the selected existing-file denominator before execution. Only a successful positive-byte read, or a successful EOF read with a known nonzero requested length on an initially empty file, covers a file. Zero-length requests and older records without a request length cannot claim EOF coverage. It deduplicates resolved aliases and preserves child failure separately from a threshold failure.
- `compare` accepts only complete compatible records, compares project-relative paths across roots, separates external accesses, and gates only added/removed files and changed operation kinds when requested. Counts and timing remain informational.
  Quiet mode suppresses stdout reports, while an explicit file destination still receives the report. Quiet compare and coverage gates emit a static redacted stderr classification when the gate fails.
- `latencylab` alternates equally traced baseline and delayed runs, three pairs by default. Delay occurs before selected operations on their calling threads and remains interruptible by cancellation, timeout, or receiver shutdown. It reports requested delay, observed injection, operation time, and execution time separately, stopping at the first failed execution.
- `min-repro` snapshots selected eligible inputs before the original run, collects observed dependencies, verifies the expected nonzero exit and stderr substring in a separate candidate directory, proves no original-tree or uncollected project read, and only then publishes a new bundle. Child stdout is forwarded to stderr so it cannot corrupt the report stream. It blocks credential-like paths listed in issue #971 and does not promise an OS sandbox or cross-machine portability.
- `fbreak` requires a control TTY and stops the matching calling thread before the operation. Controls `n`, `c`, and `q` respectively advance, continue, and terminate. Waiting for a key observes cancellation, execution timeout, and receiver shutdown, including before the root executable launches. Loss of the control channel releases or terminates all waiting callers through owned-process cleanup.
  The macOS handler owns SIGHUP only for this command, beginning before control-terminal setup and root launch. Terminal hangup records `control_channel_loss` and cancels the supervisor even after `c` disables further breaks. Queued admissions observe cancellation before continuing. If root exit wins the supervisor's wait poll during cancellation, the supervisor still confirms owned cleanup before inspecting a normal-completion trace and does not repoll the completed wait future. After terminal restoration is attempted and owned cleanup is confirmed, control loss returns 1; an unconfirmed cleanup retains `cleanup_failure` as the primary diagnostic. SIGINT 130, SIGTERM 143, `q` 130 and timeout 124 remain distinct.

## Limits and publication

The Windows supervisor reserves synthetic executable events and requires capacity for at least one complete native start/completion pair before launching a child.

The macOS and Windows supervisors reserve a conservative byte budget for the record header, summary, failed executable lookups, and root pair before launching a child; injected receivers receive only the remaining capacity.

Defaults are 1,000,000 events, 256 MiB trace, and 1 GiB/100,000 files for both reproduction snapshot and result. All overrides are positive. macOS hello frames consume byte and connection capacity but do not count as start/completion events; receipt sequence still reflects every frame. There is no default execution timeout. Cleanup requests graceful termination, waits five seconds by default, then forces termination and verifies cleanup within five additional seconds. Explicit file outputs use fspy-owned native atomic publication and `--force` rules without depending on another clibox companion crate; replacement preserves the existing file's ownership, mode or access attributes, and access ACL, and fails before replacement if preservation fails. A failed publication preserves the prior destination. Temporary private state is removed after handled failures and cancellation. No automatic history, artifact retention, or release publication is added.

Linux and macOS execution report handlers retain signal ownership through encoding and publication. A handled SIGINT or SIGTERM before the atomic report commit cancels publication, removes the temporary file, and returns the corresponding 130 or 143 status. Windows report handlers likewise retain their console-control registration through publication and return 130 on cancellation.

## Validation

Native behavior tests must exercise all seven commands and the eight supported targets, including Alpine consumers and pnport regressions where interception changes. Run root `cargo test`, formatting and applicable lint checks, `pnpm --filter @delino/clibox test`, `pnpm --filter @delino/clibox test:package`, and public-docs `pnpm test` when that frontend changes. Package and CI inventories must include the companion crate and affected native sources. Do not count parser, fixture, or macOS-only tests as validation for other native targets.

The macOS owned-group timeout fixture leaves two seconds for injected process startup so its deadline tests a running child and cleanup under loaded CI hosts. Cleanup retries transient process-inspection failures within the fixed graceful and force-confirmation windows, and still fails when liveness cannot be confirmed. A failed initial group signal, including a request racing final caller exit, also proceeds through identity-checked process cleanup and both absence checks within those same windows; persistent denial cannot produce a confirmed-cleanup result. The separate root-executable admission-delay fixture checks timeout before launch.

The control-PTY breakpoint fixture allows five seconds for injected test-runner startup before timing out a held read; its root-admission case retains a two-second deadline. A worker-ready gate can replace the held-read startup allowance. Native C threads and a `posix_spawn` descendant exercise six queued reads independently of Rust test-runner locks.

Selected root executable relocation uses the same verified logical-alias/identity mapping as required-input collection. Rerun the staged alias with the original Unix argv zero and literal arguments; external executables retain their existing handling. Required link/content verification remains mandatory before staging.

Final `min-repro` report encoding and publication retain the command cancellation state after verified bundle commit. Cancellation before report commit preserves the prior report and removes unpublished staging; it retains the committed bundle. Cancellation after report commit retains both outputs and returns the handled cancellation status. Quiet output still checks cancellation before success.
