# PR #1232: retain and retry exact native Hide

Addresses Codex thread `PRRT_kwDORRAKg86no65f`. A transient Hide failure previously erased frontend ownership while leaving the native child present. The effect now retains its own view UUID, serializes hides, blocks resize/reopening while closure is pending, and retries only that original closure at 250 ms intervals. Cleanup continues after unmount and late open completion, without clearing a newer effect's presentation identity. Failed closure uses a fixed UI message; no external content is logged. Native Hide is idempotent: absent or superseded original views receive success without closing their replacement. Trusted-document and saved-binding checks remain mandatory, and independent native close accounting still gates shutdown.

Both browser component files passed all 13 tests, including controlled failed-hide/pending-hide/reopen and post-unmount cleanup cases. Frontend typecheck passed. The pinned CEF host regression `repeated_hide_preserves_a_replacement_view` passed, proving repeated original cleanup cannot remove its replacement. These controlled checks do not establish OS window layering or real CEF close/shutdown acceptance. The browser contract and scoped frontend/native instructions retain the ownership and closure invariants.
