# CacheCow command foundation

## Scope

Own `crates/cachecow`: the Rust crate `cachecow` and its `ccow` binary, preset discovery, CoW preparation, cache lifecycle, locking, process ownership, shims, and shell integration. The [complete requirements](crates-cachecow-requirements.md) govern every behavior and acceptance gate.

## Runtime and Language

Rust, ported from the original Go implementation by owner decision. Use the workspace toolchain pinned in `rust-toolchain`. The crate is a workspace member with `publish = false`; release builds embed SQLite and set `CCOW_VERSION`, `CCOW_BUILD_REVISION` and `CCOW_BUILD_DIRTY`, which the binary exposes in its `ccow-build-info:` identity marker for distribution verification. Native Cargo operation must not depend on Node.js; only the Rspack/Rsbuild discovery hook below requires Node.js 24+. The binary is distributed as native release archives and native Homebrew/APT/DNF packages (see the [distribution contract](packages-ccow-distribution-contract.md)); there is no npm launcher. Supported platforms and tool versions are exactly those in the complete requirements.

## Users and Operators

Developers, coding agents, and CI jobs working in Git worktrees; maintainers diagnosing local failures.

## Interfaces and Contracts

Public commands are `run`, `status`, `prepare`, `clean`, `doctor`, `config get/set/unset`, `shim install/uninstall/list/doctor`, and `shell init/setup/remove`. Preserve all options, prompts, output, exit-code, and pass-through rules in the complete requirements.

Implementation boundaries:

- Preset discovery consumes the current working directory, requested command/arguments, tool selection, and optional preset. It identifies verified cache paths and compatibility information without changing tool freshness decisions. Unknown locations or compatibility prohibit reuse.
- Cache preparation consumes the preset result, source selection, and explicit copy/replacement authorization. It retains existing caches by default and reports the actual copy mode. Failed preparation preserves the old cache and prevents build launch.
- Managed execution coordinates canonical cache paths and source reads, owns the process tree, and returns the child exit status. Same-session/same-cache nesting reuses protection; different-cache nesting remains managed without deadlocks. The managed command keeps the caller's resource limits (soft and hard), `umask` and scheduling priority on every platform; on macOS the launchd job that hosts the supervisor carries them and runs with `ProcessType` `Interactive`.
- Shim dispatch resolves the real tool for each invocation, classifies managed operations versus pass-through, and enters that same lifecycle. Cargo shims silently pass through when the default manifest search finds no `Cargo.toml` in the working directory or any ancestor; preserve native diagnostics and exit status. Configurable short aliases, external `clippy`, explicit manifest/directory selection, unstable modes, existing or unreadable manifest entries, and general discovery failures do not qualify for this bypass. Managed `cargo clean` locks without preparation; `ccow clean` rejects in-use caches.
- Management output supports a versioned JSON envelope with success and result or error code, cause, and remediation. Shell initialization emits shell code separately from diagnostics.

### Frontend discovery interface

Rspack and Rsbuild projects provide `.ccow/discover.cjs` in the exact execution directory. The CommonJS module exports an async function receiving `{ preset, argv, cwd, env }`. It resolves the same configuration as the requested build and returns `{ schema: 1, preset, caches: [{ type: "persistent", path: absolutePath }], outputs: [absoluteOutputPath], inputs: [absoluteConfigPath], settings: resolvedSettings }`. It lists every persistent cache and final output. `inputs` lists all configuration files, imported dependencies, and absent configuration candidates whose creation can change cache selection. The list must be nonempty. Discovery obtains this list, captures file digests, repeats the resolver, and rejects changed results or files. The supervisor rechecks these digests after acquiring the complete lease set. Store only paths and digests, not file contents. The hook must not build, write artifacts, or print to stdout. Unknown options or unresolved dynamic configuration fail discovery. Project hooks are trusted code under the same boundary as the build.

Discovery verifies tool versions from the package that owns the selected executable, including its resolved Rspack dependency. The executable must be the package manifest's bin entry or a symlink to it. Unverifiable shell/batch wrappers fail discovery; an unrelated installation in the execution directory cannot certify them. Discovery verifies installed tool versions and excludes dependency trees, package download stores, and final outputs. Compatibility incorporates resolved settings, tool/compiler versions, platform, architecture, and relevant invocation environment. Discovery does not rewrite tool fingerprints or timestamps to manufacture cache hits.

### Cargo discovery

Stable Cargo 1.99.1+ within 1.x and nightly versions newer than that floor may enter managed discovery. Nightly remains outside the stable support guarantee. Preserve rustup directory, environment and explicit `+toolchain` selection. Require the same metadata fields and configuration checks on both channels, and retain the full rustc identity digest to prevent reuse across different nightly builds. Unstable command-line options remain rejected until their discovery semantics are verified.

Cargo metadata resolves the workspace and configured `target_directory` and `build_directory`. Missing directory fields, unresolved configuration includes, and unverifiable custom compiler wrappers prohibit reuse with actionable errors. On Unix, `RUSTC_WRAPPER` may select sccache 0.14.x by name or path. Discovery resolves and stamps that executable, verifies its version, and includes its content identity in compatibility. Execution pins the canonical binary path, so replacement or deletion of an intermediate wrapper symlink cannot break the managed command. Other wrapper variables, Cargo-configured wrappers, and Windows wrapper management remain unsupported. Distinct roots are managed together; coincident roots are processed once. Discovery queries the exact resolved command, including explicit executable paths, rather than substituting PATH Cargo. Source and destination must retain compatible build settings while Cargo remains responsible for source freshness. Before metadata discovery, capture file digests for Cargo configuration candidates (including absent files), ancestor manifests, explicit configuration and manifest arguments, and toolchain selectors. Recheck those inputs after discovery and under the complete lease set before launch; a change requires fresh discovery and must not run with stale cache claims. Store only paths and digests, not file contents. Discovery reads and replaces child environment entries by variable name the way the platform does: case-insensitively on Windows, so `Path` is the search path and `Rustc_Wrapper` is a compiler wrapper, and exactly elsewhere.

Managed sccache uses a Unix socket in the native supervisor's private session directory. Reject Cargo `[env]` entries that force `SCCACHE_SERVER_UDS`, including file and command-line configuration. Override `SCCACHE_SERVER_UDS` for that build, preserve the user's cache storage settings, and never connect to an existing shared sccache daemon. Nested managed Cargo calls use the same session endpoint. Exclude only that replaced transport address from sccache compatibility; keep all other relevant environment settings. The native owner terminates the private daemon and drains its compiler descendants before releasing cache leases, including cancellation and parent death. Shared sccache cache storage is not a CoW-managed Cargo cache.

### Coordination and recovery

Acquire the complete source and destination resource set before preparation. Inspect mutable source contents and provenance only after acquiring that complete set, so an active source build can finish before compatibility is checked. An unusable source after acquisition retains the existing interactive recovery choices. The initial coordinator uses exclusive leases for both sources and destinations; independent resource sets can proceed concurrently. Conflicts include aliases and ancestor/descendant paths. A nested request borrows existing protection only through authenticated session ownership. A nested extension that conflicts with another session fails with remediation instead of retaining a partial acquisition and waiting in a possible cycle. A nested extension that fails after admission, for example on an unusable source or a failed preparation, releases exactly the resources it newly acquired before it reports the failure, and keeps the resources borrowed from the parent. Its recovery choices therefore retry with full validation and preparation.

Lease registry transactions retry SQLite lock contention between `ccow` processes for up to one second, honoring cancellation, and then report the separate "lease registry is temporarily locked" error with retry guidance. Contention is never reported as an in-use cache or a nested conflict. `ccow clean` still refuses a real overlapping lease immediately; waiting commands keep waiting through both contention and real overlap.

Source discovery for a derived worktree runs in the source worktree context. Before discovery, environment entries and arguments are translated lexically: every occurrence of the current worktree root becomes the source worktree root, the exact inverse of the `${WORKTREE}` normalization in the settings digest. The interactive "build source first" choice runs the translated command and environment in the source, so its recorded provenance matches the following derived discovery. The tool executable for both is resolved through the `PATH` and `PATHEXT` of that translated environment, so a worktree-local tool directory in the current worktree never supplies the tool that runs in the source; a translated directory missing from the source leaves the tool unresolved and the source unavailable. The derived worktree's own discovery and run keep using the ambient `PATH`. Only these two verified roots are translated; every other difference in tool versions, platform, architecture, environment or settings keeps the source incompatible.

The compatibility digest hashes the child environment, except that it omits the CacheCow shim directory from `PATH` entries. Tool lookup already excludes CacheCow shims, so activating the shims, or running through an activated shim instead of `ccow run`, neither selects a different tool nor makes a source cache built the other way incompatible. Every other `PATH` entry and its order stay part of the digest.

Persist ownership intent before permitting child execution. The Linux supervisor reaps exited adopted orphans on every supervision tick while the root runs, by peeking with `waitid(WNOWAIT)` and reaping only non-root PIDs; the root's own waiter alone consumes its status, and the post-root `ECHILD` proof is unchanged. Release protection only after positive whole-process-tree completion evidence; a dead PID or released operating-system lock is insufficient. An unfinished ownership record remains protected until native recovery can prove completion. Process journals use version 2 and record native identity before any lease is acquired: Linux `boot_id`, macOS `kern.bootsessionuuid` (plus the coalition ID), and the Windows supervisor PID and creation time. A different boot proves completion on Linux and macOS; a zero-member coalition also proves it in the same macOS boot. On Windows, the unnamed, non-inheritable job uses `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`, so a recorded supervisor that no longer runs proves whole-job termination. In the same Linux boot, a dead supervisor keeps its leases because orphaned descendants can survive. Version-1 journals and journals without identity stay protected. A waiting acquisition attempts this positive recovery once per conflicting lease before it waits, and otherwise writes one notice with the cache path, lease and journal directory to the user's stderr; `ccow clean` attempts the same recovery once before it refuses. `ccow doctor` reports a typed reason for each kept lease and lists recovered leases. Unknown record versions are read-only. Supervisor recovery must never infer completion from elapsed time. A cancelled nested command requests termination from the authenticated outer native owner. This cancels the whole session with the same five-second graceful interval and retains outer protection until every owned descendant exits. Repository snapshots exclude contents of wholly ignored directories without tracked descendants; index, ignore-rule and directory-type changes still invalidate discovery. A snapshot goes stale when a path or Git metadata of any worktree changes, even a worktree that is unrelated to the cache, so a command that waited for a lease or raced a sibling worktree's cache creation repeats discovery and planning automatically, at most five times, before it reports the stale evidence. A change to the cache-selection configuration inputs is not repeated: it fails with exit code 125 and tells the user to repeat the command.

## Storage

Keep caches in tool-selected locations; keep settings, locks, and records in current-user-private local storage. Source precedence is invocation, saved per-worktree setting, then primary checkout. No remote storage, central cache, automatic publication, snapshots, or eviction. Unknown record versions must not be rewritten. Private records are validated and read through one non-creating open: a record removed or replaced by another session yields a complete record or a missing record, validation never creates a file, and an empty record left by an older version is reported with its path and a delete instruction.

## Security

Validate same-user/same-repository ownership and resolved paths before mutation. Cache validation checks all registered worktrees with at most eight native workers and waits for every worker before it returns. Each worker observes cancellation between source entries. Unix source inventory validation may reuse a resolved parent within one worktree pass, but must inspect every leaf and fully resolve links, directories and missing entries. Never retain parent resolution across validation passes; preserve all worktree and source-alias overlap checks. On Windows, the current user's SID identifies an owned path. `BUILTIN\Administrators` also identifies one only while the current token or its linked token is an Administrators member, because Windows assigns that owner to objects created by elevated administrators. Current-user-private storage still requires an access-control list that grants only the current user's SID. Protect sources, Git metadata, settings, and unrelated files. Do not follow external links during copies or escape the cache during deletion. Internal relative symbolic links are copied as links; absolute or escaping links, Windows junctions and special files are rejected as defined by the complete requirements. Ordinary hard links cannot provide CoW isolation. Build code is not sandboxed. Process ownership must survive abnormal parent termination without unlocked writers. On every platform, state that is not private to the current user is refused with an error that names the path, the failed check and the remedy, never with an unrelated process-ownership message.

## Logging

Use `tracing` or compatible structured logging. English notices go to stderr; child streams remain unchanged. Operating-system error causes are English too: on Windows a Win32 error code is described by the en-US system message in the `message (os error N)` shape, regardless of the user's UI language, and a code without an English message keeps the standard text. Support ANSI output with a documented opt-out. Doctor/verbose expose safe paths, versions, capability, lock state, and failure causes. Never persist source contents, environment values, or full command arguments. Shell setup and removal notices show only the CacheCow-owned block, never other profile content. Setup creates the selected configuration file but never its directory: when the directory is missing, planning fails before any confirmation with an error that names the directory and says to create it or to select another file with `--file`.

## Build and Test

Run `cargo test -p cachecow` under the repository workflow. Ubuntu Rust CI and the affected `cachecow-windows` job cover Linux and Windows; macOS coverage remains local or release work. The full requirements enumerate failure, concurrency, nesting, shell, filesystem, and native acceptance tests. Preserve the five-second graceful shutdown interval and descendant termination tests. Physical sharing/isolation and minimum-version native execution require actual supported hosts; mocks and cross-builds are insufficient. Do not add macOS runners to PR, main-push, or affected manual CI.

## Dependencies and Integrations

Git worktree discovery; Cargo target-dir/build-dir; Rspack/Rsbuild persistent caches; OS CoW and process ownership facilities; Bash, Zsh, PowerShell 7. Distribution consumes the native CLI; public guides describe supported user workflows.
