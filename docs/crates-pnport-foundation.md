## Scope
`crates/pnport` owns the private CLI and process supervision. `crates/pnport-core` owns the shared data-only PnP graph, virtual filesystem, executable admission and local cache. [The complete issue requirements](crates-pnport-requirements.md) are mandatory release gates.

`crates/fspy_preload_unix` owns the macOS pnport-mode cdylib. `crates/pnport-preload` remains the Linux/Windows companion. The source fork and licenses follow [the fspy vendor contract](crates-fspy-vendor-contract.md).

## Runtime and Language
Rust on the root nightly-2026-01-01 toolchain; explicit Cargo workspace membership, publish = false. Native interception must not upgrade the toolchain or alter protected dependencies. Retain upstream fspy attribution for adapted code.

## Users and Operators
Local developers and CI users running finite commands, servers, watchers and language servers; no hosted operators.

## Interfaces and Contracts

macOS recursion guards must construct their drop-bearing token only after successful entry. Reentrant libc calls must preserve the outer guard until its hook returns, including x64 `getcwd` implementations that call interposed metadata operations while runtime state is locked. Runtime state uses a stable normal pthread mutex with early atfork callbacks: preparation waits for runtime operations, parent and child release the copied lock, and the child clears inherited recursion state before user callbacks. Concurrent fork fixtures include non-exec child dependency reads and child callbacks while peer threads read ZIP-backed files.

macOS `fcntl` always forwards through the same command-aware native dispatcher, including hook reentry and TLS-not-ready admission rejection. Existing integer commands retain `c_int`, pointer commands retain their pointer ABI, and no-argument commands remain two-argument calls; unknown commands keep the existing integer fallback. Rejected calls return the native result and failure errno before runtime locking or descriptor-map access. Admitted successful `F_DUPFD` and `F_DUPFD_CLOEXEC` calls retain logical directory/peer provenance; failed duplications never add or replace mappings. The admitted guard lives through bookkeeping, and rejected calls never construct a token that could clear their outer owner.

macOS descendant `posix_spawnp` resolves the parent's PATH through the virtual filesystem, preserving its `/usr/bin:/bin` absent-PATH default and empty components. Child environment replacement does not change this search. The selected native image receives the same offline admission, injection environment and constructor acknowledgement as `posix_spawn`; opaque file actions and attributes pass unchanged. Relative executable/PATH candidates with opaque actions fail explicitly because child cwd changes cannot be inspected safely.

Linux cancels `io_uring_setup` before kernel execution and returns `ENOSYS`, allowing feature-probing runtimes to continue through mediated ordinary filesystem syscalls. It never creates a ring. `io_uring_enter` and `io_uring_register` remain unsupported and stop the owned tree; this preserves the boundary against preexisting rings and unmediated submissions. Validate this behavior with static native fixtures and official TypeScript under both default container filters and a container without an enclosing seccomp filter; a Docker filter's `EPERM` alone does not prove pnport's setup denial.
Commands are `run -- <command> [args...]`, `doctor [--json]`, and `cache path|list|prune|clean`. Global flags are `--project`, `--cache-dir`, `--log-level`, and `--color`. In `auto` mode, ANSI requires terminal stderr and absence of `NO_COLOR`; explicit `always` overrides `NO_COLOR`, `never` disables ANSI, and `doctor --json` is ANSI-free in every mode. Selecting a project preserves cwd. Automatic selection walks upward to the nearest .pnp.cjs. Explicit executable paths stay explicit; bare commands prefer the active workspace's direct dependency bins and reject ambiguous bins before inherited PATH lookup. Never build an implicit shell command.

Read inline and split Yarn 4 data without evaluating loader JavaScript. Validate before calling pnp hydration, including its required top-level locator. Preserve aliases, fallback policy, workspaces and peer-specific virtual identity. One owned process tree uses one graph snapshot; no independent-project merging.

descendant can inherit it with a changed

retain the caller specifier and the selected absolute loader rather than guess

including replacement environments that remove `NODE_OPTIONS`. Selection uses
the admitted graph, not a caller-replaced environment variable or descendant
cwd. Non-Node programs ignore these Node options. The supervisor, `doctor`, and
native graph hydration remain data-only; JavaScript executes only in the Node
workload. Shared option preparation also runs in pre-main native constructors;
keep it free of runtime tracing and retain structured activation/restoration
diagnostics in the supervisor and exec mediation callers. Constructor failures
retain their closed native stage/code records. Existing process ownership, graph invalidation, read-only dependency
views, and unsupported-operation boundaries remain required.

The package-owned probe verifies automatic API access from a ZIP-backed
package's require context, direct and descendant Node execution, preserved
options, and restoration after environment replacement. Caller preloads must
read `pnpapi` and ZIP-backed dependencies while retaining their relative order.
Explicit user preloads remain supported. Run probes only against prepared synthetic Yarn fixtures;
the offline probe does not install dependencies or load private application

platform acceptance.

### Native filesystem contracts

Hydration builds immutable indexes of hard-linked locators and package-location ancestors. Filesystem translation queries those indexes instead of scanning the complete raw registry for each source or unplugged-package access; reconstruct them when loading a serialized snapshot.

Classify each traversed `node_modules` component against the package-location ancestor index and its parent's exact registered package location before treating it as an issuer dependency namespace. Unplugged installation containers retain native lookup for unregistered scoped and unscoped siblings, including ordinary missing-path errors. Continue traversing the suffix so a later package-root `node_modules` remains virtual, read-only, and subject to physical-conflict checks; registered HARD package bytes remain read-only. Ordinary source and output descendants do not acquire synthetic dependency directories. Native resolvers ascend from those descendants to their containing package root; output trees may contain and remove their own native `node_modules` and dependency symlinks without mutating the referenced package.

Writable native SOFT project/workspace roots permit an empty physical `node_modules` or one containing only immediate hidden entries. Names beginning with `.` are tool-cache paths, except `.bin`, `.`/`..`, and names declared by the PnP graph or enabled fallback pool. Hidden files, directories and caller-owned symlinks retain native lookup and mutation semantics; following a link into managed packages, private cache or session backing remains read-only. HARD package roots keep their existing conflict and read-only rules. Files, symlinked namespace roots and every other physical entry remain `PNPORT_FILESYSTEM_CONFLICT`, including collisions observed after startup. Never modify or delete conflicting user content.

Reads alone do not create a project directory. `mkdir`/`mkdirat` may create the native cache container only through a literal namespace leaf reached without following any parent symlink; cache descendants support ordinary writes, rename and removal. The merged root, virtual packages and `.bin` remain protected from destructive or metadata mutations, including inherited/duplicated descriptors. Parent listings contain one `node_modules`; merged directory listings retain native cache ordering and append absent virtual dependency entries with the proper directory/link types. macOS stream cookies and Linux shared-open-file offsets support multiple appended entries, rewind and seek, with no archive extraction during eligibility queries. Linux descriptor-only virtual link opens and no-follow watches use protected private links; never publish package links into the native cache container. Cache changes become visible on new opens without stale materialized cache links. Doctor JSON v1 and CLI options are unchanged. This development behavior is not present in immutable published 0.1.0 or 0.1.0-next.1 bytes.

The macOS pnport preload mediates pathname and directory-relative mutation variants through the same classifier, including `renameat`, `renamex_np`, `renameatx_np`, `link`/`linkat`, `symlink`/`symlinkat`, `clonefile`/`clonefileat`/`fclonefileat`, and metadata variants. Extended-attribute writes and removals use the same pathname or live-descriptor admission, including duplicated read handles; `XATTR_NOFOLLOW` preserves caller-owned symlink operations. Hard links require writable source and destination paths; symlink target bytes pass unchanged. Clones read their source and require write authority only for the destination. Preserve final/all-component no-follow flags, invalid flags and native descriptor errors; ordinary native and writable tool-cache clones retain their original directory descriptors and path bytes, including native beneath-resolution constraints. Managed `CLONE_RESOLVE_BENEATH` operations return `ENOTSUP` before creation because absolute backing rewrites cannot preserve that constraint. Flag values and source/destination semantics follow the Apple SDK `sys/clonefile.h` and [XNU clone syscalls](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/vfs/vfs_syscalls.c). Final-link following follows each operation and its flags. Native cache operations and invalid-descriptor errors remain native; merged-root and dependency mutations are rejected before the native call.

Dependency content and virtual directories are read-only. Project source/output writes are native. Read, stat, enumeration, links, realpath, directory-relative handles, watches, mmap, native loading and execution are conformance requirements. Detect physical node_modules conflicts before access, including conflicts created during execution. Do not delete conflicting user content. Ordinary misses return normal filesystem errors.

Linux and the macOS pnport preload share native component lookup before PnP classification. Existing caller symlinks may lead into logical dependencies or physical managed cache storage; following reads retain virtual access and following mutations retain read-only rejection. Select final-link following from the operation and flags, preserving native `lstat`, `readlink`, no-follow open, Darwin `O_SYMLINK`, rename and unlink of caller-owned links. Retain the native 32-link Darwin and 40-link Linux traversal limits. Before erasing a parent component, validate the traversed directory against native or virtual backing: missing prefixes retain `ENOENT`, and file prefixes retain `ENOTDIR`, including when the final suffix is managed. Validate these earlier traversals before reporting a later cache conflict; reachable conflicts remain fail-closed. Linux returns the observed lookup error before rewriting; macOS forwards the failing backing prefix to libc without re-normalizing it. If no managed translation is needed, pass the original pathname bytes to libc or the kernel so symlink/parent traversal, missing-parent and trailing-separator errors remain native. This component lookup does not establish complete canonicalization or interception acceptance by itself.

Existing private runtime sessions use their canonical native spelling in the shared view, just as managed cache roots do. Synthetic dependency-directory backing under the session stays read-only through live descriptors and absolute backing paths, including Darwin's `/var` alias. Session permissions and ownership are validated by the runtime owner before constructing the view; data-only fixtures may reserve a not-yet-created session path.

The shared component walk retains terminal directory syntax from the caller and followed symlink targets. A managed regular file reached with `/` or `/.` must still return native `ENOTDIR`; a valid dependency directory keeps directory metadata rather than terminal alias-link metadata. Cache-root `mkdir`/`mkdirat` grants structural creation only when the raw final component is `node_modules`, optionally followed by separators. Existing-directory aliases through terminal `.` or `..`, including synthetic scopes, dependencies and descriptor-relative parents, and followed symlink aliases return `EEXIST` without creating the physical container. Validate the endpoint before admitting a managed operation, retain the directory requirement on rewritten backing, and leave unmanaged native pathname spelling intact.

Preserve an earlier missing-parent failure, admit ordinary link-free files and synthetic directories, and let native validation reject the conflicting `O_NOFOLLOW_ANY | O_NOFOLLOW` combination before managed write admission. The shared reject policy stops before following the forbidden link; resolving it to a link-free cache path cannot satisfy the caller's restriction.

Parent enumeration uses the same core path classification as direct dependency-directory lookup. Its eligibility query does not extract archives or create session views. Registered project, workspace and dependency package roots expose one `node_modules` entry with directory type, including empty dependency sets, nested dependency aliases and distinct peer contexts. Conflicts at virtual package-root directories encountered while enumerating remain fail-closed and preserve user files.

Direct legacy `getdirentries` and `__getdirentries64` append the same entries using their own record layouts. The 64-bit extended EOF flag remains clear until virtual entries are exhausted. Reserved overlay cookies reside in the kernel's shared open-file offset, so duplicate handles and forked readers share progress, while seek, close and descriptor reuse retain native lifetimes. Failed buffer/base copyout and insufficient record capacity do not advance the overlay position.

The macOS adapter owns its entry buffer and position per `DIR`, covering `opendir`, `fdopendir`, `readdir`, `readdir_r`, rewind/seek/tell and close. Native errors and unconsumed short-buffer or bad-pointer results remain retryable. These mechanisms do not establish untested platform or full tool compatibility acceptance.

Remembered descriptor provenance alone cannot cover inherited descriptors or the interval between a successful open and its mapping publication. Linux `recvmsg` supports ordinary IPC when the caller reserves an optional ancillary receive buffer, as libuv does. The supervisor supplies a private message header with zero control capacity, so the kernel cannot install `SCM_RIGHTS` descriptors outside the tracked FD map. On successful ordinary receives, it copies only the output name length, flags and control length to the original header, preserving caller pointers and untouched control bytes. Native payload/address writes, blocking, peek, interruption, restart and output-header `EFAULT` behavior remain available. It restores the original header argument before signal delivery or syscall restart. Actual ancillary data sets `MSG_CTRUNC` and fails the owned run with `PNPORT_UNSUPPORTED_OPERATION`, exit 125, before the receiving task resumes; discarded descriptors never become visible to peer threads or cleanup handlers. Linux's [Unix socket contract](https://man7.org/linux/man-pages/man7/unix.7.html) closes descriptors that do not fit the receive buffer. Batched `recvmmsg` with ancillary capacity remains unsupported and is denied before kernel execution. Receives without ancillary capacity retain native behavior. Keep dynamic/static native-parity regressions and actual descriptor-transfer rejection controls.

Regular-file descriptors return `ENOTDIR` and invalid descriptors return `EBADF`, whether tracked or duplicated outside interception. The macOS supervisor creates a separate same-image guardian before starting the command. The guardian first creates its own process group, starts an inert anchor in that group, and moves itself into a separate private group supplied by a short-lived bootstrap child. The bootstrap is reaped before launch acknowledgement. The command joins the original group; the live/unreaped guardian PID reserves its identifier even while the guardian runs outside it. The anchor keeps the group present before user launch. Whole-command-group SIGSTOP therefore cannot freeze the guardian's EOF recovery. Control descriptors are close-on-exec outside helper bootstrap and never supplied to user descendants. Direct or foreign-image invocation fails promptly with exit 125.

### Linux implementation and Docker execution

Linux x64/arm64 GNU execution now uses one seccomp `SECCOMP_RET_TRACE` filter. The owned launch helper stops before the supervisor attaches with `PTRACE_SEIZE`, which permits `PTRACE_LISTEN` to retain a child's requested job-control stop until `SIGCONT`. It remains in the invoking shell's foreground process group so terminal input and signals reach the child. The filter is inherited by dynamic and fully static descendants, including children that replace their environment. Pnport rewrites selected pathname syscall arguments into the existing PnP `View`, tracks cwd and file descriptors, handles virtual link metadata and same-process `/proc` descriptor aliases including tracked descriptor descendants, rejects writes into dependency/cache backing, and polls graph/active archive changes. Linux cache materialization checks for cancellation, runtime failure, and graph changes while waiting for another publisher's cache lock; a signal retains its 128-plus-signal exit status. Linux `fchmodat2` and null-path `utimensat` FD forms reject changes to tracked read-only dependencies while preserving ordinary output mutations; `close_range` closes tracked handles on success; `CLOSE_RANGE_UNSHARE` is rejected before execution because the group-wide FD map cannot represent a split table. Native directory handles use their current kernel identity for relative operations. Failed child `exec` retains command status 126/127, while unavailable mediation fails with a stable diagnostic and exit 125. The child trace event proves execution began; a missing event or helper failure cannot silently return the child's code. Cancellation and graph invalidation terminate the traced tree with a five-second grace and final kill/reap attempt, resuming parked tracees so handlers can run. The supervisor retains the root process until its final thread exits and drops group FD/cwd state after that group's final task. This is compatibility mediation, not a security sandbox; broader mutation, watch, and recovery conformance remains a release gate.

Cross-group `CLONE_FILES` and `unshare(CLONE_FILES)` fail before execution because a descriptor table shared or split independently of the thread group cannot be represented by the current ownership map. The recursion guard in the Linux preload was fixed separately: creating an optional guard eagerly cleared the thread-local flag on recursive entry and allowed private cache I/O to reacquire the runtime mutex. The guarded constructor/interpose path now keeps the flag until the outer call returns. The Linux CLI uses the syscall backend for both dynamic and static programs so static descendants of a dynamic parent retain the same interception. The pinned reference is `crates/fspy_seccomp_unotify/src/target.rs`, with the exact upstream revision and local fork changes recorded in `crates/fspy/PROVENANCE.md`. pnport adapts its no-new-privileges filter installation and selected filesystem syscall coverage in `crates/pnport/src/linux.rs`; pnport owns the filter, syscall argument rewriting, descriptor state, process lifecycle, PnP translation, and diagnostics. The kernel contract is [seccomp user notification](https://docs.kernel.org/5.19/userspace-api/seccomp_filter.html); pnport uses `SECCOMP_RET_TRACE` with `PTRACE_SEIZE` on owned stopped children rather than fspy's `USER_NOTIF` listener and IPC reply protocol.

Linux rejects `pidfd_getfd` before it can install a descriptor outside the tracked ownership map. This applies even when the source descriptor is not managed because the tracer cannot safely infer an arbitrary pidfd's source table.

On arm64, denying an unsupported syscall updates both the userspace `x8` register and the kernel's `NT_ARM_SYSTEM_CALL` active number before a parked tracee resumes. This prevents the original operation from running while a cleanup signal handler executes during the five-second grace period.

Same-group `/proc/.../root/<path>` aliases, including task aliases, resolve against the tracee root before ownership checks. Managed package and cache backing retain read-only rejection through those aliases; ordinary native aliases keep their kernel pathname spelling. Physical cache and session-view paths are treated as backing storage even when the cache is inside the project and contains `node_modules` directories.

Same-group `/proc/.../cwd` aliases of a virtual current directory resolve through the saved logical cwd, including paths below that directory. Writes still receive `EROFS`, readable opens retain descriptor ownership, and reading the cwd link reports the logical location. Descendant paths below tracked `/proc/.../fd/<fd>` and `/dev/fd/<fd>` aliases resolve through the PnP view again, including nested virtual dependencies. Successful `chdir` through a tracked descriptor directory alias updates the saved logical cwd for a virtual directory and clears it for a native directory; failed `chdir` leaves cwd state unchanged. The Linux supervisor parks same-group traced filesystem calls while `chdir` or `fchdir` is in flight, then publishes the logical cwd before resuming those calls; queued calls are cancelled during tree cleanup.
The named `/dev/stdin`, `/dev/stdout`, and `/dev/stderr` aliases and their descendant paths use the tracee's tracked descriptors 0, 1, and 2, including after duplication onto a standard stream. They retain managed read-only ownership for pathname mutations.
Linux serializes managed descriptor installation, descriptor replacement, and mediated descriptor mutations within a shared thread-group FD table through each syscall-exit stop. Native opens proceed without the FD barrier so a blocking FIFO open can be matched by another thread. A fixed dup destination reserves managed ownership at entry, and a second thread can inspect the kernel's current descriptor target before its ownership update arrives. Parked peer entries are canceled before cleanup resumes the owned tree. This closes the interval in which a mutating syscall could be admitted against a native FD and then act on a newly duplicated dependency FD.

Logical `getcwd` synthesis runs only after the kernel accepts the output buffer. Invalid pointers and other failed calls retain their original errno instead of becoming an interception failure.

The Linux tracer mediates `ioctl` on tracked read-only dependency descriptors. It permits the known read-only filesystem flag queries and `FIONREAD`; other requests receive `EROFS` before the kernel can change file or filesystem metadata. This includes `FS_IOC_SETFLAGS` and `FS_IOC_FSSETXATTR`, which can mutate through a read-open descriptor.

Cache materialization calls the lifecycle check throughout hashing, snapshotting, ZIP extraction, inventory verification, and read-only publication, including while the cache lock is held. Cancellation or graph invalidation during extraction discards the incomplete stage before a cache entry becomes visible. If publication fails after any stage directory becomes read-only, cleanup first restores directory write permission and explicitly removes the stage; a failed cleanup is reported instead of leaving an unreported `incomplete/entry-*` tree.

Parent-error precedence over later cache conflicts is tested directly against the shared resolver with real inline/split graph and filesystem fixtures. Native children verify missing, file and dangling-symlink prefix errors while their namespace remains valid. A runtime conflict child verifies fatal conflict detection separately: the supervisor may terminate it as soon as the namespace becomes invalid, so its output cannot prove that earlier lookup assertions ran.

Immediate cache-lease release conformance runs in a bounded independent test process while the overall Cargo runner stays parallel. Unix lease locks survive `fork` through inherited open file descriptions, including a concurrent native launch before close-on-exec completes. A pipe-synchronized native child proves `Active` protection after the parent drops its leases; only after that exact child exits and is reaped may corruption and removal be asserted. Passing a later retry does not establish the cause of an earlier unexplained failure; the fixture reports the observed closed state enum on assertion failure.

Every owned Linux `exec` stop validates the actual ELF image exposed by `/proc/<pid>/exe` before resuming its first user instruction. This covers descendants, descriptor-based execution, and script interpreters; a mixed class or architecture fails with the unsupported-operation diagnostic and exit 125.

The Linux tracer assigns each concurrently running task an 8 MiB scratch slot in its address space at its first seccomp stop, then replays the stopped syscall. Completed threads return their slots to the shared address-space pool, a forked private address space reuses its inherited mappings independently, and a `vfork` child borrows its suspended parent's slot until exit or exec. Repeated thread creation and process spawning therefore do not accumulate one mapping per completed task. On x64, replay restores the syscall number in `rax` as well as `orig_rax` before reentering the instruction; the seccomp stop's `rax` may hold `-ENOSYS`. The tracer writes rewritten paths and bounded `exec` vectors in the assigned slot instead of assuming unused stack bytes below an arbitrary tracee's stack pointer. A replacement image starts with a new address-space pool; an unavailable mapping fails with the unsupported-operation diagnostic and exit 125. The controlled launch probe may still use its own known stack.
The scratch reuse fixture warms the joined-thread pool, then requires two stable equal waves within five bounded attempts. This tests steady-state mapping reuse while allowing for scheduler-dependent ptrace exit-stop backlog across early waves; a persistent per-thread mapping leak still fails.

A newly auto-attached child can report its initial ptrace stop before its parent's clone event. The supervisor tracks and leaves that child stopped until the clone event registers its task, address-space, descriptor, and cwd state, then resumes it. If shutdown starts first, the unregistered child is killed and reaped without entering an unmediated syscall. This preserves syscall mediation and tree cleanup when a compiler launches many threads at once.

### Interpreter and signed native TypeScript evidence

Package entrypoints retain logical script paths while native execution uses physical backing. Linux also prepares translated descendant scripts at syscall entry, using the child environment and cwd for interpreter lookup and passing the logical script path to the interpreter. Argument and environment vectors are read up to Linux's six MiB aggregate exec ceiling rather than a fixed entry count. Bounded shebang chains support absolute interpreters and `/usr/bin/env` PATH declarations, including `-S` argument splitting. Resolving an env shebang does not execute or substitute the protected system utility. Protected interpreters remain unsupported. Universal Mach-O admission selects the current architecture, bounds all image reads, and verifies embedded signatures offline with Security.framework. Hardened images require both `com.apple.security.cs.allow-dyld-environment-variables` and `com.apple.security.cs.disable-library-validation`; ad hoc/non-hardened native fixtures remain supported. Never alter a compiler's signature or original bytes.

On Linux, a translated `/usr/bin/env` shebang with no `PATH` in the child's replacement environment uses glibc's `/bin:/usr/bin` default. An explicitly empty `PATH` remains empty. This default applies to descendant shebang interpreter selection, not pnport's bare-command lookup.

Linux `execveat` with `AT_EMPTY_PATH` keeps native descriptor execution for ELF files and prepares tracked virtual script descriptors through the same logical-path shebang path as pathname execution. The interpreter receives the virtual script path rather than a `/dev/fd` cache reference.

Missing explicit executables and missing absolute shebang interpreters report `PNPORT_COMMAND_NOT_FOUND` with exit 127; permission and format failures remain exit 126. Bare-command and env-interpreter PATH lookup skip non-executable candidates before selection. An executable that cannot accept injection still fails admission explicitly; that failure never selects a different executable from a later PATH directory.
