# Project: devhud

## Goal

DevHud is a coordinated desktop and mobile developer utility. V1 contains the desktop-only RealQA capture and GitHub issue workflow and the desktop/mobile Deck pull-request monitor; native widgets remain a future product contract. The deterministic bilingual frontend, complete guest/Logto identity and synchronized Settings boundary, direct-client GitHub.com issue/pull-request provider and credential-setup foundation, desktop RealQA capture/editor/encrypted drafts, pinned Tauri CEF desktop host, target-isolated Tauri iOS/Android system-webview hosts, versioned protocol, generated client, and Bootstrap/Settings/Upload/Account API services are implemented. GitHub issue submission, remaining populated product surfaces, the remaining API services, native widget targets, and the other planned domains remain documentation-first contracts.

Issue [#815](https://github.com/delinoio/oss/issues/815) is the current product contract. It supersedes closed historical DevHud issues #729, #755, and #757; those issues are historical context only and must not supply architecture or scope.

Official uploads return a header-bound 15-minute direct-R2 PUT and a separate 24-hour staging deadline, use 256-bit opaque identifiers, and publish exactly `<configured-public-base>/<opaque-id>.png`. One-use is an application reservation/key/finalization invariant; finalization conditionally validates the recorded generation and ETag after reading only a 33-byte PNG prefix, never an API upload body. The committed exact R2 CORS and 300-public-GET/IP/minute Cloudflare artifacts are operator-applied and production-startup validated. The bilingual removal marker is embedded; owner deletion, administrator hooks, and account purge replace origin bytes before purge/revalidation. The sweeper owns staging expiry and deferred cleanup.

## Domain Ownership Map

- `apps/devhud` — implemented localized React/TypeScript shell and target-isolated Rust/Tauri CEF desktop plus WKWebView/Android System WebView mobile host foundations; service-backed product workflows and native widgets planned.
- `apps/devhud-chrome-extension` — Chrome Manifest V3 extension (planned).
- `apps/devhud-admin` — administrator SPA embedded at `/admin` in the API artifact (planned).
- `servers/devhud-api` — implemented stateless Go Bootstrap/Settings/Upload/Account service and account/upload/retention sweeper; Diagnostics and Admin RPC registration planned, with upload administrator hooks implemented internally.
- `protos/devhud/v1` — implemented versioned Connect RPC schemas with committed Go bindings.
- `packages/devhud-api-client` — implemented generated TypeScript messages/services, Connect Query exports, and safe client helpers.
- `crates/devhud-native-messaging-host` — Rust Native Messaging broker packaged with desktop installers (planned canonical Rust workspace path).

The desktop host, protocol, client, and server foundation paths above are implemented. Only `apps/devhud/src-tauri` is currently a DevHud Cargo workspace member; remaining planned paths are not implemented runtimes, and the planned Rust host is not a workspace member until its skeleton and contract exist.

## Cross-Domain Invariants

- Upload finalization is submission-scoped: the first upload creates a server-owned UUID v7 submission and group, later groups carry that submission ID, and no submission may finalize more than 10 images across its groups. Signed checksums and staging versions are immutable finalization inputs; PNG dimensions are checked before decoding and must be at most 4096×4096 and 16,777,216 total pixels, and promotion is conditional on the recorded version/checksum.
- The iOS widget target is `io.delino.devhud.widget` and shares App Group `group.io.delino.devhud` and Keychain access group `$(AppIdentifierPrefix)io.delino.devhud.shared` with the main app. CEF `connect-src` permits only validated API, GitHub, and signed-upload origins.

- Fixed loopback development ports are frontend `46305`, administrator `46306`, and API `46307`; every launcher fails with an actionable conflict instead of remapping.
- Production API serving requires TLS termination at a configured trusted reverse proxy; `DEVHUD_TRUSTED_PROXY_CIDRS` is mandatory, only exactly one forwarded `https` protocol value from a trusted peer is accepted, and the plaintext origin listener supports HTTP/1 plus h2c for native gRPC forwarding.
- Browser/API CORS uses the exact origins `http://localhost:46305`, `http://127.0.0.1:46305`, `http://localhost:46306`, `http://127.0.0.1:46306`, and pinned Tauri `http://tauri.localhost`. Direct R2 staging uploads use the same origins with only `PUT`/`OPTIONS`, `Content-Type` and `x-amz-checksum-sha256` request headers, and `ETag` exposure. Connect preflight methods and headers are explicit, exposes `x-devhud-correlation-id`, and wildcard origins and headers are not allowed.
- Desktop targets are macOS 13+, Windows 10 22H2+, and Ubuntu 22.04 LTS on X11, each in x64 and arm64 builds. XWayland is best effort; native Wayland is excluded. Mobile targets are iOS 16+ on arm64 devices and arm64/x64 simulators, and Android 10/API 29+ on arm64/armv7 production ABIs and x64 emulators; i686 is excluded.
- Desktop uses `tauri-runtime-cef` from the authoritative `https://github.com/tauri-apps/tauri` repository, pinned exactly to Tauri commit `4af26a3f7f8b692d62cca549bbacd93f5ce90b41`; the official deep-link and single-instance plugins share that runtime through an exact-revision compatibility patch and deliver cold-start or forwarded callbacks into the validated pending-callback boundary. Mobile uses only Tauri/Wry's WKWebView or Android System WebView runtime. Android release artifacts grant `INTERNET` for System WebView API/authentication traffic and `POST_NOTIFICATIONS` for local Deck notifications. Target-specific Cargo features and immutable resolved production-default normal-dependency closure hashes prevent CEF, tray, autostart, desktop hooks, browser-extension integration, and native networking clients from entering mobile artifacts. The Tauri wrappers reject configuration and target overrides that could replace the pinned identity, security, or target definitions, and aggregate Android builds preserve each architecture's APK/AAB outside the generated Gradle output. The bundle identifier is `io.delino.devhud`; mobile registers only the `devhud` scheme and accepts only `devhud://auth/callback` plus its OAuth query, while widget-owned Deck deep links remain deferred until widget targets exist.
- Code, schemas, logs, and internal contracts are English. The implemented shell selects English or Korean from the system language, defaults to English, and mechanically preserves WCAG AA contrast for its small theme-specific eyebrow text and 3:1 non-text contrast for form-control boundaries; future end-user UI, validation, widgets, extension UI, and errors follow the same language contract with a synchronized override. React signals its mounted frontend through a native CEF-supported command; desktop startup enforces an independent five-second readiness watchdog and exits with a structured timeout diagnostic instead of leaving an unresponsive blank window. Packaged hosts observe renderer termination during normal launches on every desktop platform, while deliberate renderer-crash injection remains smoke-only. Native allowlisted browser links confirm opener dispatch in a background worker, fail after five seconds, and record timeout, worker, and opener failures as structured diagnostics; Linux uses GIO dispatch so confirmation does not follow the launched browser's lifetime. Desktop release hosts persist the same redacted structured diagnostics emitted to stderr in UTC-daily `devhud.YYYY-MM-DD.jsonl` files under `%LOCALAPPDATA%\io.delino.devhud\logs` on Windows, `~/Library/Logs/io.delino.devhud` on macOS, and `${XDG_STATE_HOME:-~/.local/state}/io.delino.devhud/logs` on Linux, keeping at most seven files and including failures that occur before the GUI starts, while hiding or restoring the main window from the tray, or while applying a tray-language update; operator `RUST_LOG` filters cannot suppress error-level DevHUD events.
- Stable first-party identifiers are enum-backed: mini-apps `realqa` and `deck`; capture actions `realqa.capture.display`, `realqa.capture.active-window`, `realqa.capture.all-displays`, `realqa.capture.selection`, and `realqa.capture.toolbar`. The implemented shell keeps a closed, capability-filtered registry for those actions plus navigation and local-preference actions; it does not expose a plugin ABI or SDK.
- The implemented shared shell has explicit Home, desktop RealQA capture/editor, mobile RealQA-unavailable, Deck, Settings, Account, Diagnostics, Loading, Empty, Offline, Blocked, and Error compositions. A runtime provider injects capability state so mobile never receives capture or issue-creation actions and official-service blocks never disable guest/local behavior. Continue locally takes precedence over an already-started Bootstrap failure and keeps guest settings writable until the user explicitly retries identity or starts Sign in; both first-run and Account Bootstrap-error recovery expose it. The desktop command palette preserves its exact right Command/Control+K focus contract. System/light/dark presentation and system/English/Korean language selection are authoritative synchronized settings for authenticated sessions and guest-snapshot settings otherwise; a local versioned startup mirror applies them before the initial render, with system theme and English fallback, and remains aligned with native-control color scheme. All state labels, alerts, status announcements, and recovery actions, including first-run and Account Bootstrap retry, are bilingual and keyboard/screen-reader accessible.
- The versioned mobile bridge exposes one closed request command and one typed event stream for lifecycle, allowlisted account-browser destinations, the pending authentication callback, non-enumerable secure settings, local notification consent/delivery, store-managed update status/opening, and future widget snapshot operations. Root API origins, including bracketed IPv6 loopback origins, open with or without a trailing slash; notification consent refreshes whenever the app becomes active, expected native consent-request and app-store-opening failures remain inline, bilingual, and recoverable, distinct Deck-change notification IDs remain distinct, and Deck cancellation removes all associated notifications. Widget operations report unsupported until native targets exist. It exposes no generic command, unrestricted URL, filesystem, or in-process networking primitive. Mobile updates remain App Store/Google Play managed and cannot download or install binaries in-app.
- Business flows use Connect RPC. The API never receives GitHub PATs or requests, brokers GitHub, polls Decks, receives GitHub webhooks, or stores PR results. The implemented v1 internal provider registry contains GitHub.com only, and all GitHub REST calls remain direct client-to-`api.github.com` operations.
- Service-owned identifiers use UUID v7. Logto subjects/issuers and GitHub identifiers remain external IDs.
- Secrets remain in platform secure storage: Logto tokens, GitHub PATs, R2 secrets, and local-agent credentials never synchronize, persist in server rows, or enter logs. Synchronized settings are versioned snapshots with expected-revision writes and typed conflicts; no last-write-wins merge. Desktop shortcuts are a fixed six-action structured enum map only: `right-primary`+`key-k` for the palette and bare `digit-1` through `digit-5` for contracted RealQA actions. `right-primary` is physical right Command on macOS and physical right Control on Windows/X11; raw keys, scan codes, and display strings never synchronize or enter diagnostics. Prototype-sensitive shortcut action names are invalid.
- Shortcut candidates reject unknown fields and are validated before native registration or snapshot persistence. Malformed, duplicate, OS-reserved (including Windows Alt+Tab), permission-denied, and registration-failed candidates retain the prior valid binding; a candidate remains staged until its synchronized persistence succeeds, so a revision conflict or failed rollback cannot activate an unsaved binding. The native matcher uses desktop global input hooks only after the always-mounted renderer boundary resolves authenticated settings from a valid snapshot or cache and hydrates the current bindings, restores and focuses the main window before emitting command-palette, selection, or toolbar actions, leaves direct display, active-window, and all-display actions UI-independent, emits only a configured closed action, discards unrelated input, and emits a held shortcut key only on its first press until release. Left Control and left Meta/Command remain independent pressed states, and an unconfigured primary-family modifier (right Control on macOS or right Meta on Windows/X11) invalidates the chord without being persisted, bridged, or diagnosed. This keeps shortcuts inactive through onboarding, suspends previously active guest matching while authenticated settings hydrate, and prevents guest or native defaults from overriding authenticated settings; blocked users hydrate their origin-scoped authenticated cache before a fallback map can apply, a failed apply makes the trigger unavailable, and a synchronized binding reserved on the current platform retains the native backend's last platform-valid map without rewriting that shared snapshot while the trigger displays the active map. The browser-only frontend development runtime has no global-hook bridge and displays desktop shortcuts as unavailable. Recoverable listener failures retry with capped backoff, clear transient pressed-modifier state before the replacement listener accepts events, and retain staged current bindings across recovery. macOS refreshes process Accessibility trust before registration and presents localized Accessibility/Input Monitoring guidance; Linux presents X11/XWayland, `DISPLAY`, and X authority guidance. Capture shortcut controls dispatch the same closed RealQA action IDs on supported desktop runtimes and remain unavailable on mobile or browser-only development runtimes. Native Wayland is unsupported.
- Synchronized Settings schema v3 combines stable UUID-v7 GitHub profile descriptors, explicit nullable profile references, bounded pending PAT-removal tombstones, and the six-action structured desktop-shortcut map. Schema v1 migrates with unselected profiles and empty tombstones; schema v2 retains profile data and both legacy versions migrate raw shortcut maps to structured defaults. Repository-less Decks require a null profile reference. Fine-grained and classic PAT profiles are never selected implicitly or used as fallbacks. PAT replacement is disabled whenever synchronized settings are read-only; profile removal atomically replaces the descriptor with a cleanup tombstone before deleting its local PAT, retains failed cleanup for retry, and clears the tombstone only after secure deletion succeeds. Every device additionally reconciles internal API-origin-scoped GitHub PAT associations against active synchronized profile IDs from the always-mounted identity/settings boundary as soon as a valid snapshot is available, independent of the active Home, Deck, Settings, or Account surface; it deletes a credential only after its last origin scope releases it and without frontend enumeration. Functional settings updates serialize silent cleanup with current guest edits, failed add rollback cleanup remains explicitly retryable, and newly written PATs remain until a Settings conflict adopts the server or reapplies the local snapshot. Repository validation accepts a root Contents `404` only for metadata-confirmed never-pushed repositories. Snapshots have matching envelope and canonical-body schema versions, expected-revision writes, and typed conflicts; no last-write-wins merge, and prototype-sensitive shortcut action names are invalid.
- Schema-v3 URL mappings are capped, typed repository/profile/pattern/priority/origin/update records; Chrome origins are concrete HTTP(S) origins with numeric ports no greater than 65535 when present, while historical schema-v1/v2 prefix mappings are validated then dropped because they cannot identify a repository/profile. Structured mappings are schema-v3 only; schema-v1/v2 snapshots migrate on read, and older schema-v2 clients explicitly treat a v3 snapshot as unsupported/read-only. Every canonical mapping path has at most 32 segments and 8 globstars, bounding overlap analysis across the 100-entry collection. New mapping drafts require an explicit configured profile, never select a PAT profile by position, and validate newly assigned or changed repository/profile pairs before synchronization. The API validates structured mapping fields and requires every structured mapping profile reference to exist. Their URL matching rejects authority backslashes, wildcard hosts whose IDNA canonicalization changes DNS-label structure, and every host the browser URL parser rejects; it canonicalizes literal paths and internationalized concrete DNS hosts (including terminal root labels) without aliasing distinct serialized escapes, supports concrete bracketed IPv6 hosts, and preserves dirty drafts and raw priority text through in-app surface navigation and null-to-current-account hydration for the current app session. A dirty draft retains its base revision through refreshes and submits against that revision, surfacing a standard conflict rather than silently overwriting remote changes; unchanged drafts never submit a replacement. Drafts reset only when the server snapshot is explicitly adopted, the submitted snapshot succeeds, the session becomes invalid, the user logs out, or the active account changes; Chrome permissions and pairing remain device-local.
- Desktop secure storage is explicitly macOS Keychain, Windows Credential Manager, or Linux Secret Service; Windows transparently commits versioned 1,024-byte UTF-8 byte chunks for logical values and the internal enumeration index so values retain the 64 KiB bridge bound without exceeding Credential Manager's physical blob limit, and failed index maintenance restores the prior logical credential. Mobile uses iOS non-synchronizing shared-access-group Keychain/App Group with legacy application-group migration and cleanup, plus Android Keystore-backed authenticated storage that migrates authenticated legacy ciphertext to setting-key AAD. Missing profile secrets and recoverable secure-storage failures remain distinct localized setup states with no plaintext or alternate-profile fallback. Synchronized URL mappings and BYO R2 base URLs reject credentials, queries, and fragments, authenticated cache writes remain best-effort, and online or offline startup without an authenticated session discards the origin-scoped settings cache before another user can reuse it. Secure-session read failures preserve retry for transient platform errors and offer an explicit device-local session reset for malformed or permanently unreadable values. Account-query failures retain typed correlation metadata with retry controls instead of exposing stale account actions.
- RealQA is desktop-only. Deck runs on desktop and mobile. Browser context is optional, permission-scoped, sanitized, bounded DOM context with typed absent/denied/revoked/disconnected/incognito/malformed/sanitized outcomes; Chrome strips credentials/query/fragments, excludes DOM selectors, and redacts every non-empty persisted path segment; local agents are desktop-only and explicit; widgets use local Deck credentials.
- Implemented desktop RealQA injects concrete macOS, Windows, and Ubuntu X11 adapters behind a testable capture interface. Display capture resolves the current pointer display, while pointer-independent capture does not require pointer lookup; all-display capture returns one image per signed-coordinate display; region composition validates each source frame, clips coordinates to the virtual desktop, uses checked fallible allocation, shares rounded output edges across every composed piece, and applies each display scale at the highest intersecting density. Native window enumeration skips targets that disappear during metadata reads. Every capture mode completes its cancellable delay before hiding a focused DevHUD window, active/window selection preserves native z-order, and a successful draft survives later focus-restoration failure. Topology is re-read with complete logical geometry after both successful and failed acquisition, retried once on hotplug, and otherwise fails recoverably. Selection and toolbar dialogs refresh topology before opening, use one keyboard-navigable radio group, remain inside the viewport with internal scrolling, restore focus to their opener on dismissal, and support Space region/window switching without overriding focused controls, Escape cancellation, 0/5/10-second timers, pointer inclusion, a floating preview, and macOS Option/window-shadow removal where supported. Overlapping shortcuts are ignored, capture completion preserves later draft navigation, and refresh failure cannot relabel an already persisted capture as failed. Protected or unavailable content is detected before pointer compositing and returns a typed error. Capture invokes still-image APIs only and never screen recording.
- The accessible English/Korean editor provides crop, arrow, rectangle, free drawing, text, blur, opaque redaction, layer/image ordering and removal, and revision-checked undo/redo. Its SVG arrow preview includes the same arrowhead geometry used by native flattening. Editor mutations, history, and flattening serialize against the latest returned revision; a successful in-flight editor response updates its listed draft after editor dismissal without reopening it, while queued work is discarded. A bundled unmodified OFL-licensed Noto Sans KR font makes English and Korean flattened annotations independent of optional system fonts. Persisted history retains at most 100 combined snapshots and adaptively discards the farthest snapshots under quota pressure so shrinking edits can still save. Layer geometry is validated against the source image and line rasterization is defensively clipped. Flattening renders a new metadata-minimized RGBA8 sRGB PNG with only structural/sRGB chunks, caps each issue draft at 10 active images, and downscales with a visible warning until every output is at most 50 MiB and 4096 pixels per side.
- Every capture is auto-saved before editing as an AES-256-GCM encrypted UUID-v7 draft. The non-exported master key is generated in platform secure storage; per-file random nonces and draft/role AAD cover sources, manifests, and flattened results. Atomic writes and startup transaction cleanup recover crashes only after the process claims primary-instance ownership. Each successful manifest save renews retention to 30 days from that save under a default 10 GiB exact encrypted-byte quota; no unexpired draft is evicted, and a full quota rejects the new save recoverably. Unreadable manifests are listed independently of capture availability as UUID-keyed delete-only drafts. Logout and account deletion cancel and join pending captures while secure credential cleanup remains exclusive, but only logout also purges RealQA drafts. Escape and destructive exits preserve drafts. Expiry, explicit deletion, confirmed future issue creation, and logout are the only deletion boundaries. Image bytes, keys, annotation text, bodies, and raw platform errors never enter logs or synchronized contracts.
- Official uploads use R2 signed direct uploads. Every `CreateUpload` selects an explicit `CreateUploadTarget`: `new_submission` carries no IDs and creates a server-owned UUID v7 submission and first group, `new_group` carries the owned submission ID and creates a group, and `existing_group` carries both owned IDs for another upload in that group. An absent request target or unset target oneof is invalid; `FinalizeUpload` uses both IDs returned by the reservation, and the 10-image limit applies atomically across all groups in one submission before a GitHub issue exists. User upload listing is owner-filtered and bounded by the shared pagination contract; user upload deletion requires ownership. Limits are 50 MiB/object, 1 GiB rolling-24-hour, 20 GiB stored, 120 signed URLs/rolling-hour, and 300 public GETs/IP/minute. `CreateUpload` atomically reserves the signed-URL issuance quota before issuing a URL; failed issuance rolls back that reservation, and `FinalizeUpload` validates the reservation without charging it again. `FinalizeUpload` revalidates authentication, block status, ownership, exact submission/staging-key/upload-group binding, size, the 32 raw-byte checksum, allowed image content, PNG signature, safe raster dimensions, and all other applicable upload quotas. It atomically rechecks or reserves the submission image-count, rolling-byte, and stored-byte quota state so concurrent finalizations cannot bypass limits; quota failures return `ResourceExhausted`. It rejects replay and removes invalid staging objects. The R2 checksum header is standard Base64 of the raw checksum bytes. Staging expires after 24 hours. API logs and crash reports retain 30 days; pseudonymized security/audit events retain at most 180 days. Account deletion purges user data, official-upload/tombstone metadata, and public cached bytes after a 30-day recovery period; upload metadata is deleted or irreversibly pseudonymized, except for the explicit audit-retention boundary, and purged identity tombstones remain effective across identity-HMAC rotation through a key-independent digest. Restore and final purge use a mutually exclusive atomic account-state transition, so a successful restore cannot follow irreversible purge work. The implemented idempotent `devhud-api-sweeper` performs post-recovery account purge and request/audit retention with multi-instance database coordination; staging expiry is added with UploadService. The worker discards a PostgreSQL session after any failed advisory unlock. Deletion and quarantine replace the origin object before purging or revalidating the public CDN URL, and are not effective while a cached original remains retrievable.
- The `devhud-api-sweeper` PostgreSQL pool requires at least two connections so repository work retains capacity while the coordinator holds its session-level advisory lock. Pool creation and schema readiness share a signal-aware 15-second startup deadline; every continuous or `--once` sweep iteration has a fixed 25-second execution deadline, preserves earlier cancellation, and drains repeated transaction-bounded retention batches until both tables return a partial batch or that deadline ends. Sessions are discarded after an indeterminate lock acquisition or failed unlock.
- Logto uses the exact native callback URI `devhud://auth/callback`, including callbacks queued before session bootstrap. Native callback inspection is non-destructive, and consumption waits until the identity session is ready so issuer-policy reloads cannot discard an authorization response; a confirmed API-origin change instead discards any queued callback before clearing the old identity transaction so it cannot replay against the new origin. Successful one-shot consumption clears the matching renderer callback before any later identity reset. A provider-owned in-flight guard admits only one native authorization attempt across first-run and Account Sign in controls. Invalid credentials, missing authentication, and terminal `invalid_grant` refresh failures become `Unauthenticated` and clear the client session, while transient Logto/JWKS and refresh-network failures preserve the session for retry. Bootstrap must identify `PROJECT_ID_DEVHUD` before discovery fields are consumed; protocol schema version controls compatibility, and API version remains deployment metadata. Configured issuer paths, development loopback HTTP issuers, and nonblank audience resource values pass through to Logto. Native policy retains the complete normalized issuer but derives only its origin for CSP; native browser dispatch requires the request issuer to equal the configured issuer and the destination to stay within its origin and path boundary. Bootstrap exposes deployment-provided public client IDs under the stable keys `desktop`, `ios`, `android`, and `admin`; the admin SPA also receives its exact deployment-configured redirect URI. Native clients use the `devhud` callback; the admin development redirect is `http://localhost:46306/auth/callback`, and the embedded redirect is the API origin's `/admin/auth/callback` path. The admin flow uses Authorization Code with PKCE and state/nonce validation.
- Chrome Native Messaging uses host name `io.delino.devhud.native_messaging`. The Web Store extension ID is a fixed 32-character release-configured value shared by the extension, host manifest, and installer; the host accepts only the exact origin `chrome-extension://<DEVHUD_CHROME_EXTENSION_ID>/`. The app owns the authenticated versioned `v1` IPC envelope and listener; the host uses `$XDG_RUNTIME_DIR/devhud.sock` on Linux, `~/Library/Application Support/io.delino.devhud/run/devhud.sock` on macOS, or the current-user Windows named pipe `\\.\pipe\io.delino.devhud\ipc`. The endpoint is user-scoped, pairing-secret authenticated, length-prefixed UTF-8 JSON with a shared 256 KiB body ceiling measured before framing/parsing, and rejects unsupported versions, failed authentication, oversized messages, and requests past the five-second deadline.
- Deck refresh intervals of 1/5/15/30 minutes apply only while a client is active and able to poll. Mobile widgets and local notifications use OS-controlled best-effort refresh scheduling, show stale state with the last successful refresh, and never imply freshness when suspended execution has delayed polling.
- Account recovery is exposed as authenticated, ownership-checked, idempotent `AccountService.RestoreAccount` during the 30-day window; restore clears only the deletion-state block and never clears an independent administrative block. Restore and final purge serialize on the account state, and after purge claims the account no restore can succeed. Calls after the window fail with `FailedPrecondition`.
- After deletion, clients immediately delete PAT/R2 secrets and account-local caches, preserve unsubmitted RealQA drafts through the recovery window, retry cleanup whenever pending deletion is observed, and retain the current Logto recovery session only until restore, logout, recovery expiry, or irreversible purge claim. Web Storage cleanup is best-effort and cannot block native secure credential purge. Purge-claimed accounts remove all local credentials and never expose Restore. Logout remains the complete local wipe boundary; operating-system permission grants remain OS-controlled while DevHud deletes its consent and permission records.
- Official desktop updates use the fixed HTTPS manifest endpoint `https://devhud.api.delino.io/updates/{channel}/{platform}/{architecture}.json`, served by the API deployment; v1 exposes the `stable` channel and maps `darwin-x86_64`, `darwin-aarch64`, `windows-x86_64`, `windows-aarch64`, `linux-x86_64`, and `linux-aarch64` artifacts explicitly. Installers pin the `devhud-release-root-v1` public-key fingerprint, key rotation requires signed successor metadata chained to that root, unknown or invalid signatures are rejected, versions cannot roll back without signed rollback authorization, and a failed update preserves the last known-good installation.
- Administration requires the `devhud-admin` Logto role, mandatory non-blank mutation reasons capped at 4 KiB of well-formed UTF-8 with credential and local-path patterns rejected before persistence, audit records that return only validated reasons, and no synchronized-settings-content display.
- The v1 wire contract uses canonical lowercase RFC 9562 UUID-v7 wrappers, response/error correlation metadata mirrored to `x-devhud-correlation-id`, RFC 8785 settings bytes capped at 1 MiB without a UTF-8 BOM, and typed bounded crash diagnostics (256-byte build/code identifiers, 4 KiB summary, 32 KiB stack). Upload creation explicitly distinguishes a new submission, a new group in an owned submission, and an existing owned group; finalization repeats immutable reservation, generation, checksum, size, and ETag bindings. Administrator upload responses use a metadata-only projection with no public or signed asset locator. Generated Go and TypeScript sources are committed but tool-owned and freshness-checked.
- CI must cover Go format/vet/unit/integration/migrations, Rust format/clippy/unit/native-host protocol tests, frontend lint/tests, schema compatibility and generated-client freshness, supported desktop/mobile/widget builds, extension packaging, installer/signature/updater-manifest checks, SBOM/provenance, and non-root OCI validation. DevHUD mobile jobs run for manual dispatch or relevant DevHUD/shared-path changes, and Android production rows inspect both APK and Google Play AAB output.
- CI and integration validation must cover owner-filtered user upload listing/deletion, bounded user-upload pagination, ListUsers prefix-query normalization and query-scoped tokens, submission-wide quota enforcement across multiple groups, concurrent CreateUpload signed-URL reservation and issuance failure rollback, finalization non-double-charging, raw checksum/Base64 conversion, upload-finalization rejection and staging cleanup, restore-versus-purge races at the recovery boundary, idempotent multi-instance sweeper execution, exact CORS origin rejection and Connect preflight/correlation-header behavior, origin replacement before CDN purge/revalidation for user deletion/quarantine/account purge, 256 KiB pre-framing IPC rejection and 128 KiB sanitized DOM acceptance, selector omission, stale widget presentation, recovery-window boundaries, and updater signature/key-rotation/rollback behavior.
- Release is one coordinated GA only after all desktop architectures, both mobile apps/widgets, extension, API/admin deployment, artifacts, updater, and documentation pass gates. Partial GA is prohibited.
- Required releases include signed macOS DMG, Windows MSI and NSIS, Linux AppImage and Debian package, signed updater manifests, App Store/Google Play packages, Chrome Web Store package plus reproducible ZIP, and separate non-root signed/provenanced OCI API and `devhud-api-sweeper` images. Deployment requires Logto, PostgreSQL, R2/public asset hosting, signing identities, store accounts, and release secrets.
- Product analytics, remote feature flags/kill switches, third-party plugin ABI/SDK, server-side GitHub brokerage, native Wayland, server-side Deck polling, webhooks, push infrastructure, and staged public beta are out of scope.

- Native GitHub PAT reads require the matching API-origin/profile association, and failed desktop or iOS PAT persistence restores any newly created association state before returning failure.
