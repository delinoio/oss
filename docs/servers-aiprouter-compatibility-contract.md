# AIPRouter compatibility contract

## Scope

Owns the pinned inference, provider/authentication, routing, continuation, pricing, and client compatibility boundary for `servers/aiprouter`. `cmds/aiprouter` implements the client configuration requirements; `packages/aiprouter` supplies shared mechanisms; `protos/aiprouter/v1` owns management schemas. The service, client, operations, and management contracts retain their respective authorization, lifecycle, deployment, and protocol ownership.

The compatibility reference is [lidge-jun/opencodex at 88aaa754566d119b6b8fc898f8fb47602387d82e](https://github.com/lidge-jun/opencodex/tree/88aaa754566d119b6b8fc898f8fb47602387d82e), package version `2.93.0`. All `src/`, `structure/`, `tests/`, `scripts/`, `gui/`, and `app/` references in source inventories below refer to that exact upstream tree, not AIPRouter paths or moving upstream branches.

Explicit AIPRouter requirements override the reference. Include means preserve observable behavior subject to these overrides. Replace means retain the capability through the specified AIPRouter architecture. Exclude means the product boundary removes the behavior. A requirement to define a narrower native or media boundary does not authorize silently dropping a provider, route, or client. Changes to the pinned revision or compatibility scope require corresponding contract changes.

## Runtime and Language

Implement server and CLI anew in Go in module `github.com/delinoio/oss`; do not bundle the upstream Bun/TypeScript server engine. PostgreSQL owns application state and encrypted temporary continuation state. React, TypeScript, Rsbuild, and generated Connect RPC clients serve the console. Inference wire protocols remain separate from Connect management RPC.

## Users and Operators

Each user owns separate provider credentials, account pools, routing, and connection state within each organization. Organization owners and administrators may inspect authorized usage metadata, not another member's credentials or content. Instance operators manage deployment, common prices, allowed destinations, limits, retention, and whole-instance aggregates without access to organization-internal secrets or content. CLI clients use organization-scoped user keys; inference keys do not grant management authority.

## Interfaces and Contracts

New persisted entities use UUID v7 unless an external protocol requires another identifier shape. Preserve externally required model, response, conversation, tool, and call IDs without treating those IDs alone as authorization.

#### Context relay uses an explicit per-user protocol capability

Upstream activates these ten endpoints only when its local Codex TOML has `features.context_management=true` or `.experimental_mode=true`. Each call requires bounded `context.session_id`, a proven principal/session/account owner, the same physical ChatGPT credential, allowlisted encrypted-tool protocol headers, 16 MiB input/output bounds and one 35-second whole-operation deadline. It does no retries and never chooses another account for an existing context. Missing/ambiguous ownership is 409. AIPRouter cannot read the server operator's Codex config to activate a user's feature. Activation is an explicit per-user protocol capability scoped to the organization, not a release flag. Preserve the wire opt-in and never read the service operator's Codex configuration for user authority. Native upstream notes/history may be durable at the external provider: AIPRouter must not duplicate that content permanently, and documentation must distinguish external provider storage from AIPRouter retention.

### Complete file-export target set

The fixed registry has **23 IDs**, including the three spread-generated entries. `src/integrations/registry.ts` owns path selection and write safety; `src/clients/config-export.ts` owns serialization and connection capability. Only **OpenCode, Hermes, OpenClaw and Kilo** currently export remote admission headers. The other **19** entries are `loopbackOnly: true`. This is a property of the pinned integration, not proof that the external client cannot ever support authenticated remote URLs. In particular, OMP, Prime and omo have header-capable schemas whose remote wiring upstream explicitly defers.

In the table, **L** means preserve the pinned loopback integration using AIPRouter's local HTTP relay; no remote key goes into its generated file. **R** means upstream supports remote credential references, so AIPRouter can supply the dedicated key from the OS store through a supported launch/environment boundary, or use a relay if the application cannot receive that environment reliably. A remote key written into settings still needs the service contract's separate explicit confirmation. The upstream header `x-opencodex-api-key` is an upstream compatibility fact, not a requirement to expose provider credentials to clients. CLI keys and provider credentials remain distinct.

`~` means the relevant client home, not always the OS home. A path function for Windows does not establish that the application is available on Windows. Path logic alone does not establish external-client platform support. Report actual application/platform acceptance separately.

### Explicit exclusions and native scope requirements

- Excluded: executing Claude CLI, CodeBuddy, Qoder or another installed program **as a provider backend**; WSS execution agents; remote command dispatch; workspace selection; tool-execution permissions. These exclusions do not remove Qoder/WorkBuddy file targets, Claude Code settings, or Grok client configuration.
- Excluded: automatic import of opencodex settings, credentials or usage. Source inspection of migration/restore routines does not authorize running them against user state.
- No automatic Cursor settings writer exists in the pinned integration; do not turn read-only installer hints into an installer feature. No OpenCode oh-my-opencode writer exists. Unsupported client/OS combinations must remain explicit.
- Native UI quota shims, local TLS trust/interception, and optional Desktop compatibility trials are present upstream and are **not silently excluded by this inventory**. They are not ordinary inference endpoints or simple settings writers. The service contract's broad native-client compatibility language plus its plain HTTP relay/feature-flag exclusions do not settle every optional native mutation. Owning contracts must distinguish required connection/configuration parity from these optional build-specific behaviors before claiming full native parity. This is a concrete scope decision, not permission to drop native clients wholesale.
- Upstream default-off/experimental flags and fixture tests do not establish real application acceptance. Record test execution and native application acceptance outside this contract. AIPRouter can release under the service contract's mock/build/contract acceptance boundary, but its public compatibility table must state native/live status separately.

### Send and state invariants

1. Do not apply a global three-attempt rule. The default guarded logical-request ledger permits three base sends plus **one shared final recovery** (four total), one alternate-target send, and one target transition. Per-provider retry policy, per-adapter loops, roster limits, replay safety, and workflow/spend ceilings intersect with that ledger. Eligible generic OAuth ingress expands its initial base/total allowance once, before any physical send, to `min(accounts,6) × 3` (up to 18). Exact caller budgets and combo-derived scopes cannot expand. Other paths use derived policies; context-free adapter helpers can be unlimited without a supplied request budget. See `src/lib/request-execution-budget.ts`, `src/server/responses/request-send-budget.ts`, `src/server/inference/context.ts`, and `structure/transports/responses-spend.md`.
2. A POST that failed before headers can already have run upstream. Ordinary model POST reset recovery is opt-in, self-contained-request-only, and consumes a shared replacement grant. It is not safe merely because bytes can be replayed. After committed output, automatic replay is forbidden. Preserve the synthetic refusal's **429**, `upstream_reset_replay_refused`, **`x-should-retry: false`**, and absence of `Retry-After` across all error translations; never turn it into a fresh quota/cooldown event.
3. The three continuation stores named in the service contract are not the complete state inventory. Additional correctness-critical state includes Gemini thought signatures, Cursor checkpoints and conversation remints, provider-private state, native Codex state issuer/account affinity, compaction handoff routes, search provenance, and in-flight audio call binding.
4. All translated adapters require locally retained history for `previous_response_id`. `src/responses/continuation-ownership.ts` explicitly defines an **empty** provider-owned continuation wire set: Devin session IDs are cache identity, Kiro conversation IDs do not reconstruct history, and Cursor checkpoint references depend on retained local state. Only native Responses passthrough can forward a chain to an upstream that owns it. Missing/expired/evicted local history must produce a continuation error, never send only the delta.
5. Most upstream state is process-global or configuration-home scoped. AIPRouter must add organization **and** user ownership, route/destination/credential-generation fencing, cross-instance correctness, and deletion fences. Simply replacing files with SQL without changing keys would leak state and route other users' traffic.
6. Upstream persistent reasoning archives, raw request/provider debug buffers, local history inspection, and local execution artifacts cannot be copied as-is. AIPRouter forbids permanent prompt/response retention and excludes local program execution. Preserve the required protocol behavior using encrypted temporary PostgreSQL state; define TTL/count/byte policies for stores whose service-contract limits are not yet explicit in the owning contract before implementation.

## Storage

The [service contract](servers-aiprouter-service-contract.md) owns encrypted PostgreSQL storage, retention, deletion, master-key rotation and R2 lifecycle. Every store below must bind organization, user, destination and credential generation where applicable. Content-bearing continuation state must remain temporary, encrypted and excluded from ordinary backups; process-local caches cannot become the authority for restart or cross-instance continuity. Missing, expired, evicted or corrupt context must produce an explicit continuation error.

### State inventory and migration disposition

**Classification:** “temporary SQL” means encrypted, backup-excluded PostgreSQL data, tenant/user-scoped, checked for expiry at access, with oldest-first bound and generation fences. “metadata SQL” means durable configuration/auth/usage metadata under service contract retention rules. “process only” is appropriate only for an active socket/lease/buffer whose loss cannot silently change durable authorization. ### Additional media boundary

The reference also supports an xAI video helper through the Responses media loop (`src/images/loop.ts`, `src/images/fulfill-video.ts`, `src/images/xai-video-client.ts`), not a public `/v1/videos` ingress. It submits one asynchronous job and polls: 5-second initial interval, 1.5x backoff capped at 15 seconds, default 300-second job deadline; max three video calls per turn. `src/images/artifacts.ts` permits 200 MiB per video and 600 MiB per turn, unlike image limits. Do not silently apply the 50/100 MiB image limits to video or omit this network helper. The owning storage contract must define video R2 retention/count/TTL and download projection consistent with temporary-only media before claiming compatibility; no local filesystem URL may be handed to a remote client.

## Security

The [service contract](servers-aiprouter-service-contract.md) governs current membership, key validity, roles, cancellation, DB-outage behavior and deletion fences. Apply those checks before every additional send, token refresh, account switch and asynchronous write. An already-dispatched response may finish only within the contract's lifecycle boundary; stale work cannot recreate deleted state.

Context history/notes is an explicit per-user protocol capability scoped to the organization, not a release flag. Retain key-scoped `/v1/usage` and `/v1/hub-state` wire capability and return only information within the key's own organization and user scope. Preserve narrower per-key usage filtering. Neither route grants management access.

The destination policy must validate URL parsing, DNS resolution, redirects, proxy selection, and TLS identity before using personal credentials. Public HTTPS is the default. Private/local HTTP requires operator approval. A server's loopback address is not a route to the user's computer. Provider credentials must never be copied into client settings or replaced with an inference admission key.

## Google OAuth deployment configuration

Google Antigravity OAuth login, completion and refresh require both `AIPROUTER_GOOGLE_OAUTH_CLIENT_ID` and `AIPROUTER_GOOGLE_OAUTH_CLIENT_SECRET` from the service environment. No upstream installed-application credentials are embedded. Missing values refuse these exchanges before network access; other provider paths remain available. Keep populated values outside version control. The deployment must supply an authorized OAuth application compatible with the provider, scopes and callback; source fixtures do not establish live acceptance.

Live/realtime offer sessions, direct WebSocket model queries and saved call bindings carry the resolved upstream model ID. Public route selectors remain caller-facing names and must not overwrite that resolved model.

Every admitted live or dictation socket records a scoped request history row after both relay directions stop, including selection, dial, protocol and cancellation failures. Provider terminal response usage is accumulated once per response ID; absent counters remain unknown. Client frames never supply billing counters.
