# typeopt Rust foundation

## Scope

`crates/typeopt` owns the CLI, private compiler integration, shared whole-program analysis, the eighteen optimization passes, the transformation pipeline, the stage-2 bundle mode, fixtures, Vite example adapter and Excalidraw benchmark harness. The CLI and output interfaces are experimental; `report.json` is schema v1 and `modules.json`/`properties.json` are schema v0. Incompatible changes require explicit documentation.

## Runtime and Language

Rust, with Node.js 24 for fixture execution and integration tooling. Pin the tsrs compiler crates to revision `abddaae32e5d4c17806095bd3874233fa29b26bf` of the `kdy1/tsrs` fork, which is upstream revision `00f16261082fbb2465f0603c667b450d5aa6694b` with only the `unicode-id-start` requirement relaxed (`=1.1.2` to `1.1.2`) so that SWC's minifier crates link in the same binary; keep `unicode-id-start` at the oldest release SWC accepts (1.2.0) in the lockfile; manually validate upstream changes. Keep optimizer code separate from upstream compiler code. Initial distribution is Cargo source builds for macOS arm64 and Linux x64.

## Users and Operators

Application maintainers invoke the optimizer, then separately run their bundler and behavior tests. GitHub issues provide support, without a support SLA.

## Interfaces and Contracts

Optimization has two stages with one pass inventory. Stage 1, `typeopt --project <tsconfig> --entry <file>... --out-dir <new-dir>`, analyzes application TypeScript before bundling and emits ESM. The stage 1 CLI owns emission controls, including `rootDir`, and overrides their tsconfig values without changing the input tsconfig. Stage 2, `typeopt --bundle <bundler-output-dir> --out-dir <new-dir>`, analyzes bundler output chunks after bundling (see Bundle Mode). `--check` performs the same analysis, in-memory transformation and size decisions without publishing output and does not require an output directory. Repeatable `--disable-pass <id>` excludes passes; unknown IDs are invalid CLI arguments. Support `--help`, `--version` and `--verbose`.

The fixed pass inventory and its stable IDs are: `property-shortening`, `property-disambiguation`, `property-ambiguation`, `finite-key-rewriting`, `unused-method-removal`, `unused-field-removal`, `constant-property-inlining`, `method-devirtualization`, `call-inlining`, `function-specialization`, `signature-reduction`, `type-directed-control-flow`, `primitive-operation-simplification`, `enum-runtime-reduction`, `discriminant-compaction`, `aggregate-elimination`, `intrinsic-specialization` and `residual-dependency-removal`. All are enabled by default. Skip reasons use stable snake_case codes.

Shared analysis covers every reachable application TS/TSX module from one tsconfig and the explicit entries: alias-resolved symbol references with their kind (declaration, alias, call, construction, write, type-only, read), public entry exports, symbols referenced from application JavaScript, computed accesses, mentioned names, names declared by external declarations, expression purity and module initialization purity. Internal exports are eligible for analysis; public entry exports, JavaScript references, module namespace objects, external declarations, unknown calls, unresolved keys, reflection, serialization, prototype mutation, decorators and declaration merging are boundaries. Type information only nominates candidates. Runtime evidence comes from source, control flow and uses; an annotation never proves a closed call graph, immutable value, impossible branch or intact intrinsic. Preserve evaluation order, effects, exceptions, property descriptors, object/function identity and observable names or arity, and preserve code when an obligation cannot be proven. Purity proofs treat runtime `typeof` of a name that resolves to no declaration, or only to ambient declarations (project `.d.ts` files, `declare` statements and libraries), as non-throwing. A declared application binding (including an imported one) needs an initialization proof because it still throws `ReferenceError` in its temporal dead zone: a class must be declared earlier in the same function, a top-level non-const enum is a hoisted `var`, and a parameter read inside its own or an earlier parameter list entry is uninitialized. An unused `typeof` initializer without such a proof is retained.

Call inlining may remove a function-valued variable declaration only when the declaration list belongs to a standalone variable statement. A declaration in a loop header is ineligible because removing the loop would discard condition and body effects.

External runtime boundary for intrinsic proofs: a runtime (non-type-only) import, re-export, dynamic import or JavaScript `require` of code outside the application (an external package, a declaration-only package whose runtime is invisible, an unknown ambient `declare module`, an unresolved specifier or a computed specifier) may replace any built-in member at initialization. JavaScript `module.require` calls and direct local aliases of loaders returned by `createRequire` from `node:module` or `module` follow the same boundary. Analysis treats unknown runtime code as a patch of every built-in, so every rewrite that depends on an intact intrinsic is skipped with `intrinsic_may_be_replaced`. `import type`, `export type`, resolved JSON files, explicit `node:` host imports, actual Node 24 bare core imports with ambient declarations, application modules (which the scan inspects itself) and bundle mode (which rejects imports outside the bundle) are exempt. The bare-core inventory is explicit and checked against Node 24's `module.builtinModules`; prefix-only modules such as `node:test` do not grant a bare-name exemption. Resolved userland packages and polyfills, unknown or computed specifiers and `.json` specifiers whose resolved source is not JSON remain unknown. The scan reads syntax and checker resolution only; it never executes or rewrites dependencies, never reads `node_modules` contents beyond normal program loading and does not change the CLI or report schema. `--disable-pass intrinsic-specialization` remains the opt-out.

Pass planners produce transformation bundles: TypeScript source edits (insertions, deletions and replacements, possibly across modules) with a stable identity, a primary pass and the cleanup passes the bundle includes. The pipeline evaluates each bundle by transpiling the affected modules before and after with equal emitter settings and accepts it only when the total emitted ESM byte count strictly decreases; source maps and reports are excluded. A bundle that needs a disabled pass is skipped; disabled transformations never run as cleanup. When a bundle removes the last runtime use of an import, the pipeline keeps module initialization with a bare import unless residual-dependency-removal is enabled and the module initialization is proven pure. Accepted bundles are type-checked; a bundle that introduces type errors is rolled back by bisection and recorded as `recheck_failed`. Syntax errors in transformed code and compiler failures fail the operation. `call-inlining` reads a mutable binding after the inlined body's effects only when the binding belongs to the function (or module) of the call site and every write to it lies directly in that function. A top-level function binding that earlier top-level code may reach is inlined only at call sites that provably run after its declaration (later top-level code, functions created after it or referenced only from such places, and modules outside its import cycle). A runtime self-import is part of that cycle even when the component contains one module. An exported namespace function, including a function-valued `const` or `let`, can be reached through the namespace object before a later binding initializes, so the late-call proof does not use its direct references alone. Every round recomputes all facts from the current text; rounds repeat in deterministic order until no reduction is accepted, and property passes run once afterward.

The property passes use a whole-program, context-insensitive points-to analysis over object literals, key literals, bindings, contained objects and internal function arguments and returns across imports, re-exports and module cycles. Functions get trusted summaries only when internal, declared once and referenced only by direct fixed-arity calls or module aliases. Unknown values taint joined regions; an escape in any joined region preserves the entire group. Named and generic annotations, `typeof` queries, namespace objects and JavaScript remain property boundaries. Instances of closed classes are values of the same analysis. A class is closed when it is a class declaration, or a class expression that initializes a variable (including its inner name), that is declared once in an internal application module; when its symbols are only declared, imported, exported, constructed with `new`, extended by another closed class, used on the right of `instanceof` or read as `C.member` (never written, and only for a static member that the class chain declares or for `name` and `length`); and when it extends nothing or another closed class, implements nothing and has no decorators (on members or parameters), `declare`, `abstract`, `accessor`, overloads, parameter properties, `new.target`, `import.meta`, constructor return values, `super` other than `super(…)` in the constructor and `super.m(…)` in instance members, or static members that use `this` or `super`. The one exception is a `keepNames` naming block, a static block that is exactly one call `H(this, "Name")` (a string or a substitution-free template literal) or, after call inlining, `D(this, "name", {value: "Name", configurable: true})`. `H` must have one declaration in a checked (not boundary) file and no write, and be a variable initialized with an arrow function or a non-async, non-generator function expression, or a function declaration, with two plain identifier parameters `a, b` and a body that is exactly `D(a, "name", {value: b, configurable: true})` (`!0` may replace `true`, and a single `return` is allowed). `D` must be `Object.defineProperty` or a single-declaration, unwritten alias of it, and `Object` must be the library global. The shared intrinsic patch scan must also show that neither the `Object` global nor `Object.defineProperty` is replaced by application code or an external runtime import (writes, reflection, `globalThis` assignment); a local alias of `Object.defineProperty` that is unwritten and only called is analysed like the direct calls, while any other use of it is a conservative patch (the parser-free scan does not follow aliases that escape). Such a block only defines the constructor's own `name`, so it exposes neither the class nor an instance; the helper may be imported from another chunk. Any other static block that uses `this` (a leaking helper, a reassigned helper, a shadowed `Object`, a non-literal name, an extra statement, or a second block with `this`) still rejects the class. At debug level the optimizer logs `keepNames static block accepted` (debug logs carry only the file, the decision, the reason and counts, never class, helper or name text) and `keepNames-shaped static block rejected` with the reason, and the `closed classes classified` event reports `name_blocks`. A base or subclass that is not closed makes the class not closed. `this` in instance members holds the instances of the class and its subclasses; `new` passes arguments to the nearest explicit constructor, `x.m(…)` and `x["m"](…)` dispatch on every instance reaching `x` to the nearest method definition (a later prototype member replaces an earlier one of the same name; an instance field of any class in the chain shadows both), field initializers and getters store into the instance fields, setters receive what code stores, and `C.m(…)` uses the summary of a static method whose every reference is a direct fixed-arity call. Methods with computed (well-known symbol) names, rest or nested-pattern parameters, `arguments`, or async or generator bodies have no summary, so their arguments escape and their results are unknown. Names that code reads or writes on an instance become instance properties without a declaration, except private names (never renamed) and names that `Object.prototype` defines (which preserve the instance); a name that no instance of the region declares or writes may resolve through an extended prototype chain, so reading it preserves the region. Loading a method without calling it, calling anything other than a dispatched method, `delete` and tagged templates through an instance, function-valued field initializers and computed member names other than well-known symbols preserve the class region. When an instance escapes, the parameters and results of every instance and static method and the `this` cells of its class chain become unknown, because unknown code can call them with any receiver and arguments. A value on the left of `instanceof` stays owned only when the right operand is a closed class whose chain has no computed static member (which could define `Symbol.hasInstance`); otherwise it escapes. Arrays that analyzed code creates are values of the same analysis, so the objects stored in them can still be renamed; arrays never have properties of their own, are never rename units and are not counted as object regions or reported in `properties.json`. The allocation sites are every array literal that is not a destructuring target and every call `x.map(…)`, `x.filter(…)` or `x.slice(…)` (the array it may return); `new Array`, `Array.of` and `Array.from` results stay unknown. Each array has one synthetic element cell that all stores flow into and all loads flow out of. Element flows are modeled for literal elements, spread into a tracked literal, `push`, `unshift`, `pop`, `shift`, `at`, `find`, `slice`, `filter`, `map`, `indexOf` and `includes` with one argument, `findIndex`, `some`, `every` and `forEach`, `for (const|let x of arr)`, `.length` (never an object) and index reads and writes `arr[k]` where `k` is proven numeric (a numeric literal, unary `-`, `+` or `~`, arithmetic other than a non-numeric `+`, `++` and `--`, `x.length` of arrays, or a variable of the module or function whose initializer and every write are numeric). An inline arrow or function expression is summarized as a callback only when it is the single argument of a callback method, is not async, a generator or a named function expression, has no rest, `this` or array-pattern parameter, does not use `arguments` and, for function expressions, does not use `this`, `super` or `new.target`; parameter 0 receives the elements, parameter 1 is the index and parameter 2 the array. The parameters and the result of a summarized callback become unknown unless every receiver value of its call is a non-escaped array and the method is modeled, so a closed class method of the same name, an unknown receiver or an escaped array hands the callback to unknown code. A method is modeled only when application code cannot replace it according to the shared intrinsic patch scan (`Facts::patched` for the method; `map`, `filter` and `slice` also need `constructor`, and iteration also needs `Symbol.iterator` and `next`). Array and numeric-index modeling follows an allowlist over the whole program. A write that could change what a numeric key means on `Array`, `Object.prototype` or an unknown owner (a member that is unknown, looks numeric, `NaN`, `Infinity`, `undefined` or `__proto__`, which replaces the chain) disables every modeled array and numeric-index operation, so arrays escape at their first use. So does any form that the intrinsic allowlist does not name, in every checked module and in every unchecked executable chunk (an operator-excluded chunk, a classic script, a `@ts-nocheck` module, a chunk with `eval` or `with`). The invariant is that no handle on a shared built-in (`Array.prototype`, `Object.prototype`, `Function.prototype`, the result of `getPrototypeOf`, a constructor read from a value, the global object) is ever stored, passed, returned or called, so code that holds none cannot mutate a shared built-in and every write that names its handle is a patch record. The sources of handles are the globals `Array`, `Object`, `Reflect`, `Function`, `Proxy`, `eval`, `importScripts`, `setTimeout` and `setInterval` and the global object under every alias (`globalThis`, `window`, `self`, `global`, `top`, `parent`, `frames`), spelled as an identifier, a member of the global object (`globalThis.Array`, `window["Object"]`) or a destructured copy; the reflection keys `__proto__`, `constructor`, `__lookupGetter__`, `__lookupSetter__`, `__defineGetter__`, `__defineSetter__`, `defaultView`, `prepareStackTrace`, `getThis` and `getFunction` in a static, literal computed, destructured or type-proven spelling; a computed member key whose type is not a number, a symbol or a harmless string literal union (`o[k]` with `k: string` can read `"constructor"`; a write through a computed key is exempt); the sloppy-mode `this` (any non-strict function, and the top level of a classic script; class bodies, ES modules and `"use strict"` code are strict); a `with` statement; a timer called with a string; and a dynamic `import()` whose specifier is not a string literal without a scheme. A guarded global counts as the global when its symbol has any declaration outside the application (the library or a global augmentation) or at the top level of a script, or when it does not resolve; a module-scoped or function-scoped binding of the same name shadows it. The allowlisted forms are: type positions, `typeof x`, equality (`===`, `!==`, `==`, `!=`) and `y instanceof x` for any guarded global, handle or constructor value; a guarded global as the receiver of a read of a library function that returns neither a handle nor the global object (`Array.isArray`, `from`, `of`; `Object.keys`, `values`, `entries`, `hasOwn`, `is`, `fromEntries`, `groupBy`, `create`, `freeze`, `seal`, `preventExtensions`, `isFrozen`, `isSealed`, `isExtensible`, `getOwnPropertyNames`, `getOwnPropertySymbols`, `getOwnPropertyDescriptor(s)`, `assign`, `defineProperty`, `defineProperties`, `setPrototypeOf`; `Reflect.has`, `ownKeys`, `isExtensible`, `apply`, `construct`, `getOwnPropertyDescriptor`, `defineProperty`, `deleteProperty`, `set`, `setPrototypeOf`), never written; `getPrototypeOf` of `Object` or `Reflect` called when the result is only compared or passed to `typeof`; `Array.prototype`, `Object.prototype` and `Function.prototype`, spelled directly or on the global object, as an operand of `typeof` or an equality comparison, as the receiver of a write or `delete` (a patch record), as the receiver of a read of a literal member that no write replaces and that is not called with the handle as `this` (`Array.prototype.slice.call(…)`), as the source of an object pattern with such static members, and as the first argument of `Object.<writer>` or `Reflect.<writer>` (`defineProperty`, `defineProperties`, `setPrototypeOf`, `assign`, `set`, `deleteProperty`) in statement position when `Object` or `Reflect` is the library global and neither the global nor that writer is replaced (both must hold); `x.constructor` and `x.__proto__` as an operand of `typeof` or an equality comparison and `x.constructor.name`; a global-object member that is not a guarded name, read, written, deleted, compared or constructed with `new` (`globalThis.hook`) but never called: a call of a global-object member passes the global object as `this`, and every global object inherits `Object.prototype`, so `globalThis.valueOf()` returns the global object itself and `globalThis.m()` runs a function that can return its `this`; only the boolean predicates `hasOwnProperty`, `isPrototypeOf` and `propertyIsEnumerable` and the primitive-returning functions `parseInt`, `parseFloat`, `isNaN`, `isFinite`, `encodeURI`, `encodeURIComponent`, `decodeURI`, `decodeURIComponent`, `escape` and `unescape` may be called, in a plain, bracket, optional or parenthesized spelling, while no write replaces them on the global object, on `Object.prototype` or through an unproven receiver (`valueOf`, `toString`, `toLocaleString`, `constructor`, `__lookupGetter__` and every application-defined member are rejected when called, and a tagged template counts as a call); a timer called with a function; and a dynamic `import()` of a string literal specifier. Everything else disables modeling for the whole program: an alias, a call argument, a return value, a property value, a spread, a destructuring of a reflection key or an unproven computed key, a writer result that is kept, and a call or construction of `Function`, `eval` or a constructor read from a value. The allowlist keeps named handles out of variables, but a value whose origin the analysis cannot see may be an intrinsic that a caller supplied: a parameter of an exported or escaping function (`export function install(p) { p.pop = f }` called with `Array.prototype` by an importer or a host), a callback parameter filled by unknown code, `this` of a method called with `.call`, a property read from a shared object, a call result. Telling them apart needs an escape analysis, so the patch scan inverts the question: a property write (assignment, compound assignment, `++`, destructuring target, `for…in/of` target), `delete` or `Object.<writer>`/`Reflect.<writer>` call (the writer name may be a static bracketed, template or parenthesized spelling, which records the same evidence as the dot form) is ignored only when its receiver is provably a fresh local object, and every other receiver is a possible patch of an intrinsic. Provably local receivers are: an object, array, function or class expression; `new C(…)` for a library constructor that returns a new object (`Array`, `ArrayBuffer`, `Boolean`, `Date`, `Error` and its common subclasses, `Map`, `Number`, `Promise`, `RegExp`, `Set`, `String`, `URL`, `URLSearchParams`, `WeakMap`, `WeakSet`, `AbortController`; not `Object`, `Function` or `Proxy`) or for an application class whose constructor chain never returns a value; `this` and `super` in a constructor, field initializer or static block; a `const`, `let` or `var` variable whose every declaration has a local initializer, that no code assigns again and that unchecked JavaScript does not reference; a function or class declaration that no code assigns again; and `||`, `??`, `&&`, conditional, comma and assignment expressions of such receivers. A parameter (including default, destructured and rest parameters and `arguments`), a closure over a parameter, `this` in a method, accessor, static method or plain function, a property read (`holder.inner.x = v`), a call result, a reassigned variable and an alias of any of these are not local. An unproven write is recorded as a possible patch of its key on any owner: a static key that no array operation relies on (`p.label = n`) changes nothing, a key an operation relies on (an array method, `constructor`, `next`) stops the model of that member (the arrays that use it escape), and a computed, numeric, `NaN`, `Infinity`, `undefined` or `__proto__` key disables array and numeric-index modeling for the whole program. Other passes keep their own patch evidence and do not read these records. Documented limits, with a conservative default and no further heuristic: a value that is only ever a fresh object but reaches a parameter, a property or a call result (`this.cache[k] = v`, `function set(o, k, v) { o[k] = v }`, `state.items[i] = x`) turns modeling off when its key is computed or numeric; a class whose constructor chain returns a value or extends a base that is not an application class or a listed library class is not local; a global-object member call that returns a primitive but is not on the list keeps modeling off; unchecked JavaScript is covered by the text needles and the allowlist but not by receiver analysis. Runtime evidence rules that sit beside the receiver rule: a class with a class decorator (and every class that extends one, or that a variable, `new` or `this` names) is never a fresh receiver, because the decorator may replace the declaration with a constructor that returns an arbitrary object; a listed library constructor stops being fresh once application code may replace it (an assignment to its global binding, a write of the same member of the global object, a `declare global` augmentation, or a write through an unproven receiver that can name it), and the set of replaced constructors is grown to a fixed point so that the receivers it makes unproven can in turn replace more of them; a computed key is harmless only when its checker type is harmless and nothing overrides the type, so a type assertion or JSDoc cast, an initializer or assignment whose own type is not harmless (including `any`), reached through aliases, conditional, logical and comma operands, rejects it; and a timer callback counts as a function only when it is a function or arrow expression, or a reference to an application function declaration or a variable initialized with a function expression that nothing assigns again, never because its type has a call signature. Known limits of these rules, with the conservative default and no further heuristic: a key that arrives through a parameter, a property or a call result keeps its declared type as evidence, because telling what a distant producer really returns (for example one that hides `"constructor" as unknown as number`) needs an escape analysis; a timer callback that is a parameter, a property or a call result is assumed to be string code, so such programs keep their names; and a call of a function that the program does not define (a host-provided global or an ambient declaration, such as `const hook = globalThis.hook; hook()`) is trusted not to patch built-ins, like `console.log`, because the allowlist covers the routes of the language and the host is a residual below, so only application-defined code is scanned for patches. Residuals outside the language: a host module loader (`require("vm")`), DOM script injection (`document.write`, a script element) and a literal `data:` specifier are not recognized; bundle mode rejects imports outside the bundle before planning and project mode treats an unknown external runtime import as a numeric patch. At debug level `intrinsic allowlist rejected a form` names the class of the first rejected form and whether its file is unchecked, and `array builtins intact` reports the cause that disabled modeling. An array escapes (and so do its elements) when it reaches a context that preserves objects, when code reads any member other than `length`, a proven index or a modeled method call (including reading a method without calling it, `delete`, tagged templates, unresolved keys and any write to `length`, whether `arr.length = value` (which also escapes `value`), a compound assignment, `++` or `--`, or a destructuring target, because it truncates or extends the array), when a call has an unsupported shape (for example a `thisArg` or a callback that is not inline), and when its receiver cell also holds an object that is not an array. An escaped array exposes the results, callback cells and loop variables of every call on it, because unknown code may have given it own members. At debug level the optimizer logs `array builtins intact` (modeled methods, disabled methods with the patch record that disabled them, and the index and iteration flags), `array values allocated` (literal and call-result counts, summarized callbacks and rejected callbacks by reason) and `array preservation causes` (arrays per cause and the most frequent unmodeled member names); the array causes are `array:unmodeled-member`, `access:mixed-array-receiver`, `store-into-array-length`, `sink:exposed-callback-result` and `call-argument:escaped-array`.

TypeScript modules with a leading `@ts-nocheck` comment are unchecked boundaries like JavaScript, because they disable the semantic recheck behind every transformation.

Resolve reachable workspace sources using the project's configuration. Declaration files provide external types. JavaScript passes through unchanged; node_modules is read-only external code. Reject syntax/type errors, eval, with, CommonJS module syntax (`import = require()` and `export =`, which `module: Preserve` would emit as CommonJS), unsupported configuration and project-reference orchestration with actionable diagnostics. Read configuration as data; do not execute it. Compatibility adjustments must be explicit and semantics-preserving.

Emit JS and source maps plus versioned `modules.json`, `properties.json` and `report.json`. Source maps compose every round's edits; inserted, deleted, inlined or moved code maps to the original range it replaced. Module mappings link original paths to output JS/maps, record the SHA-256 of each analyzed source and mark any module with an accepted runtime transformation as `optimized`. The `inputs` list records SHA-256 digests of configuration files and every other file the compiler read, including module-resolution metadata. It also records negative resolution dependencies: every non-`bundled:` path the compiler probed through `file_exists`, `directory_exists` or `stat` that did not exist (for example `dep.ts` when only `dep.tsx` exists) is emitted as an `absent` input with no digest, after the positive inputs and sorted by path; a path is kept when nothing resolves there at snapshot time, and probes follow symlinks, so a dangling symlink is recorded as absent until its target appears. A path that a failed probe reported missing but that now satisfies that probe (it appeared while the program was being analyzed) is recorded too, so consumers reject the output instead of trusting a module graph built without it; a path that exists but does not satisfy the failed probe, such as a directory probed as a file, is recorded as a digest-less `mismatch` input whose `becomes` field (`file` or `directory`) names the kind that would satisfy the probe, so it is never a false absence. Consumers must reject output when any module or input changed, when any `absent` path now resolves to a file or directory, or when any `mismatch` path becomes its `becomes` kind, following symlinks. `modules.json` stays at `schema_version` 0; the `absent` and `mismatch` kinds are additive input forms, and an adapter that predates it rejects the digest-less entry as an invalid input snapshot and requires regeneration. Directory listings the compiler enumerates (for example `node_modules/@types`) are not snapshot inputs. Property mappings include stable group identities and original/final names and describe property transformations only. Report v1 keeps the applicable v0 statistics and adds enabled/disabled pass IDs, rounds, emitted size before and after, per-pass applied/skipped counts with reason codes, accepted bundles with locations and measured byte changes, and skipped locations with reasons. Bundle savings are attributed to the whole bundle, never split among its passes. Identical inputs/configuration/options/tool versions produce identical code, mappings and reports. Exclude time and peak-memory measurements from deterministic comparisons. Zero safe changes is a valid explained result.

The Vite example validates the whole analysis snapshot at build start and substitutes mapped JS for `optimized` modules under original module identities; preserved TS modules retain the original Vite transpilation. Compose source maps through the original module identities. Keep assets in the original project and preserve resolution context. It is not a separately published plugin. Roll back one optimization by excluding its pass and rebuilding into a new directory; roll back adoption by restoring original build inputs/configuration.

## Bundle Mode

Stage 2 loads every `.js`/`.mjs` file of a bundler output directory as one closed ES module program with the standard DOM libraries and no `@types` packages; `--project` and `--entry` are not used. Static imports and literal dynamic imports in the parsed chunks link them. A chunk that no other chunk imports, or that an inline HTML script, event handler or `javascript:` URL imports, is an entry whose exports are public. HTML (`.html`/`.htm`) script URLs resolve with URL semantics against the `<base href>` parsed before each script, after decoding character references; an import map, an inline import with a non-literal or undecodable specifier, an event handler attribute (`on*`) or a `javascript:` URL in a navigating attribute (`href` of `a`/`area`, `action`, `formaction`, `src` of `iframe`/`frame`/`embed`, `data` of `object`) with a character reference this parser cannot decode (the browser decodes it before running the code, so its imports are unknown; undecodable references in other attributes are ignored; such an executable attribute also counts as source reflection, so `--minify` publishes the edited chunks unminified), or a computed `import(…)` in any chunk makes every chunk a public entry; and classic scripts are recognized by every JavaScript MIME type essence. Chunks that import modules outside the bundle directory, including package specifiers when no page defines an import map, are rejected. If a chunk contains a literal dynamic import of a package specifier, typeopt keeps the chunk unchanged as a boundary. It leaves the package specifier unresolved in the published bundle and logs a warning with the chunk and specifier. Every chunk that the boundary can import stays frozen. A chunk is transformed only when it is known to be an ES module (an `.mjs` file, ESM statements or `import.meta`, imported by a chunk or loaded by an HTML module script); classic scripts (including chunks an HTML page loads with a classic `<script>`, even when a module also imports them, chunks that call `importScripts` and the chunks it loads (a literal target resolves relative to the calling chunk, or, for a root-relative URL, under the bundle directory after dropping leading deployment-base segments as for root-relative module imports; every chunk without ESM syntax when a target is computed), which stay in the program so that what they reach remains observed) and chunks matched by repeatable `--bundle-exclude <text>` stay unchecked boundaries that no pass edits. A chunk is also an unchecked boundary when its syntax needs it: a `with` statement; the global `eval` used as a value (a direct call or an alias such as `const e = eval`, `globalThis.eval`, or a destructuring such as `const { importScripts: load } = self`); and `importScripts` called through any callee form (`importScripts(…)`, `self.importScripts(…)`, `globalThis.importScripts(…)`, `self["importScripts"](…)`, parenthesized forms) or used as a value that can alias it. A chunk that a worker loads through any of these callee forms is a classic script. Mentions that run no code are not boundaries: `typeof eval`, `typeof (eval)`, `typeof importScripts`, `typeof self.importScripts`, property names such as `obj.eval`, property keys such as `{ eval: 1 }` and module export names such as `import { eval as helper }` or `export { helper as eval }`. At debug level the optimizer logs the rule (`dynamic-package-import`, `excluded-or-classic-script`, `with-statement`, `eval-reference`, `import-scripts-call`, `import-scripts-reference` or `boundary-reachable`) that made each chunk a boundary. Boundary chunks are never edited by a pass. Classic, eval, with and importScripts boundaries are rewritten and renamed during publication so they import renamed copies and keep one instance of each module. Dynamic package boundaries are pinned: they and every chunk they can import retain their original names and content. Chunks matched by `--bundle-exclude` are pinned too: they stay byte-for-byte unchanged under their original names. Every chunk that an excluded chunk can import, statically or through a literal dynamic `import()`, directly or through other chunks (boundary chunks included), is frozen with it: it is not edited, renamed or rewritten, because the excluded chunk keeps importing the original name and a renamed copy would be a second instance of the module. Service worker precache entries in the Workbox form `{url, revision}` (either key order, string values) that name a file whose published content differs from the input get a new revision string of the original length derived from the new content, so a worker does not keep serving cached HTML that names removed chunks; manifests in pinned or content-hashed files are not changed this way.
Precache refresh trusts only Workbox calls whose callee resolves without dynamic `with`-scope lookup. Calls inside a `with` body are ambiguous even when a same-named global or imported Workbox binding exists; leave their revisions unchanged and do not reject an empty revision as a trusted Workbox entry.

Bundled JavaScript is not type-checked, so inferred and JSDoc types can be wrong. The bundle pass set is fixed to the passes whose proofs do not depend on static types: `property-shortening`, `property-disambiguation`, `property-ambiguation`, `call-inlining`, `signature-reduction`, `type-directed-control-flow`, `primitive-operation-simplification` and `residual-dependency-removal`. The other ten passes are reported as disabled and cannot be enabled in bundle mode; `--disable-pass` narrows the set. Identifier-like tokens of string and template literals count as mentioned names. Candidates are not parsed individually; the recheck after each round treats syntax errors (including TypeScript-only syntax) and semantic diagnostics that the original chunk did not have (chunks may opt into checking with `// @ts-check`) as failures and rolls the responsible bundles back with `recheck_failed`. The intrinsic patch scan narrows a global-object write under a computed key to globals whose name starts with the key's known literal start, and ignores symbol keys while `Symbol` is unpatched; a reflection helper bound once and only called is analysed like direct calls. Input chunks with syntax errors are rejected.

Edits apply to the chunk text, and the size gate compares the edited chunk text bytes without emitting. Output is a staged copy of the input directory with edited chunks replaced (publication fails when the copied directory differs from the fingerprint taken before analysis), source maps (located through `sourceMappingURL`, including inline `data:` maps, or adjacent `<chunk>.map` files) composed with the edits (uncomposable map references of edited chunks, such as remote, missing or outside maps, are removed; an existing local map that is malformed or unsupported is removed from the output together with its trailing `sourceMappingURL` directive, and a malformed hidden adjacent map is removed without adding a directive), and edited content-hashed chunks and text assets (`<name>-<hash>.<ext>` or `<name>.<hash>.<ext>` for `js`, `mjs`, `cjs`, `css`, `json` and `webmanifest` with an 8-character base64url hash that contains a digit, an uppercase letter, `-` or `_`) plus every hashed chunk that references a renamed chunk renamed deterministically (each new hash covers the final content of the chunk and of every renamed chunk it reaches) with every reference position in text assets rewritten (a name follows `/`, a quote, `(` or `=`; whitespace may separate it from `=` or from the `(` of a CSS `url(` token that starts its own identifier (`myurl(` and `--url(` do not count), case-insensitively, and absolute or protocol-relative URLs keep their names); names that a reference spells with URL or HTML escapes keep their original files (with the renamed files those originals reference) beside the renamed ones, and pinned chunks are never rewritten or renamed and, because the chunks they import are frozen, keep originals only for non-import mentions of renamed names; report `size.retained` discloses the code bytes of kept originals in addition to `size.after`; `--keep-chunk-names` disables renaming. Opt-in `--minify` minifies every edited chunk with SWC's compressor and mangler (module and top-level scope, terser-compatible defaults) before renaming, and keeps the minified code only when its Brotli (quality 11) size shrinks and its gzip (level 9) size does not grow; function and class names, names inferred from anonymous function and class bindings and from object literal keys, and parameter lists are preserved so `Function.prototype.name` and `length` stay unchanged; legal comments (`/*!`, `@license`, `@preserve`) stay, including those attached to code the compressor removes; after compression typeopt removes the internal name-keeping calls (the compressor can move one into any expression position, and typeopt reduces it there to its non-identifier arguments in order followed by `undefined`), and minification is skipped for a chunk that already contains the internal keep marker, or when a name-keeping call remains after that removal; the original trailing source map comment follows the code, the chunk's map is composed with SWC's map, unedited chunks are never minified, and report `size.minified` (omitted when zero) gives the code bytes minification removed, which `size.after` and `size.saved` include. Bundles with symbolic links and pages with Subresource Integrity attributes or a Content Security Policy with hash sources are rejected before analysis in check and output modes. The report v1 is printed to standard output; its `size.metric` is `chunk_text_bytes` instead of `emitted_esm_bytes`, and the gate and the report both exclude trailing source map comments. Behavior tests against the optimized directory remain the operator's responsibility.

Legal comments (`/*!`, `@license`, `@preserve`) remain attached to the published chunk, including comments attached to code removed by compression. Typeopt verifies emitted legal-comment identity by kind, exact text, count, and source order; if it cannot verify the notices, it keeps the chunk unminified.

## Storage

One-shot, in-memory analysis; no daemon, watch mode or persistent cache. Each round rebuilds the program from in-memory texts in an operation-owned allocation region. Release checker handles and the unshared program before freeing its region. Keep the checker single-threaded, leaf-file reclamation disabled and checker recycling disabled so analysis, rechecks and emit never read freed compiler objects. Compiler-owned identities never escape the private adapter. Never modify input files or an existing output destination. Stage output in an operation-owned temporary directory and publish without replacing an existing destination. Error and cancellation paths return failure, remove owned temporary artifacts and never publish a complete result.

## Security

After installation, analysis performs no network access, user-code execution or telemetry. Do not log source contents, credentials or environment values. External APIs and observable object shapes form preservation boundaries.

## Logging

Use structured Rust tracing and English stderr diagnostics. Verbose mode adds diagnostic context without source text or environment values. Measure elapsed time and peak resident memory; no performance threshold or resource ceiling applies.

## Build and Test

Run root `cargo test` after Rust changes and applicable frontend `pnpm test` after frontend changes. Compare original and optimized fixtures in Node, including side effects. Cover each optimization, combinations, structural types, unions, aliases, computed keys, accessors, inheritance, reflection, serialization, external escape, collisions, determinism, maps, malformed input, filesystem failures and Ctrl+C. Verify no input execution or network access in a restricted environment.

The root `Cargo.toml` builds the pinned tsrs compiler crates with `opt-level = 3` in the dev and test profiles. The tests run that compiler on every fixture, and unoptimized it dominated workspace test time. typeopt itself and the other workspace crates keep unoptimized debug builds with debug assertions.

Bundle mode needs Node fixtures that compare original and optimized entry chunks, including chunks whose unchecked types lie, runtime-parsed member paths, generated functions, dynamic namespace access, observable arity, unimported entry chunks, classic scripts, exclusion, map composition, rehashing and determinism.

Every pass needs positive fixtures that demonstrate its transformation and size benefit and negative fixtures for its safety boundaries, run with the pass alone, in combinations and with every pass enabled and disabled; every fixture compares original and optimized Node behavior. Cover the measurement script's reference validation with synthetic builds (missing and valid references, harmless strings, remote URLs, removed unreferenced chunks, two- and three-build forms) in `crates/typeopt/tests/benchmark_measure.rs`, which requires the pinned Node and is skipped otherwise. Validate Vite with workspace aliases, TSX, unchanged JS, original assets, non-property transformations, stale transitive inputs and shadowing files that appear at recorded absent resolution candidates and wrong-kind candidates that change kind. Pin the Excalidraw commit, lockfile, runtime, browser, production settings and compression tools before benchmarking; apply documented compatibility adjustments equally to all builds. Compare three builds: original inputs, existing typeopt at the pinned `existing_typeopt_revision` and the extended optimizer; each optimized build records the clean source revision its optimizer binary was built from. Asset sets may differ; record added and removed assets, verify that every local loading reference (HTML module scripts and modulepreloads, static imports and literal dynamic imports, quoted or a template without substitutions, with JavaScript escapes decoded) resolves to a file of its own build (HTML URLs without a `./` or `/` prefix are document-relative, JavaScript specifiers without one are bare and ignored), independent of any asset another build emits, and sum every production JS asset excluding source maps. The extended build's raw, gzip and Brotli totals must each be strictly smaller than both other builds; no minimum percentage applies.

Chromium acceptance compares drawing shapes/freehand, text/move/resize edits, undo/redo, save/reload/file import and PNG/SVG export across the three builds. Actual application acceptance cannot be replaced by fixtures. Require native build/execution on macOS arm64 and Linux x64. Retain source revision, commands, results and unperformed checks in CI artifacts or PR/issue records. Preserve existing affected CI and macOS runner restrictions.
